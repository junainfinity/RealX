# Build Orchestration

**This note explains how to run the RealX app build later. There is one run per milestone: <!--g:milestones-->11<!--/g--> milestones (AM0-AM10), <!--g:nodes-->107<!--/g--> nodes (A00-<!--g:last_node-->A106<!--/g-->) and <!--g:items-->2<!--/g--> scheduled follow-up items (<!--g:item_ids-->A12.1, A61.1<!--/g-->) in all.** Each run takes the milestone's unfinished nodes and items and schedules the ready ones over the build streams. Every node goes through the [[App Gauntlet]] with the four model roles of decision D19 (30 Sep 2026): **Opus 5.5 (high) plans**, **Grok 4.7 (xhigh) builds**, **Opus 5.5 (high) does the node QA** at every loop in a fresh session, and **Fable 5.1 (high) does the graph QA** once all of the milestone's nodes have passed. There are at most three fix loops per node and two graph rounds per milestone. The run ends with the status of every node and of the milestone's graph gate. If a usage limit stops a run, it ends cleanly with a list of ids to re-run, and never leaves a half-built milestone behind. Nothing is built yet. This note is not legal advice, and no step in it crosses a human gate ([[Human Gates]]). This note is generated by `06 Evidence\Tools\app_plan\build_orchestration.py` from `orchestration\orch-skeleton.md`, the tested script, the runner and `Data\app-graph.json`; edit those, not this note.

**How this plan was checked.** Fable 5.1 (high) wrote the graph and the node specs A00-A45 and A47. Its weekly limit then ran out. Opus 5.5 wrote the other specs and assembled the plan. An independent Opus 5.5 reviewer checked every node spec and the whole plan. When that check run started, every spec had had one independent check and one fix pass. <!--g:checks.passed-->1<!--/g--> spec (<!--g:checks.passed_ids-->A05<!--/g-->) had passed a re-check, and <!--g:checks.awaiting-->105<!--/g--> were still waiting for theirs, because the usage limit stopped the check run. <!--g:checks.unchecked_ids-->A106<!--/g--> was added by the plan fixer on 24 Sep 2026 and has had no independent check yet. Under D19 the remaining re-checks are run by Opus 5.5 (high) per spec, and Fable 5.1 (high) reviews the plan as a whole. The run enforces this: a spec without a passed re-check does not start unless the user names it in `acceptUnconfirmedSpecs` (§3). **No role is ever replaced.** Every run first asks each of the four role models its name and stops if any answer is not the model D19 names; it never falls back to another model.

## 2. Before the first run (once)

1. **Machine.** Windows 11 with Node 24.21.0, Docker Desktop 29.8.0 (running), Git 2.55 and Python 3.13 (`py`). `<workspace>\app` does not exist yet: A00 creates it, and A01 runs `git init` on it.
2. **Folders outside the repository.** Create `<workspace>\gauntlet\` with `tools\`, `hidden\`, `qa\`, `workflows\`, `runs\` and `journal\`, and `<workspace>\worktrees\`. The first Prepare step writes `gauntlet\tools\set-status.mjs` (§4) and an empty `gauntlet\status.json` if they are missing.
3. **The runner.** In `<workspace>\gauntlet\` run `npm init -y` and `npm install @cursor/sdk`. Set `CURSOR_API_KEY` (a user key from the Cursor dashboard, Integrations) in the shell that starts runs. The runner stops before any agent call if a role model id is not in `Cursor.models.list` for that key.
4. **The graph file.** `09 App Build\Data\app-graph.json` must be generated from the current node specs (`py build_app_plan.py "<workspace>\RealX"`, then `py check_plan.py`, which must pass). Titles, milestones, `oracle`, `human_gate`, estimates, dependencies and owned paths all come from the notes; the run reads `deps`, `est_hi`, `human_gate`, `ui`, `docker` and the follow-up items from the graph file. `ui` (the node renders screens, so the node QA's design-fidelity check applies) and `docker` (its Challenge and re-verify need the compose stack, so they take the Docker lock) are derived by the generator from each node's lane and owned paths, with a frontmatter override; the Prepare step copies them and never judges them. <!--g:oracle_specs-->53<!--/g--> specs say `oracle: yes`, plus <!--g:oracle_items-->1<!--/g--> oracle follow-up item (<!--g:oracle_item_ids-->A12.1<!--/g-->).
5. **The requirements file.** `09 App Build\Data\requirements-lists.json` must exist with SHA-256 `<!--g:reqs_sha256-->6d281f45435f4732e8c312f45bdfadfc5bb55c232f90d0fdb2c6b7c35246f6e5<!--/g-->` (the hash A00 pins). Every Prepare step checks it and stops the run if it is missing or changed.
6. **Stream count.** Use `streams: 3`. A01 freezes "up to three nodes may build at once", and the schedule in §1 is computed for three streams. Four streams would need an A01 change first (the graph note shows the four-stream schedule for comparison).
7. **Spec check status.** Each Prepare step reads the latest record in `Data\checks\` for every listed node and stops a node whose spec has no passed re-check. To run such a node anyway, the user names it in `acceptUnconfirmedSpecs` after reading its check record; the check file's hash goes into the node's manifest.
8. **Usage.** Each node needs one planner Specify and Plan pass, one node-QA oracle or fixture pass, one to four node-QA loops and one node-QA re-verify, so most of the load falls on Opus 5.5. Fable 5.1 runs once or twice per milestone, at the graph gate. Plan one milestone per usage window, and split a large milestone (AM3 has <!--g:ms.AM3.nodes-->23<!--/g--> nodes, AM7 has <!--g:ms.AM7.nodes-->13<!--/g-->) across two runs by passing a subset of ids (§3). The graph gate runs only in the run that finishes the milestone's last id.
9. **Save the templates.** Copy the script in §7 exactly into `<workspace>\gauntlet\workflows\realx-milestone.js` and the runner in §8 into `<workspace>\gauntlet\workflows\run-milestone.mjs`. Every run uses those files, so a resume runs the same code.

## 3. How the user starts a run

The user types, for example: **"run milestone AM0"**. To run part of a milestone: "run milestone AM3, nodes A30-A38 only". The session (any Cursor agent in `<workspace>`) then does this:

1. Reads this note and [[App Gauntlet]].
2. Reads `app-graph.json` and `gauntlet\status.json`. The id list is every node **and every follow-up item** of that milestone (the row in §1) whose state is not `passed`, minus any id the user left out. A node whose state is `escalated` is included only if the user has resolved it; it is then also passed in `reset`. A `parked` node is included; the run resumes it only when its condition is met. If every id has passed but the milestone's graph gate has not (`status.json` entry `AMx`), the list is all of the milestone's ids, so the run goes straight to the graph gate.
3. Writes the args to `<workspace>\gauntlet\runs\<runLabel>.args.json` (AM0 and AM1 shown; the lists come from §1):

```json
{
 "milestone": "AM0",
 "nodes": ["A00", "A01", "A02", "A03", "A04", "A05", "A07", "A08", "A09"],
 "streams": 3,
 "humanApprovals": {},
 "reset": [],
 "reserveTokens": 400000,
 "runLabel": "AM0-r1",
 "now": "<the current date and time, ISO 8601>",
 "acceptUnconfirmedSpecs": [],
 "journalDir": "<workspace>\\gauntlet\\journal\\AM0-r1"
}
```

```json
{
 "milestone": "AM1",
 "nodes": ["A06", "A10", "A11", "A12", "A12.1", "A13", "A14", "A15", "A16", "A17", "A18", "A19", "A20", "A21", "A22", "A23", "A104"],
 "streams": 3,
 "humanApprovals": {},
 "reset": [],
 "reserveTokens": 400000,
 "runLabel": "AM1-r1",
 "now": "<the current date and time, ISO 8601>",
 "acceptUnconfirmedSpecs": [],
 "journalDir": "<workspace>\\gauntlet\\journal\\AM1-r1"
}
```

   Then it starts the runner in the background from `<workspace>\gauntlet\`: `node workflows\run-milestone.mjs workflows\realx-milestone.js runs\AM0-r1.args.json`. It checks `journal\<runLabel>\run.log` now and then, and waits for `result.json`.
   - `humanApprovals` holds sign-offs the user has actually given in chat, keyed by node id or by the key a parked node names, for example `{"A50": "HG-REVIEW: founder approved Ext A frames on 2026-11-03", "A86:HG-ACCOUNTS": "bundler account and faucet funding done on 2027-01-04"}`. The session never adds an approval the user did not give. **Approvals persist:** the run writes each node sign-off into `status.json` (`approval=`, and `held=0` for a held node) the first time it sees it, at the node's gate or, for a node held by an earlier run, in Prepare. Later runs read it back, so a milestone's run never needs the sign-offs of an earlier milestone again; the session passes only the sign-offs the user gave since the last run.
   - `reset` lists escalated nodes the user has resolved (re-specified, split or answered). They restart from Specify with the loop counter at zero.
   - `now` is the current date and time, which the session reads from the user's machine and passes in, because the script never reads a clock. A node parked until a time resumes only when `now` has reached it.
   - `acceptUnconfirmedSpecs` lists the ids whose spec has no passed re-check that the user has chosen to run anyway (§2 item 7).
   - `journalDir` is the run's journal folder. The runner writes one `.jsonl` file per agent label there, with every event of that agent's session. The oracle-isolation scan (App Gauntlet §2) reads the planner and builder files there.
4. When the run returns, the session reports what happened: passed nodes; nodes held for a human sign-off before their dependents start; milestone-close sign-offs still due; escalated nodes with their reasons; nodes waiting for a sign-off; parked nodes with their resume condition; blocked nodes with the reason; the oracle-isolation scan result; the graph gate (state, rounds, open findings with their owner nodes); and the `rerun` list with the reason the run stopped. It sends the user the milestone's exit evidence (for example A61's preview guide) and `app\evidence\graph-<AMx>.qa.md`.
5. If `nextArgs` is not null, the session tells the user the exact phrase that continues the run, for example "resume milestone AM0". `nextArgs` is a copy of this run's args with `nodes` replaced by the rerun list (or all of the milestone's ids when only the graph gate is left), `reset` emptied (the resets were applied), `acceptUnconfirmedSpecs` filtered to the rerun ids, and every other field kept (`streams`, `humanApprovals`, `reserveTokens`, `journalDir`, `runLabel`, `now`). Its `refreshBeforeResume` list names the fields the session must refresh before the resume: `now` (read the clock again), `runLabel` (a new label, for example `AM0-r2`) and `journalDir` (the new run's journal folder).

**Commits.** Starting a run is the user's permission for its local git commits: one per passed node or item, and one per graph-QA reopen of a node, made by the clerk, on `main` in `<workspace>\app`. There is no remote and nothing is ever pushed.

## 4. status.json and its only writer

`<workspace>\gauntlet\status.json` holds the build state of every node, follow-up item and milestone graph gate, outside the repository, as [[App Gauntlet]] §3 describes. Agents never edit it by hand. They run this tool, which checks the vocabulary, takes a file lock and writes atomically, so that parallel nodes cannot overwrite each other. It accepts node ids (`A12`), the scheduled follow-up items (`A12.1`, `A61.1`), a spec-named follow-up loop run keyed by its requester (`A04.1-A12`: loop A04.1 as A12 asked for it), follow-ups the run creates without a spec id (`A01-fu-A87`) and milestone ids for the graph gate (`AM3`). Besides the step and verdict it keeps a node's recorded sign-off (`approval`) and an open-Critical flag (`critical`), so both survive a stop. It accepts the states `not started`, `building`, `challenged`, `passed`, `escalated` and `parked`:

```js
// <workspace>\gauntlet\tools\set-status.mjs - the only writer of status.json (App Gauntlet §3).
// Usage: node set-status.mjs <id> key=value ...   keys: state step verdict loop reset specHash oracleVersion
//        hiddenCasesHash commit humanGate approval reason run parkUntil parkKey held critical
// Ids: a node (A12), a scheduled follow-up item (A12.1, A61.1), a spec-named follow-up loop run keyed by its requester
// (A04.1-A12: loop A04.1 as A12 requested it), a follow-up created by the run (A01-fu-A87), or a milestone's graph gate (AM3).
// approval: the user's sign-off text, stored once given, so later runs treat the node as approved.
// critical: 1 while the node has an open Critical finding (the milestone's critical hold survives a resume), 0 when closed.
import fs from 'node:fs'
const FILE = process.env.REALX_STATUS_FILE || '<workspace>\\gauntlet\\status.json'
const LOCK = FILE + '.lock'
const STATES = ['not started', 'building', 'challenged', 'passed', 'escalated', 'parked']
const STEPS = ['specify', 'oracle', 'build', 'challenge', 'gate']
const VERDICTS = ['pass', 'fail', 'escalate', 'awaiting-human']
const KEYS = ['state', 'step', 'verdict', 'loop', 'reset', 'specHash', 'oracleVersion', 'hiddenCasesHash', 'commit', 'humanGate', 'approval', 'reason', 'run',
  'parkUntil', 'parkKey', 'held', 'critical']
const [node, ...pairs] = process.argv.slice(2)
const fail = (m) => { console.error('set-status: ' + m); process.exit(1) }
if (!/^(A\d+(\.\d+(-A\d+(\.\d+)?)?|-fu-A\d+(\.\d+)?)?|AM\d+)$/.test(node || '')) fail('first argument must be an id such as A12, A12.1, A04.1-A12, A01-fu-A87 or AM3')
const upd = {}
for (const p of pairs) {
  const i = p.indexOf('=')
  const k = p.slice(0, i), v = p.slice(i + 1)
  if (i < 1 || !KEYS.includes(k)) fail('unknown key in ' + p)
  upd[k] = v
}
if (upd.state && !STATES.includes(upd.state)) fail('bad state ' + upd.state)
if (upd.step && !STEPS.includes(upd.step)) fail('bad step ' + upd.step)
if (upd.verdict && !VERDICTS.includes(upd.verdict)) fail('bad verdict ' + upd.verdict)
if (upd.loop && !/^\d+$/.test(upd.loop)) fail('loop must be a whole number')
if (upd.state === 'passed' && !upd.commit) fail('state=passed needs commit=<sha> (A00 without a repo: commit=none)')
if (upd.state === 'parked' && !upd.parkUntil && !upd.parkKey) fail('state=parked needs parkUntil=<ISO time> or parkKey=<humanApprovals key>')
if (upd.parkUntil && upd.parkUntil !== 'none' && isNaN(Date.parse(upd.parkUntil))) fail('parkUntil must be an ISO time')
if (upd.held && !['0', '1'].includes(upd.held)) fail('held must be 0 or 1')
if (upd.critical && !['0', '1'].includes(upd.critical)) fail('critical must be 0 or 1')
const sleep = (ms) => Atomics.wait(new Int32Array(new SharedArrayBuffer(4)), 0, 0, ms)
let fd
for (let i = 0; ; i++) {
  try { fd = fs.openSync(LOCK, 'wx'); break } catch (e) {
    if (e.code !== 'EEXIST') throw e
    try { if (Date.now() - fs.statSync(LOCK).mtimeMs > 60000) fs.unlinkSync(LOCK) } catch {}
    if (i > 400) fail('status.json is locked')
    sleep(50)
  }
}
try {
  const s = fs.existsSync(FILE) ? JSON.parse(fs.readFileSync(FILE, 'utf8')) : { version: 1, nodes: {} }
  const blank = () => ({ state: 'not started', lastPassedStep: '', verdict: '', loop: 0, history: [] })
  let n = s.nodes[node] || blank()
  if (upd.reset === '1') n = Object.assign(blank(), { history: n.history })
  if (upd.step) n.lastPassedStep = upd.step
  if (upd.state) n.state = upd.state
  if (upd.state && upd.state !== 'parked') { delete n.parkUntil; delete n.parkKey }
  if (upd.verdict) n.verdict = upd.verdict
  if (upd.loop) n.loop = Number(upd.loop)
  if (upd.held) n.held = upd.held === '1'
  if (upd.critical) n.critical = upd.critical === '1'
  for (const k of ['specHash', 'oracleVersion', 'hiddenCasesHash', 'commit', 'humanGate', 'approval', 'reason', 'run', 'parkUntil', 'parkKey']) if (upd[k]) n[k] = upd[k]
  n.updatedAt = new Date().toISOString()
  n.history.push(Object.assign({ at: n.updatedAt }, upd))
  s.nodes[node] = n
  fs.writeFileSync(FILE + '.tmp', JSON.stringify(s, null, 1))
  fs.renameSync(FILE + '.tmp', FILE)
  console.log(node + ': ' + n.state + ', last passed step ' + (n.lastPassedStep || 'none') + ', loop ' + n.loop + (n.held ? ', held for a human sign-off' : '') + (n.approval ? ', approved' : '') + (n.critical ? ', open Critical finding' : ''))
} finally {
  fs.closeSync(fd)
  fs.unlinkSync(LOCK)
}
```

A86 state=parked parkUntil=2027-01-10T09:00:00Z`. `... A50 state=passed step=gate commit=<sha> held=1`. `... A50 held=0 approval="HG-REVIEW: founder approved Ext A frames on 2026-11-03"`. `... A04.1-A12 state=building step=specify`. `... A37 critical=1`. `... A12 reset=1`. `... AM3 state=passed step=gate verdict=pass loop=1 commit=<sha>`. ## 5. Stopping, usage limits, parking and resuming

- **Stop guard.** Every agent call goes through `call()`. If an agent returns nothing (a usage limit, a run that ends in error, no JSON matching the schema after one retry, or the token budget falling below `reserveTokens`), the run sets `stopping`. **An agent call that throws** (for example an unknown model id, a bad key or a network failure before the run starts) **also sets `stopping`**, so the run does not keep starting nodes that would each fail. After that it starts no new step and no new node. Steps already running finish, and each node stops at its next step boundary. The run returns `rerun` and `nextArgs`. A node is never half-merged, because the merge is one commit and a fast-forward. No dependent starts on a node that has not passed.
- **Role probes.** Before Prepare the run asks each role model (planner, builder, node QA, graph QA) for its exact name. If an answer is not Opus 5.5, Grok 4.7, Opus 5.5 and Fable 5.1 respectively, the run stops at once. The reported names go into every node's manifest (`modelVersions`) and into the report (`models`).
- **Graph gate first.** Prepare reads the previous milestone's graph-gate entry. If it has not passed, the run stops before any node starts and says which milestone to resume.
- **Resume from the last passed step.** Each step records `lastPassedStep` in `status.json` only when it completes. On the next run, Prepare reads it back and each node carries on from there: after `oracle`, the planning and build start; after `build`, the Challenge runs; after a failed `challenge`, the Fix runs. The loop counter is kept, so an interruption never gives a node extra fix loops. When the node QA's re-verify after the rebase fails, the run first writes `state=building step=challenge verdict=fail loop=<n>` and only then requeues the node, so a stop before the fix can never send it straight back to the merge, and the three-loop cap holds across runs. The graph gate resumes the same way: Prepare returns its state and round count, so a stop never gives a milestone an extra graph round.
- **Parked is waiting, not failing.** A node that must wait for real time or for a human step is `parked`, never escalated, and its loop counter is kept. Two cases: the Specify step finds only a human step missing (for example A86's bundler account and faucet funding) and returns the approval key it waits for; or the Build step finishes one session of a multi-session node (A86's Base Sepolia sessions, separated by 48-hour timelocks) and returns the earliest time the next session may start. The run records `state=parked` with `parkUntil` or `parkKey` and moves on; a later run resumes the node once `now` has reached `parkUntil` and the user has given the `parkKey` approval. No agent call ever waits for hours.
- **Re-run, never resume agents.** Each agent is a fresh SDK session, and every result that matters is already on disk and in `status.json`. So the rule is: **re-run the same script with `nextArgs`, which lists the unfinished ids.** The node QA in particular must never resume a builder's or planner's session.
- **Never edit the saved script to resume.** Change args, not code. If the template has to change, change the tested script in `06 Evidence\Tools\app_plan\orchestration\`, run `node test-workflow.mjs`, regenerate this note, copy it to the file again, and record the reason in [[Decisions]].
- **Critical hold.** While any node has an open Critical finding, no new node starts in the milestone ([[App Gauntlet]] §5), and the graph gate does not run. Nodes already running carry on, and the held node itself keeps its fix loop. The hold lifts when the finding is fixed or the node escalates. The hold is persisted: the run writes `critical=1` to the node's `status.json` entry when a Critical opens and `critical=0` when it closes or the node escalates, and Prepare returns the open ones (`criticalOpen`), which seed the hold before anything is scheduled, so a resumed run cannot start new nodes beside an open money or G22 bypass.

## 6. Scheduling

- **Prepare checks, before any node starts.** The requirements file hash (§2 item 5); the previous milestone's graph gate (§5); every dependency of a listed id is either passed or listed in the same run (otherwise the id is blocked and the report names the missing dependency); each note's "Depends on" links are all in the graph's dependencies for that node (a link the graph does not carry is a problem that stops the node, because the Specify step would wait on it); and each spec's check status (§2 item 7).
- **Ready nodes.** A node is ready when every dependency is `passed` and not held, either before the run or during it, and, if it is parked, its condition is met. Among the ready nodes, the one with the longest remaining path (by `est_hi`) starts first, ties broken by id. At most `streams` nodes run at once.
- **Human gates are data, not prose.** Every node note carries `human_gate` in its frontmatter, and the graph carries it too: `none` (the node QA never returns "awaiting-human"; A00, whose charter review does not block), `blocks-own-gate` (the node is not passed until the user's sign-off is in `humanApprovals`; A51 and A87), `blocks-dependents` (the node merges and is marked passed with `held=1`, and no dependent starts until the sign-off is given; A50), and `milestone-close` (the node passes; the milestone is reported closed only after the sign-off; A61 and A89).
- **Blocked nodes.** A node whose dependency escalated, is held or waiting for a human sign-off, is parked, or is outside the run and not passed, is reported as `blocked` with the reason and does not start.
- **Follow-up loops.** The specs name small changes they need from upstream nodes by loop id (AXX.n, for example A04.1 or A09.1). Two are scheduled items in the graph with their own estimates and rows in §1 (A12.1 and A61.1); they run under their owner's note section and owned paths. For every other loop, the follow-up is **keyed by the loop and by its requester**, because different nodes ask the same loop id for different changes (A04.1, for example, is requested with different column lists by A09, A12, A16, A18, A21, A46 and A104, and A04's migrations are immutable once passed). The requester's Specify step looks up `<AXX.n>-<requester>` (for example `A04.1-A12`) in `status.json`: if it is not passed, it returns the follow-up with the requester's full change list, the run adds it as `<AXX.n>-<requester>` (or `<owner>-fu-<requester>` when the spec names no id) with the owner's paths, note and flags, runs it through the same gauntlet, and starts the requester again once it has passed. Another requester's passed run of the same loop id never counts; if it already landed part of the change, the new run adds the rest and at least the tests that pin this requester's contract. Completion is always read from `status.json`, never from git log text, because many loops change data rows rather than code. A follow-up inherits its owner's `human_gate`: a design-extension loop on A50 (for example A50.2, a founder redraw after a preview) is `blocks-dependents` like A50, so it merges held and its requester waits for the user's HG-REVIEW sign-off of the new drawings; a loop on A51 is `blocks-own-gate`. The time for these loops is the loop allowance in §1, one run per loop id and requester.
- **Graph gate.** When every id in the run has passed, none is escalated, blocked or waiting for a human, and no Critical is open, Fable 5.1 (high) runs the graph QA of [[App Gauntlet]] §9 under the Docker lock. On a fail, each owner node of an open Critical or High finding is reopened: `status.json` goes back to `building` at the `challenge` step with the loop counter raised by one, the findings are passed to the builder's Fix step, and the node goes through the node QA and the merge again (commit `<id>: graph QA fix <round>`). Then the graph gate runs again. The milestone escalates after the second failed round, on an `escalate` verdict, or when a finding's owner node is not in this run (for example a node of an earlier, closed milestone).
- **Locks.** Merges are serialised: the commit, the rebase, the node QA's re-verify and the fast-forward happen for one node at a time. Challenge, re-verify and graph-QA steps that use the Docker stack are serialised by a second lock. The two rules work together: each worktree uses its own compose project name (`REALX_STACK_ID=realx-<node>`), so containers, volumes and networks of different nodes never mix and a stack left behind by one node cannot pollute the next; but every stack binds the same host ports that A08 and A23 fix, so only one stack runs at a time, which is what the Docker lock enforces. The schedule in §1 models it: the stack-bound share of each Docker node's estimate runs one node at a time. Only one milestone run happens at a time.
- **Shared generated files.** `packages\sdk\openapi.json`, `packages\sdk\src\generated\`, the generated files under `packages\mcp\catalogue\` and `apps\web\screens.generated.json` belong to A09, A104 and A52, but every node that adds a route or a screen must regenerate them, because verify byte-diffs them. A01's owned-path check accepts them under its sanctioned-regeneration rule (the generators reproduce them byte for byte from the node's tree). At the merge, a rebase conflict in them is handled like a `package-lock.json` conflict: the clerk takes main's copy, re-runs the generators, stages the result and amends the node's commit; only a conflict in any other file stops the merge.
- **Limits of the runner.** At most 8 agent sessions run at once, and more queue. The Cursor SDK reports no token budget, so `budget.remaining()` is unlimited and `reserveTokens` never trips; a usage limit shows up as a run that does not finish, which stops the run cleanly. A node uses about 12 to 30 agent calls, so AM3's <!--g:ms.AM3.nodes-->23<!--/g--> nodes need roughly 300 to 700, which is a good reason to split AM3 across two usage windows.

## 7. The milestone script

Plain JavaScript in the Workflow format: `export const meta` is a pure literal; the script uses `phase()`, `agent(prompt, {label, phase, model, effort, schema})`, `parallel()`, `log()`, `budget` and `args`. It does not use `Date.now()` or `Math.random()` (the current time comes in `args.now`), and it ends with a top-level `return`. The model ids are Cursor model ids: `claude-opus-5-5-high` (planner, clerk and node QA), `grok-4.7-xhigh` (builder) and `claude-fable-5-1-thinking-high` (graph QA). The id fixes the reasoning effort; the `effort` field is what the script asks for, and the runner records it in the journal. The script is kept in `06 Evidence\Tools\app_plan\orchestration\milestone-workflow.js` and was dry-run on 30 Sep 2026 with simulated agents in 47 scenarios (`node test-workflow.mjs`), all of which behaved as designed. They cover: a clean run; fix loops and escalation after three; usage-limit stops early and mid-milestone; an agent that throws; a graph-QA model that is not Fable 5.1 and a builder that is not Grok 4.7; a previous milestone whose graph gate has not passed; a graph gate that passes, one that fails and reopens its owner node before passing, one that fails twice and escalates, and one whose finding is owned outside the run; a run where only the graph gate is left, and a stop just before it; a changed requirements file; each of the four human-gate modes, pending and approved; follow-ups under a run id and under a spec's own id; the scheduled dotted item A12.1; resuming from each step; bad args; an unconfirmed spec blocked and then accepted; a Depends line that differs from the graph; a dependency outside the run; a human step that parks; a build that parks between sessions, then waits and resumes by `now`; a builder whose transcript touched the hidden oracle, which triggers an oracle rewrite; a follow-up keyed by its requester (`A01.2-A07`); a design-extension follow-up that inherits its owner's blocks-dependents gate; sign-offs recorded in one run and honoured in the next; `nextArgs` that keep every input field; a failed re-verify written to `status.json` before the requeue; and an open Critical that is persisted and holds a resumed run. function standingFailures(v) {
  const f = []
  if (!v.verify.passed) f.push('whole-repo verify is red')
  if (!v.ownedPathsOk) f.push('owned-path check failed')
  if (!v.evidenceMatchesDisk) f.push('evidence does not match disk')
  if (v.hidden.failed > 0) f.push(v.hidden.failed + ' hidden cases failed')
  if (v.designFidelity.applicable && v.designFidelity.failures > 0) f.push('design fidelity failures')
  if (v.gatesServerSide.applicable && v.gatesServerSide.bypasses > 0) f.push('gate bypass')
  if (v.agentParity.applicable && v.agentParity.missing > 0) f.push('UI actions without API/MCP equivalent')
  if (v.makerChecker.applicable && v.makerChecker.bypasses > 0) f.push('maker-checker bypass')
  if (!v.auditOk) f.push('audit events missing or chain broken')
  if (v.findings.some((x) => x.open && (x.severity === 'Critical' || x.severity === 'High'))) f.push('open Critical or High finding')
  return f
}

async function escalate(res, reason) {
  res.state = 'escalated'; res.reason = reason
  criticalHold.delete(res.id)
  try { await call(clerkPrompt(res.id, 'state=escalated critical=0', reason), { label: 'status:' + res.id, phase: 'Merge', model: PLANNER, effort: 'low', schema: CLERK }) } catch (e) { /* stop: reason is in the result */ }
  return res
}

async function park(res, until, key, why) {
  res.state = 'parked'; res.parkUntil = until || ''; res.parkKey = key || ''; res.reason = why
  const kv = 'state=parked' + (until ? ' parkUntil=' + until : '') + (key ? ' parkKey=' + key : '')
  try { await call(clerkPrompt(res.id, kv, why), { label: 'status:' + res.id, phase: 'Merge', model: PLANNER, effort: 'low', schema: CLERK }) } catch (e) { /* stop */ }
  return res
}

async function isolationScan(n, res) {
  const r = await call(isolationPrompt(n), { label: 'isolation:' + n.id + '#' + res.loop, phase: 'Build', model: PLANNER, effort: 'low', schema: ISOLATION })
  if (!r.scanned) { res.isolationScan = 'not run: ' + (r.note || 'no journalDir'); return [] }
  res.isolationScan = 'scanned'
  return (r.hits || []).map((h, i) => ({ id: n.id + '-ISO' + res.loop + '-' + i, severity: 'High', title: 'builder touched the hidden oracle', where: 'workflow journal', detail: h, open: true }))
}

async function runNode(n) {
  const last = n.lastPassedStep || ''
  const res = { id: n.id, state: last ? 'building' : 'not started', lastPassedStep: last, loop: n.loop || 0,
    verdict: last === 'challenge' ? (n.verdict || '') : '', findings: [] }
  let humanRetried = false
  let isoFindings = []
  const opt = (label, phase, model, effort, schema) => ({ label: label + ':' + n.id, phase, model, effort, schema })
  try {
    // Specify
    if (!after(res.lastPassedStep, 'specify')) {
      const s = await call(specifyPrompt(n), opt('specify', 'Prepare', PLANNER, 'high', SPECIFY))
      if (s.followUps && s.followUps.length) { res.state = 'waiting'; res.followUps = s.followUps; return res }
      if (!s.ready && s.waitingOnHuman && !APPROVALS[s.waitingOnHuman]) return park(res, '', s.waitingOnHuman, 'waiting on a human step: ' + s.waitingOnHuman)
      if (!s.ready && !s.waitingOnHuman) return escalate(res, 'not ready: ' + s.reason + (s.openQuestions && s.openQuestions.length ? ' | ' + s.openQuestions.join(' | ') : ''))
      if (!s.ready) return escalate(res, 'not ready after the human step was approved: ' + s.reason)
      res.lastPassedStep = 'specify'; res.state = 'building'
    }
    // Oracle (hidden oracle for core nodes, hidden challenge fixtures for the rest)
    if (!after(res.lastPassedStep, 'oracle')) {
      const o = await call(oraclePrompt(n, false), opt('oracle', 'Oracle', NODE_QA, n.oracle ? 'max' : 'high', ORACLE))
      res.oracle = { version: o.oracleVersion, hash: o.hiddenCasesHash, cases: o.caseCount }
      res.lastPassedStep = 'oracle'
    }
    // Build: decompose, parallel builders, integrate, self-verify
    if (!after(res.lastPassedStep, 'build')) {
      const plan = await call(planPrompt(n), opt('plan', 'Build', PLANNER, 'high', PLAN))
      const parts = await parallel(plan.subtasks.map((t) => () =>
        call(partPrompt(n, plan, t), { label: 'build:' + n.id + ':' + t.key, phase: 'Build', model: BUILDER, effort: 'max', schema: PART })))
      if (stopping) throw STOP
      const b = await call(integratePrompt(n, plan, parts), opt('integrate', 'Build', BUILDER, 'max', BUILD))
      if (b.needsEscalation) return escalate(res, 'builder: ' + b.reason)
      if (b.parkUntil || b.parkKey) return park(res, b.parkUntil, b.parkKey, 'session finished; next session after ' + (b.parkUntil || b.parkKey))
      isoFindings = await isolationScan(n, res)
      res.lastPassedStep = 'build'; res.verdict = ''
    }
    // Challenge and fix loop
    let lastFindings = n.pendingFindings || []
    while (res.verdict !== 'pass') {
      if (res.verdict === 'awaiting-human') {
        if (!approvalOf(n.id)) { res.state = 'challenged'; return res }
        if (humanRetried) return escalate(res, 'QA still reports a missing human sign-off after the approval was recorded')
        humanRetried = true
        res.verdict = ''                       // re-challenge with the approval recorded
      }
      if (res.verdict === 'fail') {
        if (res.loop > MAX_FIX) return escalate(res, 'failed after ' + MAX_FIX + ' fix loops: ' + lastFindings.map((f) => f.title).join('; ').slice(0, 300))
        await call(fixPrompt(n, res.loop, lastFindings), { label: 'fix:' + n.id + '#' + res.loop, phase: 'Build', model: BUILDER, effort: 'max', schema: BUILD })
        isoFindings = await isolationScan(n, res)
        res.verdict = ''
      }
      if (isoFindings.length) {                // the builder saw the oracle: the cases are burned, Fable rewrites them
        const o = await call(oraclePrompt(n, true), { label: 'oracle-rewrite:' + n.id + '#' + res.loop, phase: 'Oracle', model: NODE_QA, effort: n.oracle ? 'max' : 'high', schema: ORACLE })
        res.oracle = { version: o.oracleVersion, hash: o.hiddenCasesHash, cases: o.caseCount, rewritten: true }
      }
      const challenge = () => call(qaPrompt(n, res.loop, SURFACES_PASSED), { label: 'qa:' + n.id + '#' + (res.loop + 1), phase: 'Challenge', model: NODE_QA, effort: n.oracle ? 'max' : 'high', schema: VERDICT })
      const v = await (n.docker ? dockerLock(challenge) : challenge())
      v.findings = v.findings.concat(isoFindings); isoFindings = []
      const failures = standingFailures(v)
      const critNow = v.findings.some((x) => x.open && x.severity === 'Critical')
      if (critNow !== criticalHold.has(n.id)) {        // persist the hold, so a resumed run starts no node while it is open
        if (critNow) criticalHold.add(n.id); else criticalHold.delete(n.id)
        await call(clerkPrompt(n.id, 'critical=' + (critNow ? '1' : '0'), critNow ? 'open Critical finding' : 'Critical finding closed'), opt('status', 'Challenge', PLANNER, 'low', CLERK))
      }
      res.findings = v.findings.filter((x) => x.open)
      res.notApplicable = v.notApplicable || []
      if (v.verdict === 'escalate') {
        criticalHold.delete(n.id); res.state = 'escalated'; res.reason = v.escalationReason
        await call(clerkPrompt(n.id, 'critical=0', 'escalated by QA: ' + v.escalationReason), opt('status', 'Challenge', PLANNER, 'low', CLERK))
        return res
      }
      const mode = n.humanGateMode || 'none'
      if (v.verdict === 'awaiting-human' && failures.length === 0) {
        if (mode === 'blocks-own-gate') { res.verdict = 'awaiting-human'; res.humanGate = v.humanGate; continue }
        log(n.id + ': QA returned awaiting-human but human_gate is ' + mode + '; treated as a software pass')
        v.verdict = 'pass'
      }
      if (v.verdict === 'pass' && failures.length === 0) { res.verdict = 'pass'; res.lastPassedStep = 'challenge'; break }
      if (v.verdict === 'pass') log(n.id + ': QA said pass but the standing criteria failed (' + failures.join(', ') + '); treated as fail')
      res.loop += 1; res.verdict = 'fail'
      lastFindings = res.findings.length ? res.findings : failures.map((t, i) => ({ id: n.id + '-S' + i, severity: 'High', title: t, where: '', detail: t, open: true }))
    }
    // Gate: one merge at a time
    const held = (n.humanGateMode === 'blocks-dependents') && !approvalOf(n.id)
    const merged = await mergeLock(async () => {
      const m = await call(mergePrompt(n), opt('merge', 'Merge', PLANNER, 'medium', MERGE))
      if (m.conflict) return { ok: false, reason: 'rebase conflict outside package-lock.json and the shared generated files: ' + (m.conflictFiles || []).join(', ') }
      const rv = await (n.docker ? dockerLock(() => call(reverifyPrompt(n), opt('reverify', 'Merge', NODE_QA, 'high', REVERIFY))) : call(reverifyPrompt(n), opt('reverify', 'Merge', NODE_QA, 'high', REVERIFY)))
      if (!rv.pass) return { ok: false, refix: rv.findings }
      const f = await call(finalizePrompt(n, m, held), opt('finalize', 'Merge', PLANNER, 'low', FINAL))
      return { ok: f.passed, commit: m.commit, reason: f.note }
    })
    if (merged.refix) {                          // rebased tree broke: back into the fix loop
      res.loop += 1; res.verdict = 'fail'; res.lastPassedStep = 'challenge'; res.findings = merged.refix
      if (res.loop > MAX_FIX) return escalate(res, 'verify failed after rebase and no fix loops remain')
      // record it first: status.json still says challenge = pass, and a stop before the fix would otherwise skip it
      await call(clerkPrompt(n.id, 'state=building step=challenge verdict=fail loop=' + res.loop, 'reverify failed after rebase'), opt('status', 'Merge', PLANNER, 'low', CLERK))
      return Object.assign(res, { state: 'building', requeue: true })
    }
    if (!merged.ok) return escalate(res, merged.reason)
    res.state = 'passed'; res.lastPassedStep = 'gate'; res.commit = merged.commit; res.held = held
    return res
  } catch (e) {
    if (e === STOP) { res.stopped = true; return res }
    const msg = String(e && e.message ? e.message : e).slice(0, 300)
    stopping = stopping || ('agent error: ' + msg)     // an unknown model, a budget ceiling or any thrown error stops the whole run
    res.stopped = true; res.error = msg
    return res
  }
}

// ---------- prepare ----------
phase('Prepare')

SURFACES_PASSED = prep.surfacesPassed || []

  nodes[r.id] = r
}

for (const r of prep.nodes) {
  if (r.state === 'passed') passed.add(r.id)
  if (r.state === 'passed' && r.held && !approvalOf(r.id)) held.add(r.id)

  const kids = Object.keys(nodes).filter((k) => nodes[k].deps.includes(id))

async function schedule() {
while (true) {
  for (const id of [...pending]) {
    const d = deadDep(id)

  }
  if (!stopping) {                          // while a Critical is open, only the held node itself may (re)start

      .sort((a, b) => (rem[b] - rem[a]) || (a < b ? -1 : 1))

      inflight.set(id, runNode(nodes[id]).then((r) => ({ id, r })))
    }

  inflight.delete(id)

  log(id + ': ' + r.state + (r.stopped ? ' (stopped at ' + (r.lastPassedStep || 'start') + ')' : '') + (r.reason ? ' - ' + r.reason : ''))
  if (r.state === 'passed') { passed.add(id); if (r.held) held.add(id) }
  if (r.requeue) { Object.assign(nodes[id], { lastPassedStep: r.lastPassedStep, verdict: r.verdict, loop: r.loop, pendingFindings: r.findings }); delete results[id]; pending.add(id) }
  if (r.state === 'waiting' && r.followUps) {
    for (const fu of r.followUps) {
      // keyed by loop and requester: another requester's passed run of the same loop id never counts for this one
      const fid = !fu.id ? (fu.owner + '-fu-' + id) : /^A\d+\.\d+$/.test(fu.id) ? (fu.id + '-' + id) : fu.id
      if (!nodes[fid]) {           // a design-extension loop inherits its owner's human gate (A50: blocks-dependents)
        nodes[fid] = { id: fid, title: 'follow-up ' + fid + ' for ' + id, notePath: fu.ownerNote, deps: [], oracle: fu.oracle, estHi: 2, docker: fu.docker, ui: fu.ui,
          worktreeMode: 'worktree', humanGateMode: fu.humanGate || 'none', state: 'not started', lastPassedStep: '', verdict: '', loop: 0, humanGate: '', approval: '', specConfirmed: true,
          followUp: { owner: fu.owner, requester: id, change: fu.change } }
        rem[fid] = 2 + (rem[id] || 0)
        pending.add(fid)
      }
      if (!nodes[id].deps.includes(fid)) nodes[id].deps = nodes[id].deps.concat([fid])
    }
    delete results[id]; pending.add(id)
  }
}
}

  if (v.verdict === 'pass' && blocking.length === 0 && v.cleanTree.passed && v.oraclesRerun.failed === 0) { graph.state = 'passed'; graph.head = v.mainHead; break }

    graph.reason = v.verdict === 'escalate' ? ('graph QA: ' + v.escalationReason)
      : outside.length ? ('graph findings owned outside this milestone run: ' + outside.map((o) => o || '(no owner)').join(', '))
      : owners.length === 0 ? 'graph QA failed without a Critical or High finding that names an owner node'
      : ('graph QA failed after ' + MAX_GRAPH_ROUNDS + ' rounds: ' + blocking.map((x) => x.owner + ' ' + x.title).join('; ').slice(0, 300))
    try { await call(clerkPrompt(A.milestone, 'state=escalated loop=' + round, graph.reason), clerkOpt(A.milestone)) } catch (e) { /* stop: reason is in the result */ }
    break
  }
  graph.state = 'challenged'
  try {
    for (const o of owners) {                // reopen: counts against the node's three fix loops
      const n = nodes[o]
      const loop = ((results[o] && results[o].loop) || n.loop || 0) + 1
      Object.assign(n, { reopen: round, state: 'building', lastPassedStep: 'challenge', verdict: 'fail', loop,
        pendingFindings: blocking.filter((x) => x.owner === o).map((x) => ({ id: x.id, severity: x.severity, title: x.title, where: x.where, detail: x.detail, open: true })) })
      await call(clerkPrompt(o, 'state=building step=challenge verdict=fail loop=' + loop, 'graph QA round ' + round + ' reopened it'), clerkOpt(o))
      passed.delete(o); delete results[o]; pending.add(o)
    }
  } catch (e) { break }
  log('graph QA round ' + round + ' reopened ' + owners.join(', '))
  await schedule()
}

const byState = (s) => all.filter((id) => results[id] && results[id].state === s)
const escalated = byState('escalated').map((id) => ({ id, reason: results[id].reason }))
const awaitingHuman = all.filter((id) => waitingHuman(results[id])).map((id) => ({ id, gate: results[id].humanGate || '' }))
const parked = byState('parked').map((id) => ({ id, until: results[id].parkUntil || '', key: results[id].parkKey || '', reason: results[id].reason }))
const heldForHuman = all.filter((id) => held.has(id)).map((id) => ({ id, needs: 'the user\'s sign-off in humanApprovals["' + id + '"] before its dependents start' }))
const milestoneCloseAwaiting = all.filter((id) => passed.has(id) && nodes[id].humanGateMode === 'milestone-close' && !approvalOf(id))
const blocked = all.filter((id) => results[id] && results[id].blockedBy).map((id) => ({ id, by: results[id].blockedBy }))
const rerun = all.filter((id) => !passed.has(id) && !(results[id] && (results[id].state === 'escalated' || waitingHuman(results[id]) || results[id].blockedBy)) && !nodes[id].followUp)
const graphPending = !graphDone() && rerun.length === 0 && escalated.length === 0 && blocked.length === 0 && awaitingHuman.length === 0
return {
  milestone: A.milestone, streams: STREAMS, stoppedBecause: stopping, models: MODELS,
  criticalHold: [...criticalHold],
  passed: all.filter((id) => passed.has(id)),
  escalated, awaitingHuman, parked, heldForHuman, milestoneCloseAwaiting, blocked, rerun,
  graphGate: { state: graph.state, rounds: graph.rounds, head: graph.head, reason: graph.reason, openFindings: graph.findings },
  milestoneClosed: rerun.length === 0 && escalated.length === 0 && blocked.length === 0 && awaitingHuman.length === 0 && milestoneCloseAwaiting.length === 0 && graph.state === 'passed',
  isolationScan: all.filter((id) => results[id] && results[id].isolationScan).map((id) => ({ id, scan: results[id].isolationScan })),
  nextArgs: rerun.length ? resumeArgs(rerun) : graphPending ? resumeArgs(A.nodes) : null,
  results: all.map((id) => results[id] || { id, state: nodes[id].state, notStarted: true }),
}

## 8. The runner

`run-milestone.mjs` loads the script above and supplies the Workflow globals through the Cursor SDK (`@cursor/sdk`): each `agent()` call is a fresh local agent session in `<workspace>` on the model the script names, with no ambient user or project settings loaded. The prompt ends with the step's JSON Schema; the runner takes the last JSON object in the reply, asks once more if it does not match, and returns nothing (a stop) if the second answer does not match either. Every event of every session is written to `journalDir`. The runner exits 0 only when the milestone closed, 2 otherwise, and 1 when it could not start.

```js
// Runs the milestone Workflow script with the Cursor SDK, so each D19 role gets its own model (Grok 4.7 is not
// available to the Claude Code Workflow tool). Supplies the Workflow globals: agent, parallel, phase, log, budget, args.
// Usage (from <workspace>\gauntlet, after `npm install @cursor/sdk`, with CURSOR_API_KEY set):
//   node workflows\run-milestone.mjs workflows\realx-milestone.js runs\AM0-r1.args.json
// Writes journal\<runLabel>\ (one .jsonl per agent label, run.log, result.json) and prints the result.

const [scriptPath, argsPath] = process.argv.slice(2)

if (!apiKey) { console.error('CURSOR_API_KEY is not set'); process.exit(1) }

const ROOT = '<workspace>'
const MAX_AGENTS = 8

const args = JSON.parse(fs.readFileSync(argsPath, 'utf8'))

const note = (m) => { const line = new Date().toISOString() + ' ' + m; console.log(line); fs.appendFileSync(runLog, line + '\n') }

// every role model named in the script must exist for this account; the script's probes then confirm the names
const roleIds = [...src.matchAll(/^const (PLANNER|BUILDER|NODE_QA|GRAPH_QA) = '([^']+)'/gm)].map((m) => [m[1], m[2]])
if (roleIds.length !== 4) { console.error('the script does not define the four D19 role models'); process.exit(1) }
const listed = await Cursor.models.list({ apiKey })
const known = new Set((Array.isArray(listed) ? listed : listed.models || listed.data || []).flatMap((m) => [m.id, ...(m.variants || m.presets || []).map((v) => v.id)]).filter(Boolean))
const missing = roleIds.filter(([, id]) => !known.has(id))
if (missing.length) { console.error('models not available to this key: ' + missing.map(([r, id]) => r + '=' + id).join(', ')); process.exit(1) }

let active = 0
const queue = []
const slot = () => new Promise((res) => { if (active < MAX_AGENTS) { active++; res() } else queue.push(res) })
const release = () => { const next = queue.shift(); if (next) next(); else active-- }

function lastJson(text) {
  const fenced = [...text.matchAll(/```json\s*([\s\S]*?)```/g)].map((m) => m[1])
  for (const f of fenced.reverse()) { try { return JSON.parse(f) } catch { /* try the next block */ } }
  const end = text.lastIndexOf('}')
  for (let i = text.indexOf('{'); i !== -1 && i < end; i = text.indexOf('{', i + 1)) {
    try { return JSON.parse(text.slice(i, end + 1)) } catch { /* try a later start */ }
  }
  return undefined
}
const fits = (v, schema) => !schema || (v && typeof v === 'object' && (schema.required || []).every((k) => k in v))
const fileOf = (label) => path.join(journal, label.replace(/[\\/:*?"<>|#]/g, '_') + '.jsonl')

// agent() returns null when the run did not finish (the script treats that as a stop) and throws when it never started
async function agent(prompt, opts) {
  const { label, model, effort, schema } = opts
  const jf = fileOf(label)
  const rec = (o) => fs.appendFileSync(jf, JSON.stringify(o) + '\n')
  const ask = schema ? '\n\nEnd your reply with one JSON object, in a ```json block, that matches this JSON Schema:\n' + JSON.stringify(schema) : ''
  await slot()
  try {
    rec({ label, model, effort, prompt })
    await using a = await Agent.create({ apiKey, model: { id: model }, local: { cwd: ROOT } })
    for (let attempt = 0; attempt < 2; attempt++) {
      const run = await a.send(attempt === 0 ? prompt + ask : 'Reply again with only the JSON object that matches the schema.')
      rec({ agentId: a.agentId, runId: run.id, attempt })
      let text = ''
      for await (const ev of run.stream()) {
        rec(ev)
        if (ev.type === 'assistant') for (const b of ev.message.content) if (b.type === 'text') text += b.text
      }
      const res = await run.wait()
      rec({ status: res.status })
      if (res.status !== 'finished') { note(label + ': run ' + res.status); return null }
      if (!schema) return text
      const v = lastJson(text)
      if (fits(v, schema)) return v
    }
    note(label + ': no JSON matching the schema after one retry')
    return null
  } catch (e) {
    if (e instanceof CursorAgentError) { note(label + ': did not start: ' + e.message); throw e }
    throw e
  } finally { release() }
}

const parallel = (thunks) => Promise.all(thunks.map((t) => t().catch(() => null)))
const phase = (name) => note('== phase ' + name)
const log = (m) => note(m)
const budget = { total: null, spent: () => 0, remaining: () => Infinity }

const AsyncFunction = Object.getPrototypeOf(async function () {}).constructor
const fn = new AsyncFunction('agent', 'parallel', 'phase', 'log', 'budget', 'args', src)
note('start ' + runLabel + ' (' + roleIds.map(([r, id]) => r + '=' + id).join(', ') + ')')
const out = await fn(agent, parallel, phase, log, budget, args)
fs.writeFileSync(path.join(journal, 'result.json'), JSON.stringify(out, null, 2))
console.log(JSON.stringify(out, null, 2))
process.exit(out && out.milestoneClosed ? 0 : 2)
```

| `finalize:<id>` | planner, Opus 5.5 (clerk) | Merge | Fast-forward of `main`, `status.json` = passed (with `held=1` for a blocks-dependents node, or `held=0` and `approval=` when the sign-off is given) |

The builder is never a verifier, and the node QA never reuses a planner or builder session. The clerk records and merges but never judges code.

## 10. After each milestone

1. The session reports to the user: the passed, held, escalated, waiting, parked, blocked and re-run lists; the graph gate result with its rounds; the open Medium findings recorded with their owner nodes; the oracle-isolation scan result; the agent calls used by model.
2. The milestone's exit node is the founder's checkpoint. For AM1 it is A23 (the whole stack boots in Docker Desktop). For AM3 it is A49 (the money-path smoke, with a one-page "magic inputs" guide). For AM5 it is A61.1 (the full re-run of the Docker Desktop preview of the investor app once every AM5 screen node has passed; A61's HG-REVIEW closes the milestone). For AM6 it is A65, for AM7 A78, for AM8 A89 (the P1 launch in Docker Desktop, closed by the user's P1 software sign-off), and for AM9 A94. The user looks at the result before the next milestone starts.
3. The time estimate is updated from real gate times after AM0, and after any milestone where it drifts by more than a third.
4. Human gates that the finished milestone now needs are listed in the report ([[Human Gates]]). The build never crosses them. Examples are counsel on the T-REX GPL-3.0 licence, vendor contracts (KYC/DVS, bank/NPP, custody, registry) behind the sandbox adapters, the key ceremony for V1-V7, the smart-contract audit, the pentest and go-live.
