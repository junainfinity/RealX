# A05 - Design system package from the prototype tokens

**`packages/ui` is generated from `RealX App.dc.html`: the full colour token table (including the TONE map), the Newsreader / Geist / Geist Mono type scale, radii, spacing and shadows, and the 46 components of the design inventory (56 exports), with the phone-width behaviour decided in the design analysis §6.3; a catalogue page shows every component in every state, a token-diff test against the dc file makes drift fail `npm run verify`, and WCAG AA contrast is measured on the real tokens.**

**Build status:** not started. **Milestone:** AM0 (Foundations). **Lane:** Design. **Planner:** Opus 5.5 (high). **Builder:** Grok 4.7 (xhigh). **Node QA:** Opus 5.5 (high, every loop). **Graph QA:** Fable 5.1 (high, at milestone close).
**Estimate:** 8-12 agent-hours (build, challenge and verify loops).

**Depends on:** [[A01 - Repo scaffold, toolchain and verify command]], [[A02 - Domain ids, money and unit math]] (money, unit and basis-point formatters, branded `Cents`), [[A03 - State machines, gate codes, approval codes and permission matrix as data]] (gate registry `gates.ts`, the 181 states of SM-00..13 and `labels.ts`). All three are AM0, so the milestone is unchanged; A05 starts after A03 passes. (Plan note: the graph data still lists only A01 for A05; the A02 -> A05 and A03 -> A05 edges must be added there.)
**Unlocks:** [[A50 - Design extension A- investor and sponsor screens not in the prototype]], [[A51 - Design extension B- operator console screens not in the prototype]], [[A52 - Web app shells, routing and passkey sign-in (public, investor, sponsor)]], [[A53 - Operator console shell, hardware-key sign-in and approval action pattern]]

**Oracle rule:** this node has no hidden oracle (`oracle: no`); no money, supply or holdings move here. The node QA still writes its Challenge material to `<workspace>\gauntlet\hidden\A05\` before the build starts: its own token extractor for the dc file (independent of the builder's), its contrast script, the scratch-copy mutation patches used in the challenges below, and the fourteen reference-region crops of the prototype (the list is under Challenge). The builder never reads that folder ([[App Gauntlet]] §2). The builder's own token-diff test is public and lives in the package.

This node builds the visual language only. It renders gate labels and status tones; it never decides eligibility, money or approvals. Every rule stays server-side in the API (architecture brief §1.1).

## Build brief

The source of truth is `<workspace>\design\RealX App.dc.html` (921 lines) run by `support.js`. The design folder is read-only; nothing is copied into it and nothing in it is edited. The dc runtime (`<x-dc>`, `<sc-if>`, `<sc-for>`, `{{ }}` bindings, `DCLogic`) is a preview harness and is not ported (design analysis §0).

- `tone.ts` is the TONE map exactly as dc line 740: `green ['#E3EEE8','#1F5E4B']`, `amber ['#F6ECD6','#7A4F00']`, `red ['#F6E1DE','#A3312A']`, `grey ['#ECE8E0','#4A4D52']`, `brick ['#F5E4DB','#9A4524']`, plus the two semantic maps the prototype derives from it: property status (`Open offer` green, `Fully funded` grey, `Coming soon` amber; dc line 760) and approval risk (`High` red, `Medium` amber). For key (a) an unknown machine or state throws in development and renders grey in production; for key (b) an unknown string renders grey and logs in development. Neither form ever falls back to green.
- `type.ts` is the type scale of §1.2: three families with the fallbacks `system-ui, sans-serif` / `serif` / `monospace`; every role from Hero h1 (Newsreader 400 64/1.02, −.025em, `text-wrap: balance`) down to the 8px PDF icon text, as named text styles (`display.hero`, `display.property`, `display.page`, `display.console`, `display.onboarding`, `h2.34/26/24`, `card.30..19`, `logo.26/22`, `body.15/14/13/12/11`, `button.15/14/13/12`, `label.13/12`, `eyebrow`, `kpi.26/24`, `num.30..14`, `pill.11/10`, `th`, `caption.12/11/10`, `pdf.8`), plus the roles the §1.2 table does not name but the dc file uses: `numeral.32` (Newsreader 400 32, green, "How it works" numerals, dc line 82), `title.16` (Geist 500 16, "How it works" step titles, dc line 83), `lead.18` (Geist 400 18 / 1.5, hero lead paragraph, dc line 61), `sub.16` (Geist 400 16, property subtitle, dc line 168), `qty.glyph` (Geist 400 24, the `−` / `+` glyphs of the quantity buttons, dc lines 409 and 411) and `mono.caption.13/14/15` (Geist Mono 400: chart subtitles dc line 217, dark order-summary lines dc line 453, mono input text dc line 486). Base 14px Geist, antialiased; links green underlined with `text-underline-offset: 2px`, ink on hover.
- `radius.ts` (the twelve values the dc file uses: 999 / 14 / 12 / 10 / 8 / 7 / 6 / 5 / 4 / 3 / 2 / 50%; 7 and 5 are the half-height radii of the 14px raise bar on the offer monitor and the 10px price band, and the bar-chart cap `3px 3px 0 0` is a variant of 3), `space.ts` (the paddings, gaps and grid patterns of §1.4, including the 240px sidebar column, 1240px and 1280px content widths, sticky top 20px), `shadow.ts` (featured card `0 30px 60px -30px rgba(23,25,28,.25)`; toast `0 12px 30px rgba(0,0,0,.25)`; nothing else), `photo.ts` (the 135° stripe placeholder gradient).
- Tokens are emitted twice from one source: TypeScript constants and a generated `tokens.css` of custom properties (`--rx-color-ink`, `--rx-font-display`, …). Components use only the tokens; an ESLint plugin in the package (`packages/ui/src/lint/`) forbids raw hex, `font-family` strings and `px` radii in component files (allow-list: `tokens/`) and forbids importing `@realx/ui/dev` outside catalogue, e2e, story and test files. The plugin and the contrast checker are exported for other nodes as `@realx/ui/lint` (a flat-config plugin with a `recommended` config) and `@realx/ui/contrast` (a Node-only function that takes foreground, background and usage role and returns the ratio and the threshold result), so A52, A53, A60, A77 and any other node that composes its own blocks from A05 components apply the same rules to its own folders through its own lint and test steps. A05's own tests cover only `packages/ui`; they do not reach other nodes' folders automatically.
- Fonts: Newsreader (opsz 6..72, 400 and 500, upright only), Geist (400, 500; 600 is loaded by the prototype but never used, so it is not shipped) and Geist Mono (400, 500) are vendored as woff2 under `packages/ui/fonts/` with their SIL OFL licence files, served with `font-display: swap`. No request to Google Fonts from the product (the prototype's `<link>` on dc line 12 is the reference for weights only). A test asserts the package contains no `fonts.googleapis.com` string. The prototype's link loads no Newsreader italic, so the browser synthesises the italic of the logo "X"; the package ships no italic file either and lets the logo's `font-style: italic` synthesise the same way (`font-synthesis: style` on the logo only), so the logo matches the prototype glyph for glyph. Swapping in a true Newsreader italic is a visual change and would first need a DF finding and the founder's approval.
- `tokens.json` (generated, committed) is the machine-readable table used by the token-diff test, by A50/A51 (design extensions) and by the e2e fidelity checks in later nodes.
- `design-source.json` records the SHA-256 of `RealX App.dc.html` and of `support.js` at the time of generation, so a changed design file is detected (lesson 13c of the OddX QA trail). The values must equal the ones A00 recorded in `docs\charter\design-baseline.json` (`8ef1e73c…` and `8fe7df74…`); a test compares the two files.

**2. Token-diff test (`packages/ui/test/token-diff.test.ts`, runs in `npm run verify`)**
- Reads the dc file from the folder named by the env var `REALX_DESIGN_DIR`, defaulting to `<workspace>\design\` (the folder A00's `docs\charter\design-baseline.json` records; the same source A01's design-untouched check uses). It does not read `packages/config`, which A08 owns and which may be built in parallel. When the file is absent the test fails. The one exception is an explicit `CI=true` in the environment: then it is skipped with a loud warning and the skip is written into the verify JSON and the evidence (`tokenDiff: "skipped-ci"`). Under `RUN_MODE=local` or with `RUN_MODE` unset, a missing file fails, and the gate accepts only a run in which the test actually executed.
- Extracts every hex colour (template markup and the `data-dc-script` block, so the TONE map and the `#FBFAF7 / #17191C / #E3DED4` values built inside `renderVals()` are covered), every `font:` shorthand, `font-family` and standalone `font-size`, every `border-radius`, `box-shadow`, `letter-spacing` and `max-width` value.
- Fails when: a hex in the dc file is not in `colors.ts`; a `colors.ts` value is not in the dc file (dead token); the font check fails in either direction (every distinct dc `font:` shorthand, keyed by weight, size, line height and first family, and every standalone `font-size` maps to a role in `type.ts`, and every role in `type.ts` maps back to a shorthand or size in the dc file); a `letter-spacing` value in the dc file is not carried by a role, or a role carries one the dc file does not use; a `max-width` value in the dc file is missing from `space.ts`, or the content widths are not 1240 and 1280; a radius or shadow differs; the SHA-256 in `design-source.json` no longer matches the file. The failure message names the token, the dc line number and both values.
- Expected counts are asserted (35 distinct colour tokens including white, with `#fff` normalised to `#FFFFFF`; 5 TONE entries; 3 families; 46 distinct `font:` shorthands, not counting `font:inherit`; 7 standalone `font-size` values (11, 12, 13, 14, 15, 16, 18px); 6 `letter-spacing` values (−.025em, −.02em, −.015em, .05em, .06em, .08em); 7 `max-width` values (520, 680, 720, 760, 900, 1240, 1280px); 12 radius values; 2 shadows; 2 `rgba()` values, both inside the shadows) so a silently shrinking extractor also fails. These counts were measured on the dc file on 24 Sep 2026 and are the reference for the node QA's independent extraction.

**4. Phone-width behaviour (design analysis §6.3, decided here)**
- Public and investor components must work at 375px: `PublicHeader` collapses its nav into a menu button below 768px; card grids use the design's `auto-fill minmax(280px,1fr)` and therefore go single-column; two-column sections stack; `DataTable` scrolls horizontally inside its card while the page never scrolls horizontally; `QuantityStepper`, `OrderSummaryAside` and `Timeline` fit 343px content width; minimum 16px side gutter.
- Every public or investor component has a phone rule below `bp.phone`, not only the shell frames: `HoldingRow` stacks into a card (thumbnail and name, then Tokens / Value / Gain / Monthly income as a 2 x 2 grid, then the Buy / Sell buttons); `FeeRow` stacks name and value over the description; `KeyValueList` puts each label above its value (the 160px label column goes); `BarChart` keeps its bar widths and scrolls horizontally inside its card; `WalletCard` goes single-column and its `ValueChip` wraps or truncates through `truncateAddress`; `GateRow` keeps the 52px id column and moves the pill under the text; `VerticalStepper` becomes a compact "Step n of 8" row and stops being sticky; `HorizontalStepper` shows the labels on two lines; `FactsGrid` and `KpiGrid` drop to one or two columns. Console components (`KycReview`, `ApprovalDetail`, `TokenOpRow`, `DistributionChain`) stack their grids below `bp.console` so they never force a page scroll, even though consoles are desktop-first.
- A Playwright check at 375px visits every catalogue entry and asserts the entry frame's `scrollWidth` does not exceed its `clientWidth`. The only allowed horizontal scrollers are inside cards and are listed by name: `DataTable`, `Tabs`, `BarChart`. The check reads its list of entries from the export map, so a new component cannot skip it.
- Consoles are desktop-first: `SponsorSidebar` and `AdminSidebar` collapse to an off-canvas drawer with a menu button below 1024px; content `max-width` 1240 / 1280 as designed.
- Breakpoints are tokens (`bp.phone 768`, `bp.console 1024`) so screens and tests use the same numbers.
- Dark mode is not built; tokens are named so it can be added later.

**6. Accessibility (requirement N11, measured here, not assumed)**
- `packages/ui/test/contrast.test.ts` computes WCAG 2.x contrast for every foreground/background pair the components actually use (generated from the components' token usage, not a hand list). Each usage carries a role tag in the component's style declaration: `text`, `large-text`, `ui-boundary`, `state-graphic` or `decorative`. An untagged usage fails the test. Thresholds per role: `text` 4.5:1; `large-text` 3:1; `ui-boundary` and `state-graphic` 3:1 unless the pair is listed in DF-A05-01 with its non-colour cue; `decorative` is not measured. Focus indicators are `ui-boundary`. Reference values from the analyst's measurement, which the builder's test must reproduce within ±0.01: ink on cream 15.76; text.2 on cream 8.22; text.3 on cream 5.56; green on cream 6.81; white on green 7.61; green pill 6.40; amber pill 6.07; red pill 5.53; grey pill 6.94; brick pill 5.23; brick.text on brick.tint 6.94; muted.dark on ink 8.53; dark.text on dark.1 13.16; **dark.muted on dark.1 4.85 (the thinnest text margin; keep, do not darken the surface)**; dark.muted2 on dark.2 5.38; nav.inactive on dark.1 9.61; green.onDark on dark.1 8.40; green on green.soft 5.80. All text pairs pass AA.
- Non-text contrast (WCAG 1.4.11, 3:1 for control boundaries): the design's input border `#D6D0C4` on cream measures 1.37:1 and the card border `#E3DED4` on white 1.34:1. This node keeps the design's borders unchanged and satisfies 1.4.11 through the visible green focus outline (6.81:1 on cream), the `bg.input` background step and the always-present label. **7. Package contract**
- `@realx/ui` exports `tokens`, `components`, `format`, `gateLabel`, `toneFor`; `@realx/ui/tokens.css` is the stylesheet; `@realx/ui/lint` and `@realx/ui/contrast` are the tooling entries described in §1 (built, but never imported by app code at runtime).
- `@realx/ui/dev` exports only the catalogue fixtures. It is a **source-only** export: the `exports` map lists `./dev` only under the `development` condition, pointing at `src/dev/index.ts`; it is not built into `dist/`, and `src/dev/` is not in the package's `files` list. A production build that resolves `@realx/ui/dev` therefore fails to resolve instead of shipping fixtures. The `@realx/ui/lint` plugin forbids importing `@realx/ui/dev` from any file outside `**/catalogue/**`, `**/e2e/**`, `**/*.test.*` and `**/*.stories.*`.
- There is no reserved `src/ext/` folder. A05 owns all of `packages/ui/` (as the graph data says) and adds nothing there on other nodes' behalf. Blocks that the design extensions specify (A50, A51) are coded by the UI nodes that own each surface, in their own folders, composed from A05 components and `tokens.json` values, and those nodes apply `@realx/ui/lint` and `@realx/ui/contrast` there.

The token-diff, contrast and unit tests are Vitest files picked up by A01's step 7; the verify JSON must show them as run (not skipped) with their test counts. After adding the block the builder runs `npm run scripts:sync` and commits the regenerated root targets, never hand-editing A01's root files.
- **Evidence path.** The manifest `app\evidence\A05.json` and the node QA's `app\evidence\A05.qa.md` are the only files A05 writes outside `packages\ui\`, under the plan-wide evidence carve-out raised in A01-check1 (a node may add or change only `evidence\<its id>.json` and `evidence\<its id>.qa.md`). Screenshots and the contrast table are written inside the owned path at `packages\ui\evidence\` and are referenced from the manifest by relative path.

## Node-specific challenges (node QA)

- **Design fidelity, hidden colour.** The node QA changes one hex in a scratch copy of the dc file (say TONE amber background `#F6ECD6` to `#F6ECD7`) and points the token-diff test at the copy: the test must fail and name the token, the dc line and both values. It then adds a raw `#1F5E4B` inside a component file: lint must fail. It deletes the `numeral.32` role from `type.ts` (the dc shorthand is then unmapped), then adds a role with a size the dc file never uses, then changes one `letter-spacing` in a scratch dc copy: each must fail the two-way font check with the dc line. It unsets `CI` and points `REALX_DESIGN_DIR` at an empty folder: the token-diff test must fail, not skip. It then renders `FeaturedCard` with a "Coming soon" property: the pill must be amber, not the hard-coded "Open offer" green.
- **Money formatting.** `@realx/ui`'s `formatAud` must be the identical function object as `@realx/domain`'s (same for `formatAudCompact`, `formatUnits`, `formatUnitsOf`, `formatBp`). Fed `239592n`, `5n`, `0n`, `-100000n` and `1852000000n` cents it must print `A$2,395.92`, `A$0.05`, `A$0.00`, `-A$1,000.00` (A02's convention, hyphen-minus) and `A$18,520,000.00`. A fixture file that calls `formatAud(2395.92)` must make `tsc` fail (`Cents` is a branded bigint, so a float cannot reach the function); the test runs `tsc` on the fixture and expects the type error. The node QA then plants a local `formatAud` in `format/` that divides a number by 100: lint (A01's no-float-money rule) must fail.
- **Dates across daylight saving.** `formatDateTimeAu` in `Australia/Sydney` must print `AEDT` just before 3:00 on 5 Apr 2026 and `AEST` just after, `AEST` just before 2:00 on 4 Oct 2026 and `AEDT` just after; the seed's 22 Sep 2026 prints `AEST` and Kent Street's 14 Oct 2026 close (and Ann Street's 2 Nov) print `AEDT` with the correct local hour; the same instant in `Australia/Brisbane` prints `AEST` one hour earlier. `OrderSummaryAside` is given lines that do not sum to the total: it must render exactly what it is given and never recompute (the API is authoritative). `QuantityStepper` with `max 480` must not let the `+` button pass 480 and must show the maximum in its label.
- **Compliance semantics.** The node QA renders a recon row with status "Break · 2 units" and a KYC check "PEP screen: Review" through `toneFor`: both must be red, never green or grey; "Frozen" must be red; "Separate" (the operating account) must be grey; an unknown status must not default to green (it defaults to grey and logs in development). The node QA deletes the `tone.ts` entry for one A03 state (any terminal state of SM-06, for example): the exhaustiveness test must fail naming the machine and state. `gateLabel` must return A03's title for all 22 ids, with `gateLabel("G22")` = "Agent authority"; after the node QA changes one title in a scratch copy of A03's `gates.ts`, `gateLabel` must follow it (no second copy of titles); `gateLabel("G23")` must throw in development. `PriceBand` or `RaiseBar` rendered without the band or soft-cap props must fail `tsc`, not render a default band.
- **Authority never lives in the component.** `SignatureMeter` is rendered with `signatures: 2, canBroadcast: false`: the button must stay "Sign", because broadcast readiness comes from the server. `ApprovalDetail` is rendered for a user flagged as the maker: it must display the SoD note and disabled buttons exactly as the props say, with no local override. `AcknowledgeCard` unchecked must not enable a sibling "Confirm and pay" button on its own.
- **Security and privacy of the package.** The built `dist` must contain no `fonts.googleapis.com`, no `DevRoleSwitcher`, no catalogue fixtures (the mock investor "Alex Morgan", PayID or wallet strings), no `eval`, and the components must make no network request when rendered in jsdom (a fetch spy stays at zero). `TextField` masked variant, unfocused and after blur, must show only the mask, and a scan of every attribute (including `data-*`, `aria-*`, `title`, `placeholder`) and every text node must not contain the raw TFN or account number; while focused only the input's `value` property may hold it. The node QA plants `import { fixtures } from '@realx/ui/dev'` in a non-test source file of a scratch consumer: the `@realx/ui/lint` rule must fail, and a production build of that consumer must fail to resolve the import.
- **Verify wiring.** The node QA removes the `realx.verify` block from `packages/ui/package.json` in a scratch clone and runs `scripts:sync` and `npm run verify`: verify must go red (step 12 or a missing-step check), proving the package's lint, dist, axe and phone-width steps really run inside `verify`. It also plants a raw hex in a component and confirms the failure comes from the `ui:lint` step, not from a manual run.
- **Phone width.** At 375px the catalogue's public investor frame and the sponsor frame must show no horizontal page scroll (`document.documentElement.scrollWidth === 375`), a 16px gutter, a collapsed header nav and an off-canvas sidebar; `DataTable` may scroll inside its card only. The per-entry run at 375px must pass for every catalogue entry, with only `DataTable`, `Tabs` and `BarChart` scrolling inside their cards; the node QA widens `HoldingRow`'s grid back to the desktop columns in a scratch copy and the run must fail naming that entry. At 1024px and 1280px the sidebars are visible and `AdminSidebar` is 240px wide.
