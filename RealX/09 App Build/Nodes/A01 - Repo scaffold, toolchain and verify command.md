# A01 - Repo scaffold, toolchain and verify command

**One git repository at `<workspace>\app` with npm workspaces, strict TypeScript, lint with the module-boundary rule, format, unit and e2e test runners, secrets scanning, a Postgres 17 base compose file, a frozen commit and worktree policy for parallel nodes, and a single `npm run verify` that every later node must pass; every version pinned after a real install on Node 24.21.0, with what worked and what did not written down.**

**Build status:** not started. **Milestone:** AM0 (Foundations). **Lane:** Platform. **Planner:** Opus 5.5 (high). **Builder:** Grok 4.7 (xhigh). **Node QA:** Opus 5.5 (high, every loop). **Graph QA:** Fable 5.1 (high, at milestone close).
**Estimate:** 5-7 agent-hours (build, challenge and verify loops).

**Depends on:** [[A00 - Charter and acceptance baseline]]
**Unlocks:** [[A02 - Domain ids, money and unit math]], [[A05 - Design system package from the prototype tokens]], [[A07 - Local chain and contracts toolchain (Hardhat, T-REX vendored)]], [[A08 - Sandbox adapter framework, config and phase flags]]

**Oracle rule:** this node has no hidden oracle (`oracle: no`); no money, supply or holdings move here. The node QA still prepares its Challenge material before the build starts: the fault-injection patches and the clean-clone procedure listed under Pass criteria are written to `<workspace>\gauntlet\hidden\A01\` and the builder never reads that folder ([[App Gauntlet]] §2).

## Build brief

This is the first node that writes code. It turns the folder A00 created (which holds `app\docs\charter\` and `app\evidence\A00.json`) into a repository that the other 100-odd nodes build inside. Nothing in it is product behaviour; everything in it is an invariant that later nodes inherit. Each bullet is testable.

**Repository**

- `git init` at `<workspace>\app` on branch `main`, no remote, never pushed. `<workspace>` itself stays a plain folder (the vault, the design and the research pack are not in the repo).
- `.gitattributes`: `* text=auto eol=lf`, with `binary` set for images, fonts, PDFs and `.keystore` files. `.gitignore`: `node_modules`, `dist`, `.next`, `coverage`, `playwright-report`, `test-results`, `contracts/artifacts`, `contracts/cache`, `.env` and `.env.*` (except `.env.example`), `*.keystore`, `*.pem`, `*.key`, editor folders.
- **Git settings survive a clone.** Git for Windows sets a system-level `core.autocrlf=true`, and repo-local settings are not cloned. The root `prepare` script (`tsx scripts/prepare.ts`, listed in `scripts\root-scripts.json`, so `npm ci` and `npm install` run it) idempotently sets the repo-local `core.autocrlf false` and `core.hooksPath scripts/git-hooks`, prints what it changed, and no-ops with a one-line notice when not inside a git work tree. `.gitattributes` `eol=lf` keeps checked-out files LF even before `prepare` runs. `npm run hooks` remains as a manual alias for the same script.
- **Evidence folder (shared, per-node files).** `app\evidence\` is a shared folder with no single owner. A node may add or change only its own files there: `evidence\<id>.json`, `evidence\<id>.qa.md` and anything under `evidence\<id>\` (screenshots, logs, the verify JSON). A00's `evidence\A00.json` (and any other `evidence\A00*` files A00 wrote) is committed in A01's first commit. Every `evidence\*.json` manifest must validate against A00's `docs\charter\evidence-manifest.schema.json`; verify step 10 checks this with `scripts\check-evidence.ts` (using `ajv`).
- **Commit policy (frozen here, applied by the orchestrator):** one local commit on `main` per passed node, made only after the node QA's gate passes, message `<node>: <title> (gauntlet pass)`, no commits during a build or a fix loop by the builder. The first commit is `A01: repo scaffold (includes A00 charter)` and is staged with explicit pathspecs, never `git add -A`: `docs\charter\`, `evidence\A00*`, `evidence\A01*` and A01's owned paths. The gauntlet's `status.json`, the hidden oracles and the node QA's working files live outside the repo at `<workspace>\gauntlet\`; no tracked file may carry those paths (see the hygiene step).
- **Parallel nodes: one worktree per node (frozen here, because A01 owns the commit policy).** Up to three nodes may build at once. From A01's commit on, the orchestrator gives every node its own git worktree and branch: `git worktree add <workspace>\worktrees\<id> -b node/<id> main`. The builder works, runs `npm ci` and runs verify only inside that worktree, so a sibling's half-built files can neither appear in this node's owned-path check nor turn this node's verify red. Owned paths in every node spec are written against `<workspace>\app\` and are read as repo-relative paths, so they apply unchanged inside a worktree. At the gate: the orchestrator commits the node's work on `node/<id>` as one commit, rebases it onto the current `main`, the node QA re-runs the full verify and the owned-path check on the rebased tree (a rebase conflict in anything but `package-lock.json` is an owned-path defect and escalates; a lockfile conflict is resolved only by re-running `npm install` on the rebased tree and re-verifying), and then `main` is fast-forwarded to that single commit. The worktree and branch are removed after the merge. `<workspace>\worktrees\` is orchestrator state, not a tracked path.
- **Nodes that start before the repository exists.** A01, A50 and A51 all unlock from A00 and may run while no `main` exists yet; A50 and A51 write only inside `app\design-ext\`. A01's builder never touches, lints, formats or stages `design-ext\`: verify ignores untracked paths that `check-owned-paths` is told belong to another in-flight node (`--exclude-inflight <paths-file>`), A01's first commit uses the explicit pathspecs above, and A01's gate candidate is built by the node QA in a scratch repository from exactly that pathspec set (see Challenge). A50 and A51 are committed by their own gates with their own pathspecs; after A01's commit, any node that has not started uses a worktree.
- **Docker in parallel worktrees.** Compose steps read `REALX_STACK_ID` (default `realx`) for the compose project name, and the orchestrator sets `realx-<id>` per worktree, so two worktrees never share a volume; Docker-using gauntlet steps are additionally serialised by the orchestrator with one machine-wide lock.
- `.npmrc`: `save-exact=true`, `engine-strict=true`, `fund=false`, `audit=false` (the audit runs as an explicit verify step, not on every install), `ignore-scripts=false`. Install scripts are enforced, not merely documented: every `package-lock.json` entry with `hasInstallScript: true` must be listed in `scripts\toolchain.json` under `installScripts` with the package, the version and a reason; verify step 2 fails on an unlisted one. Root `package.json`: `private: true`, `name: realx-app`, `engines: { node: ">=24.21.0 <25", npm: ">=11" }`, `packageManager: npm@<exact version found on the machine>`.

**Workspaces and TypeScript**

- npm workspaces declared as globs: `apps/*`, `services/*`, `packages/*`, `packages/adapters/*`, `contracts`, `e2e`, `scripts`. A01 creates only the `scripts` workspace (`@realx/scripts`); the other folders are created by the nodes that own them (A02 `packages/domain`, A05 `packages/ui`, A07 `contracts`, A08 `packages/adapters/core` and `packages/config`, and so on). Verify iterates over whatever workspaces exist, so the scaffold is valid with one workspace and stays valid at one hundred.
- `tsconfig.base.json`: `strict`, `noUncheckedIndexedAccess`, `exactOptionalPropertyTypes`, `noImplicitOverride`, `noFallthroughCasesInSwitch`, `verbatimModuleSyntax`, `module`/`moduleResolution` `NodeNext` for services and packages (the Next.js apps override to `bundler` in their own tsconfig, nothing else), `target ES2023`, `lib ES2023`, and `paths` for `@realx/*` mapped to each workspace's `src/index.ts`. Every workspace tsconfig must `extends` the base; a config lint in verify fails any workspace that re-enables a laxer setting (`strict: false`, `skipLibCheck` on a source project, `noUncheckedIndexedAccess: false`).
- Dependencies pre-installed at the root so later nodes rarely add packages: `typescript`, `next` with `react`/`react-dom` 19, `fastify` 5 with the zod type provider and `@fastify/swagger`, `zod` 4, `drizzle-orm` and `drizzle-kit`, `pg`, `pg-boss`, `@simplewebauthn/server` and `@simplewebauthn/browser` 13, `viem` 2 and `wagmi`, `pino` and `pino-pretty`, `vitest` with `@vitest/coverage-v8`, `fast-check`, `@playwright/test` with Chromium installed once, `eslint`, `typescript-eslint`, `prettier`, `tsx`, `dotenv`, `ajv`. Hardhat, the T-REX submodule and the account-abstraction packages are not installed here; A07 owns that toolchain because the Hardhat 2 versus 3 trial belongs with it.
- **Majors are floors, not fixed, unless stated.** Floors: TypeScript 5.9, Next 15, React 19, Fastify 5, zod 4, pg-boss 10, SimpleWebAuthn 13, viem 2, Vitest 3.2, ESLint 9, Playwright 1.5x. On build day the builder takes the newest stable major on the npm registry at or above each floor, subject to these compatibility bounds, which are the only fixed rules: TypeScript is the newest major inside the resolved `typescript-eslint` peer range; `react`/`react-dom` are the major the resolved `next` peer range requires; `@simplewebauthn/server` and `/browser` share one exact version; `vitest` and `@vitest/coverage-v8` share one exact version. For every package `toolchain.json` records the floor, the resolved version, the rule applied and the upstream support status on build day (active, maintenance with end date, or end-of-life). Choosing an older major than the newest stable because the newest failed on Node 24.21.0 is recorded, not escalated; failing to meet a floor is escalated.
- Pinning is done from a real install, not from memory: the builder runs `npm install` on Node 24.21.0, records `node -v`, `npm -v`, the date, each top-level package with the version that actually resolved, any package that failed to install or to typecheck on this Node line and the alternative chosen instead, into `scripts\toolchain.json` and a "Toolchain record" section of `README.md`. Package versions are exact (no `^` or `~` anywhere in any `package.json`); the lockfile is committed; a verify test asserts both.

**Lint, format, tests**

- `eslint.config.js` (flat config): `typescript-eslint` recommended-type-checked, `no-floating-promises`, `no-explicit-any` as an error, `no-console` outside `scripts`, `linterOptions.reportUnusedDisableDirectives: 'error'`, `no-restricted-imports` blocking any import whose specifier contains a `gauntlet/` segment and any absolute drive path (`E:\`, `E:/`), and the **module-boundary rule** as a local rule in `scripts\eslint-rules\module-boundaries.js` (no third-party boundary plugin): a module under `services/api/src/modules/<a>/` may import another module `<b>` only through `modules/<b>/index.ts`; `apps/*` may import `packages/*` but never `services/*`; `packages/domain` imports no other workspace; `packages/*` never import `apps/*` or `services/*`; `contracts` is imported by nothing except `packages/contracts`; the rule resolves relative paths, `@realx/*` aliases, `require()` and dynamic `import()` alike. The rule ships with its own unit tests in `scripts` using fixtures, so a later node cannot break it silently.
- A third local rule, `scripts\eslint-rules\no-weakening-disables.js`, reads every comment and fails on: a blanket or file-level disable (`/* eslint-disable */` with no rule list, or any `eslint-disable` block comment that is not closed by `eslint-enable` in the same file); any disable, on any line, of `module-boundaries`, `no-float-money`, `no-weakening-disables`, `@typescript-eslint/no-floating-promises` or `@typescript-eslint/no-explicit-any`; and a `/* eslint ... */` inline config comment that turns any of those rules off or down. Line-level disables of other rules stay allowed but must name the rule and carry a `-- reason`.
- A second local rule, `scripts\eslint-rules\no-float-money.js`, is the scaffold's half of the integer-money invariant that A02 owns. Outside `packages/domain` (and its tests) it forbids `parseFloat` and `.toFixed(` whose result or argument is a money-named value (below), and it forbids any `*`, `/`, `+` or `-` expression where at least one operand is money-flavoured: an identifier or member whose name ends in `cents`, `Cents`, `amount`, `Amount`, `price`, `Price`, `units`, `Units`, `bps` or `Bps`; a value typed as one of `@realx/domain`'s money or unit types (checked through type information once A02 exists); or a value that flowed directly from `parseFloat`, `Number(...)` or `.toFixed(`. Such an expression is legal only as a call into `@realx/domain`. Plain layout, chart, animation and design-token maths are not money-flavoured and stay legal: fixtures prove `width * 1.5`, `opacity - 0.1`, `index / total` and `Number(px) * 2` in an `apps/*` file pass, and `units * price`, `amount.toFixed(2)`, `parseFloat(amountText)` and `priceCents / 100` fail. It ships with fixture tests like the boundary rule. Money and unit arithmetic therefore has exactly one home from the first commit, before any module exists to get it wrong.
- `.prettierrc`: single quotes, semicolons, trailing commas `all`, print width 100, `endOfLine: lf`; `prettier --check` is a verify step.
- Vitest config for the whole repo lives at `scripts\vitest.config.ts` (not a root file) as `defineConfig({ test: { projects: [...] } })`, with one project per workspace that has tests (workspace files and `defineWorkspace` are not used; they are deprecated from Vitest 3.2 and removed in 4). It is run as `vitest run --config scripts/vitest.config.ts`. `passWithNoTests` is off, so a workspace that declares `src/**/*.test.ts` but collects zero tests fails verify. Coverage is collected per workspace with `@vitest/coverage-v8`; thresholds are set by the owning nodes, not here.
- Playwright is installed and Chromium downloaded (`npx playwright install chromium`, recorded in `toolchain.json`); the e2e project, its config and the visual-fidelity checks are owned by later nodes. A01 only proves the binary runs: `scripts\playwright-smoke.ts` opens `about:blank` headless and exits 0.

**`npm run verify`**

- One command, implemented as `scripts\verify.ts` (run with `tsx`, works identically in PowerShell and Git Bash, no bash-only step), run from the repo root (or a node worktree root) and resolving every path relative to that root, never to `<workspace>\app`. It runs these steps in order and stops at the first failing group, printing one line per step with `PASS`/`FAIL`, the duration and, for a failure, the workspace and file:
  1. **Environment:** Node and npm versions match `engines`; `py --version` reports Python 3.13; repo-local `core.autocrlf` is `false` and `core.hooksPath` is `scripts/git-hooks` (both set by `prepare`; the failure message says "run npm ci or npm run hooks"); no tracked file has CRLF (`git ls-files --eol`); `RUN_MODE` is `local` or unset.
  2. **Lockfile:** `npm ls --all` exits 0; `package-lock.json` matches every `package.json`; every lock entry with `hasInstallScript: true` is listed in `toolchain.json` `installScripts` with a reason.
  3. **Typecheck:** `tsc --noEmit -p` for every workspace with a tsconfig.
  4. **Config lint:** tsconfig strictness (above); no vitest config in any workspace (or `scripts\vitest.config.ts`) sets `passWithNoTests`, and no workspace config is used outside the root projects list; every workspace `test` script invokes `vitest` (a `test` script that does not, such as `echo ok`, fails); every tsconfig `extends` the base.
  5. **Lint:** `eslint .` including the boundary, no-float-money and no-weakening-disables rules, with unused disable directives as errors.
  6. **Format:** `prettier --check .`
  7. **Unit tests:** `vitest run --config scripts/vitest.config.ts`.
  8. **Audit:** `npm audit --audit-level=high`, with an allowlist at `scripts\audit-allowlist.json` where each entry names the advisory, the reason and an expiry no more than 30 days out; an entry with no expiry or an expired entry fails verify; a network failure fails verify (fail closed, no silent skip).
  9. **Secrets scan** (below).
  10. **Charter, design and evidence:** the design-untouched check (below); `verify:charter`, which runs A00's checker repo-relative from the root as `py docs/charter/check_charter.py` with the vault graph path passed explicitly (see below) and fails on a non-zero exit; and `check-evidence`, which validates every `evidence\*.json` against `docs\charter\evidence-manifest.schema.json`.
  11. **Registered workspace steps** (see "Script registration" below), in workspace order.
  12. **Repository hygiene:** no tracked file matches a gauntlet path pattern outside the exemption list (below); the root `package.json` scripts block, the generated block of `.gitignore` and `scripts\verify-steps.lock.json` equal what `scripts:sync` produces; and verify changed nothing: `git status --porcelain=v1 --untracked-files=all` taken at the start and at the end of the run are identical, except for the `--json` output file when one was requested.
- **`--json` output.** `npm run verify -- --json <path>` writes the step results as JSON. The path must be outside the repo or inside `evidence\<id>\` for the node being verified (the gauntlet convention is `evidence\<id>\verify.json`); any other in-repo path is refused before step 1. `npm run verify -w <workspace>` scopes steps 3-7 and 11 to one workspace for fast loops.
- **Vault graph path for `verify:charter`.** The repo never hard-codes or reads the vault by itself. `verify:charter` reads the graph path from the `REALX_APP_GRAPH` environment variable; when it is unset it uses the documented default `<workspace>\RealX\09 App Build\Data\app-graph.json`, printed on the step line. A missing or unreadable graph file fails step 10 loudly with the path it tried (never "skipped"). The dependency is declared in the README prerequisites. The path is handed to A00's checker as `--graph <path>` and also exported as `REALX_APP_GRAPH` to the checker's process.
- **Script registration** (`scripts\scripts-sync.ts`, `npm run scripts:sync`): later nodes never hand-edit A01's root files, yet A06, A07, A08, A09 and A13 all need root npm scripts, extra verify steps and gitignore lines. The root `package.json` `scripts` block, a marked `# registered by workspaces` block at the end of `.gitignore`, and `scripts\verify-steps.lock.json` are generated: A01's own entries come from `scripts\root-scripts.json`, and every workspace may declare in its own `package.json` a `realx` block with `rootScripts` (name to command, for example `"chain:up": "npm -w contracts run chain:up"`), `verify` (a list of `{ step, group, run, scope }` where `group` is one of `build`, `lint`, `test`, `check`) and `gitignore`. The sync merges them deterministically (sorted by workspace path then name), refuses a name that collides with A01's scripts or with another workspace's, refuses a registered step that names one of A01's steps 1-10 or 12, and writes the three generated targets. **Gitignore lines are confined to the registering workspace:** each line is written relative to the repo root and must resolve inside that workspace's own folder (for example `contracts/artifacts/` from `contracts`); the sync refuses any line that starts with `!`, contains `..`, is absolute, resolves outside the workspace folder, or matches a file that is currently tracked, each with a message naming the workspace and the line. Verify step 12 fails if the committed targets differ from a fresh sync, so a node that registers inside its owned path and runs the sync is green, and a node that types into `package.json` by hand is red.
- **`RUN_MODE`**: `infra\base\.env.example` sets `RUN_MODE=local`, the README defines it as the switch every later config layer reads (A08's `packages/config` validates it and refuses a live adapter under `local`; A07's chain guard refuses a non-loopback RPC under it), and verify step 1 fails if the shell environment sets `RUN_MODE` to anything other than `local` or unset. The scaffold knows one value; adding others is A08's decision.
- Verify does not need Docker. A separate `npm run verify:infra` boots the base compose file, waits for a real query to succeed, runs `SELECT version()` to confirm Postgres 17, and tears down.
- **Secrets scan** (`scripts\secrets-scan.ts`): scans every tracked and staged file (including `evidence\`, Markdown and JSON fixtures). Detection is context-aware so that the hashes this build legitimately stores (A00's design baseline, evidence `artifactHashes` and `hiddenCasesHash`, the allowlist's own SHA-256 values, later transaction hashes) never need allow-listing:
  - Always a finding: `-----BEGIN ... PRIVATE KEY-----` blocks; mnemonic runs of 12 or 24 BIP-39 words, including runs split across adjacent lines or JSON array items; cloud and registry tokens (AWS, GitHub, npm, Slack); JWTs; RealX's own API tokens (below).
  - A 64-hex string (with or without `0x`) is a finding only in key context: the value of a key or variable whose name matches `private_?key`, `pk`, `secret`, `signer`, `mnemonic`, `seed`, `PRIVATE_KEY` or `.*_KEY` (case-insensitive), a `.env`-shaped `KEY=value` line with a secret-looking key, or a value passed to a known key-loading call (`privateKeyToAccount`, `new Wallet(`). A 64-hex value under a field named `sha256`, `hash`, `digest`, `integrity`, `txHash`, `transactionHash`, `blockHash`, `artifactHashes`, `hiddenCasesHash` or `folderDigest`, and every value in `scripts\secrets-allowlist.json`, is never a finding.
  - Generic `api[_-]?key`, `token`, `password` assignments with a high-entropy value, and base64 blobs that decode to `.env`-shaped text.
  - **RealX token shapes from the first commit.** The scanner reads the token prefixes from A00's `docs\charter\agent-access.json` (`rx_inv_`, `rx_spn_`, `rx_ptr_`, `rx_stf_` and `rx_sb_`, the prefixes A00 freezes to match A12 and [[Decisions]] D11) and flags any committed literal made of a prefix followed by a token body of 16 or more token characters; the bare prefixes (as in `agent-access.json` itself) are not findings. Tests must generate tokens at runtime; a committed literal needs an allowlist entry. Extra patterns are loaded from any tracked `secrets-patterns.json` anywhere in the repo, so A12 (API tokens) and later nodes add patterns inside their own owned paths without touching A01's files. Pattern files are additive only: they cannot remove a built-in pattern, add an exemption or change the allowlist.
  - Allow-listing a finding needs an entry in `scripts\secrets-allowlist.json` with the file, the SHA-256 of the exact string and a reason (the Hardhat deterministic accounts are the expected first entries, added by A07); an entry missing any of the three is refused. The same scanner runs as a `pre-commit` hook in `scripts\git-hooks` (installed by `prepare`), so the per-node commit cannot carry a secret even if verify was skipped.
- **Design-untouched check** (`scripts\check-design-untouched.ts [--design-dir <path>]`, default `<workspace>\design`): reads A00's `docs\charter\design-baseline.json` by name, recomputes the SHA-256 and byte length of every file it records (today `RealX App.dc.html`, `support.js`, `.thumbnail` and `uploads\RealX-Product-Map.html`) on raw bytes, recomputes the folder digest by A00's rule (SHA-256 over the sorted list of relative path plus hash for every file under the folder), and fails verify on any difference, on any recorded file that is missing, and on any file added to the design folder. A01 reads the charter file, never writes it; the design folder is never opened for writing by any script. `--design-dir` exists only so the node QA can prove failure on a scratch copy.
- **Hygiene path patterns** (`scripts\check-hygiene.ts`, verify step 12). The check does not grep for the bare words `gauntlet` or `hidden` (CSS `overflow: hidden`, `aria-hidden` and ordinary prose must stay legal). It flags, case-insensitively and with either slash direction: a path segment `gauntlet` followed by a separator (`gauntlet[\\/]`); a hidden-oracle path `hidden[\\/]A\d+`; the literal `<workspace>\gauntlet` in any spelling; and any tracked file named `status.json` at the repo root or under `evidence\` or `docs\`. **Exemption list** (the only places a match is allowed): the README's one-sentence "Out-of-repo state" paragraph; `eslint.config.js`; `scripts\check-hygiene.ts`, `scripts\secrets-scan.ts` and their fixtures under `scripts\test\fixtures\hygiene\` and `scripts\test\fixtures\secrets\`; and A00's `docs\charter\*.md` for the `gauntlet[\\/]` and root-path patterns only (the `hidden[\\/]A\d+` and `status.json` patterns apply there too).
- **Reason-code spelling** (`scripts\check-reason-codes.ts`, verify step 12; added 24 Sep 2026 after the plan review found two spellings of the same G22 codes across the specs). Every upper-snake string literal in `apps\`, `services\`, `packages\`, `contracts\` and every published `oracle\` test folder that starts with a registered code-family prefix must exist in the registry that owns the prefix: `SCOPE_` and `SM_` in A03's `packages\domain\src\codes\reason-codes.ts` (the single source), `G22_SCOPE_` as `G22_` plus an A03 `SCOPE_` code or a code A12 registers, and every other family in the error catalogue that nodes register through A09's `registerErrors`. A misspelling (for example `NOT` in place of A03's `NON` in `SCOPE_NON_DELEGABLE`, or the two words of `SCOPE_PENDING_COUNSEL` swapped) fails verify with the file, the line and the nearest registered code. A01 ships the checker; until A03 registers its reason-code file through script registration the step prints `no registry yet` and passes, and from A03's commit on a missing or unreadable registry fails the step. From A12's commit on, the same step also runs A12's registered `check-agent-refusal-codes` rule, which rejects the unused spelling for each case of A12 §5 'Order of agent refusals': a test or published oracle file that expects `G22_SCOPE_NON_DELEGABLE` or `G22_SCOPE_PENDING_COUNSEL` as the error code of an operation marked `x-realx-requires-human` in `packages\sdk\openapi.json` (that route answers `AGNT_NOT_ALLOWED`), or `AGNT_NOT_ALLOWED` from an operation that is not.
- **Owned-path check** (`scripts\check-owned-paths.ts <node> <paths-file> [--base <ref>] [--exclude-inflight <paths-file>]`), used by the gauntlet for standing pass criterion 3 ([[App Gauntlet]] §4) on every later node. The changed set is the union of: `git diff --name-status -M <base>` against the working tree (modifications, additions, deletions and both sides of a rename or copy); `git diff --cached --name-status -M <base>`; and `git ls-files --others --exclude-standard` (new untracked files). `<base>` defaults to `git merge-base HEAD main` in a node worktree and to `HEAD` in the main working tree. Every path in the changed set that is not inside the node's owned paths is printed and fails the check, including a deleted or renamed-away file. The owned-path list is passed in from the vault's `Data\app-graph.json` (`owned_paths`, plus `owned_paths_excluded` for carve-outs such as A60's `(investor)\account\agents\` inside A59's `(investor)\account\`; a changed file under an excluded sub-path is out of path for the node that excludes it); the repo does not read the vault. The only tolerated paths outside a node's list are:
  - `evidence\<node>.json`, `evidence\<node>.qa.md` and anything under `evidence\<node>\`, for the node being checked only; another node's evidence is out of path;
  - root `package.json` and `.gitignore` when, and only when, `scripts:sync` regenerates them identically (the sanctioned registration route);
  - **Sanctioned regeneration of shared generated files.** `packages\sdk\openapi.json` and everything under `packages\sdk\src\generated\` (A09's), everything under `packages\mcp\catalogue\` except the hand-pinned `catalogue\inputs.lock.json` (A104's), and `apps\web\screens.generated.json` (A52's), when, and only when, re-running their generators (`npm run openapi:emit`, `npm run sdk:build`, `npm run mcp:generate` with and without `--fixtures`, and A52's `defineScreen` build test) on the node's tree in a scratch copy reproduces the committed files byte for byte. ## Node-specific challenges (node QA)

- **Boundary rule bypass.** A test fixture imports `services/api/src/modules/ledger/src/internal/postings.ts` from the `orders` module three ways: a relative path, a `@realx/api/modules/ledger/src/internal` alias added to a workspace tsconfig, and a dynamic `await import()` built from a string. All three must fail lint; if any passes, later nodes can reach into the ledger around the approvals engine and the maker-checker guarantee becomes a convention.
- **False green verify.** A workspace with `"test": "echo ok"`, a workspace vitest config with `passWithNoTests: true`, a child tsconfig setting `strict: false`, a file-level `/* eslint-disable */`, a line-level `eslint-disable-next-line no-float-money`, an unused disable directive, and an `audit-allowlist.json` entry with no expiry. Verify must fail on each, at steps 4, 4, 4, 5, 5, 5 and 8 respectively; a scaffold that can be quietly weakened will be, under fix-loop pressure, forty nodes from now.
- **Secret smuggling.** A 64-hex private key under a `privateKey` field inside a JSON fixture, a base64-encoded `.env` pasted into a Markdown file under `evidence\`, a mnemonic split over two lines, and an `rx_inv_` token literal (a prefix followed by a full token body) in a test snapshot with no A12 workspace present. The scanner and the pre-commit hook must both catch them, and widening the allowlist without the string's hash and a reason must be refused. In the other direction, A00's `design-baseline.json` and `evidence\A00.json` (full of SHA-256 digests) scan clean with zero allowlist entries.
- **Untracked and deleted files.** A builder creates a new file in another node's folder without staging it, deletes a file A00 owns, and renames one of its own files into another node's folder. The owned-path check must report all three.
- **Line endings and shells.** A file staged with CRLF on a machine with `autocrlf true`, and a compose `entrypoint` script with CRLF that Docker then cannot execute. Verify must catch the first and `verify:infra` the second.
- **Postgres readiness race.** `db:up` returns after the container reports healthy but before the database accepts the application's first query (the classic `pg_isready` window during init scripts). A test runs `db:reset` then an immediate query 20 times; any connection refusal is a failure.
- **Commit policy and out-of-repo state.** A builder commits mid-build, or copies `status.json` or a hidden oracle file (`gauntlet\hidden\A01\...`) into `app\`. The hygiene step and the git log check must expose both, while a UI fixture containing `overflow: hidden` and `aria-hidden="true"` stays green.
- **Dishonest toolchain record.** `toolchain.json` lists a version that is not the one in the lockfile, omits a package that failed to install and was replaced, or omits a package with an install script. The node QA rebuilds the record from `npm ls` and the lockfile and diffs.
- **Registration used as a back door.** A workspace registers a verify step named `typecheck` that shadows A01's step 3 with `echo ok`, registers a root script `verify` that replaces the real one, registers gitignore lines `evidence/`, `apps/`, `**/*.test.ts`, `!.env` and `../x`, or registers a step whose `run` command deletes `scripts\verify-steps.lock.json`. The sync must refuse the first two by name and every one of the gitignore lines by the workspace-confinement rule, and the last must make step 12 fail on the next run.
- **Float money outside the domain package.** A fixture in a non-domain workspace computes `units * price` with a `number`, formats with `amount.toFixed(2)`, and parses an amount with `parseFloat`. All three must fail lint before A02 exists; if the rule only fires once `packages/domain` is present, the invariant arrives too late. The allowed fixture `width * 1.5` in an `apps/*` file must pass.
- **Parallel builds.** The two-node concurrency script under Challenge; plus a sibling's untracked `design-ext\` file present in A01's own working tree, which must not appear in A01's owned-path check or verify.
