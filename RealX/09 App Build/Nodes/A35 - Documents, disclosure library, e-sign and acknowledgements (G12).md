# A35 - Documents, disclosure library, e-sign and acknowledgements (G12)

**The versioned document library every screen, order and statement hangs off: platform documents (FSG, terms, privacy, complaints policy, fees) and per-listing documents (IM now, PDS/SPDS and TMD in P2, deed, valuation, notices) with a sha256 per version, effective dates, superseded versions kept and marked, seven-year retention and legal holds, publication as 4E (LEGL to CCO) with an optional on-chain hash anchor through `DocumentAnchor.setDocument` under the same approval id; the single acknowledgement record that G12 reads (document id, version, timestamp per order, opened before acknowledged, written inside the order placement transaction through one exported function, and an agent acknowledging only under a passkey-created standing consent that the CQ-02 counsel parameter allows for the offering's regime, otherwise the order waits for the person); the cooling-off statement per regime rendered from the offering's own `cooling_off_days`; the e-sign sandbox adapter; templates with sponsor placeholders; the holder's disclosure and notice library (`/v1/me/library`); and the deterministic PDF renderer for the documents this module owns (AMMA and tax summaries for A41, notices and memos, board packs, sponsor terms, signature pages), whose output bytes and sha256 never change for the same inputs. Order confirmations, contract notes, payment advices, annual statements and the `/v1/me/documents/*` namespace stay A47's.**

**Build status:** not started. **Milestone:** AM3 (Business services). **Lane:** Services. **Planner:** Opus 5.5 (high). **Builder:** Grok 4.7 (xhigh). **Node QA:** Opus 5.5 (high, every loop). **Graph QA:** Fable 5.1 (high, at milestone close).
**Estimate:** 12-16 agent-hours (build, challenge and verify loops; a versioned library with A14 effectors and an on-chain anchor path, the acknowledgement and consent gate with hidden vectors, an e-sign adapter with conformance tests, templates with a PII scan, a byte-deterministic cross-platform renderer with a fallback plan, and about 40 endpoints in OpenAPI, SDK and MCP). **Oracle rule:** an oracle node (oracle: yes). No money, supply or holdings move here, but G12 decides whether an order's money may go to escrow at all, and a delegated acknowledgement is agent authority, which D04 puts under an oracle. Oracle scope: the acknowledgement evaluator (including `recordAcknowledgements` and the opens it accepts), the standing-consent evaluator with the CQ-02 regime parameter, and renderer determinism. The node QA writes those hidden vectors to `<workspace>\gauntlet\hidden\A35\` before the build starts ([[App Gauntlet]] §2), brings the rest of its vectors to the Challenge step, and files everything under that folder after the gate so A36, A37, A57, A63, A75 and A90 re-run them as regression. This note is not legal advice. Whether an agent may acknowledge a disclosure for its principal (CQ-02), whether a signer's agent may ever sign an envelope (CQ-01 list), what the retail cooling-off statement must say and for how many days (P2, CQ-06), which record classes must be kept for seven years and which longer, and whether a hash anchor of a disclosure has any legal weight are counsel questions (HG-LEGAL). Each is a parameter row with a default and a `set_with_counsel` marker; counsel's answers change rows, not code. The seed uses the design's sample documents and sponsors and nothing real.

## Build brief

**Scope and placement**

- Module `documents` in the API (`services/api/src/modules/documents/`) following the A09 module pattern: a public `index.ts` (the only import other modules may use, enforced by the boundary lint), zod schemas that feed the OpenAPI document from the first commit, Drizzle repositories over the A04 core tables `document`, `document_acknowledgement` and `standing_consent` (any missing column on those three is requested from A04 as a numbered follow-up loop, number assigned by the orchestrator and called "the A04 follow-up loop" below, before this node's build starts) and over this module's own tables (`document_version`, `document_open`, `document_template`, `template_version`, `esign_envelope`, `esign_signer`, `cooling_off_statement`, `render_record`, `anchor_request`), which belong wholly to this module and are created through A04's module-schema registry (A04 §6), never by altering a core table, and job definitions exported from the module and registered with the worker through A09's job registration. The only source of time is A09's injectable clock; `Date.now()` and argument-less `new Date()` are forbidden in both owned paths and `npm run verify` greps for them. Every uploaded or rendered file goes through A08's `storage` adapter (`putObject`, `presignUpload`, `presignDownload`, `setLegalHold`), never to the filesystem directly.
- Package `packages/adapters/esign` following A08's `defineAdapter` pattern: `manifest.ts`, `interface.ts`, `sandbox/`, `conformance/`, and a `SWAP-POINTS.md` row (DocuSign or Dropbox Sign as candidates; the swap changes the client only; envelopes, hashes and audit stay RealX's; human gate HG-VENDOR).
- Everything here is data behind screens owned by other nodes: the property page Documents tab and PUB-09 Help and documents ([[A55 - Public site- how it works, returns calculator, transparency, help and documents]]), the buy stepper AcknowledgeCard on INV-02 ([[A57 - Buy flow- order, review and confirm, order status (INV-01 to INV-03)]]), the listing wizard Documents step SPN-06 ([[A63 - Sponsor console- new listing wizard SPN-03 to SPN-06 and offer monitor SPN-07]]), ADM-24 Disclosure library ([[A75 - Console- AML cases, complaints register, marketing compliance, disclosure library]]), POR-07 Statements and documents (A58, which merges A47's confirmations, advices and statements with A41's AMMA rows and this module's library) and the P2 PDS, SPDS and TMD flows ([[A90 - P2- registered scheme, sub-funds, PDS and TMD, target market (G05), retail cooling-off]]). This node fixes the record shapes, column names, state vocabularies, statement texts and reason codes so those nodes render without translation.

**Document library (module M18, the library half)**

- Tables (core tables through the A04 follow-up loop, own tables through the module-schema registry): `document` (logical document: `id` `DOC-<6 base32>`, `tenant_id`, `doc_type`, `scope_type` (`platform`, `vehicle`, `offering`, `investor`, `tenant`, `property`), `scope_id`, `title`, `language` (`en-AU`), `current_version_id` (the version in effect now), `pending_version_id?` (a published version whose `effective_from` is still in the future; at most one), `supplements_document_id?`, `is_public`, `retention_class`, `state` (`active`, `withdrawn`)); `document_version` (`id` `DOCV-`, `document_id`, `version_no` (1, 2, 3, never reused), `storage_object_id`, `sha256` (equal to the storage object's sha256, checked on every read), `content_type`, `byte_size`, `page_count`, `effective_from`, `effective_to?`, `state` (`draft`, `in_review`, `published`, `superseded`, `withdrawn`), `published_by_approval_id?`, `supersedes_version_id?`, `anchor_state` (`none`, `requested`, `anchored`, `failed`), `anchor_ref?` (chain id, `DocumentAnchor` address, tx hash, block, log index, approval id), `created_by_principal`, `on_behalf_of_id?`, `source` (`upload`, `template`, `render`)); `document_open` (insert-only: `document_version_id`, `principal_id` (the person, or the token id), `principal_kind` (`human`, `token`), `on_behalf_of_id?` (set exactly when `principal_kind = token`), `channel` (`ui`, `api`, `mcp`), `context_ref?` (an order, quote, listing or envelope id), `opened_at` (from the injectable clock at the server, never from the client), `session_or_token_id`); `document_template`, `template_version`, `esign_envelope`, `esign_signer`, `cooling_off_statement`, `render_record`, `anchor_request`. `document_acknowledgement` and `standing_consent` are A04's core tables; if any column below is missing there, that is the A04 follow-up loop.
- Document type vocabulary (`doc-types.ts`, data, extendable only by a data change and a seed test), each with its scope, `is_public` default, retention class and whether it is a **disclosure** that G12 can require: platform: `fsg`, `terms`, `privacy_policy`, `complaints_policy`, `fee_schedule_platform`, `transparency_report`; vehicle or offering: `information_memorandum` (P1 disclosure), `pds` and `spds` (P2 disclosure), `tmd` (P2), `trust_deed`, `constitution` (P2), `fee_schedule` (disclosure), `risk_statement` (disclosure; the design's card reads "information memorandum, fee schedule and risks", so risks are a document version too, either a section of the IM registered as a pointer or a stand-alone document), `valuation_report`, `property_report`, `significant_event_notice`, `notice`, `explanatory_memo` (A93's meeting memos), `resolution`, `sponsor_declaration` (SPN-06's "Sponsor declaration", signed by an SP-OWN in person through an envelope, see below; `delegable: "counsel"` in A03), `sponsor_terms`; investor: `amma_statement` and `tax_summary` (rendered here from A41's data), `notice` addressed to one holder, `register_extract` (produced by A18 and stored here when A18 hands it over; A18 renders its own), `board_pack` (staff and partner), `signed_copy` (the e-sign output). Order confirmations, contract notes, payment advices, holding statements and annual statements are not doc types here: they are A47's `portfolio_document` kinds, rendered by A47's `confirmation-pdf.ts`, `payment-advice-pdf.ts` and `annual-statement-pdf.ts` and served under A47's `/v1/me/documents/*` and `/v1/me/transactions/{id}/confirmation.pdf`.
- Two document sets per regime, kept apart because they answer different questions; both are rule-pack rows (`set_with_counsel`), read through this module's interface only:
  - `acknowledgement_set` (what G12 needs the investor to open and acknowledge before an order): `s708_wholesale` = IM + fee schedule + risk statement (the design's card reads "information memorandum, fee schedule and risks", so the risks are a document version too: either a section of the IM registered as a pointer document with the IM's version and hash, or a stand-alone document); `au_mis_retail` (P2) = PDS (+ SPDS when current) + TMD + fee schedule + risk statement. Exposed as `getDisclosureSet(offering, {asOf?, caller?})`.
  - `listing_submission_set` (what a sponsor must attach before A36 lets a listing go to review; SPN-06's CheckRows): `s708_wholesale` = IM, trust deed, fee schedule, risk statement, valuation report, sponsor declaration; `au_mis_retail` (P2) = PDS, constitution, fee schedule, risk statement, valuation report, sponsor declaration, TMD. Exposed as `getListingDocumentSet(offering)` returning each member with `doc_type`, `document_id?`, `version_id?`, `version_no?`, `page_count?`, `state` (`missing`, `draft`, `in_review`, `published`, `signed` for the declaration) and a `meta` string, so A36 blocks review (`OFR_DOCS_INCOMPLETE` naming the member) and A63 renders the "Ready" or amber "Missing" row without re-deciding membership.
- Versioning rules: a new version is created as `draft` by upload (presigned through A08, sha256 computed on completion, magic-byte type check is A08's) or from a template or the renderer; `draft -> in_review` (maker sets `effective_from`; must be in the future or "now"; a `draft` may be edited or discarded); `in_review -> published` only by the A14 effector for action code `document.publish` (LEGL -> CCO, `4E`; for a document scoped to a sponsor's vehicle the sponsor's SP-OWN is an additional required checker where the policy row says so, and RealX's CCO always). Approval and effect are separate. If the approved `effective_from` is at or before the clock, the effector in the same transaction marks the new version `published`, sets the previous in-effect version `superseded` with `effective_to = new.effective_from - 1 ms`, moves `current_version_id`, and `is_public` documents appear in the public listing the same tick. If `effective_from` is in the future, the new version becomes `published` and is recorded as `pending_version_id`; the previous version stays in effect, stays current for `getDisclosureSet` and stays acknowledgeable until then; the public listing shows the pending version as "Effective <date>" beside the current one. The worker job `documents.effect-sweep` (every minute on A09's injectable clock) and, as a backstop, every read-time resolver apply the same switch the instant `effective_from <= now`: previous version `superseded` with `effective_to = new.effective_from - 1 ms`, `current_version_id` moved, `pending_version_id` cleared, one `document.superseded` and one `document.effective` event, idempotent if the job and a read race. A second publish while one version is pending is refused `DOCV_PENDING_EXISTS` (withdraw the pending one first). Invariant: for every document, exactly one version is in effect at any instant after the first publish and at most one is pending. `published -> withdrawn` is `document.withdraw` (LEGL -> CCO, `4E`, reason code mandatory; a withdrawn disclosure makes every dependent offering fail G12 until a replacement is published, which is A36's concern and this node's fact). A `superseded` or `withdrawn` version is never deleted, is always retrievable by its id, and every read of it returns `superseded: true` with `superseded_by` so the UI can mark it (design analysis §5: "superseded stays available and marked"). Any other transition is 409 `DOCV_TRANSITION_NOT_ALLOWED`.
- Supplements: a `spds` or `significant_event_notice` is a document of its own whose `document.supplements_document_id` points to the IM or PDS; the disclosure set treats "PDS + current SPDS" as one requirement, so a new SPDS makes acknowledgements of the plain PDS stale (`DISCLOSURE_VERSION_STALE`) from its `effective_from`.
- Integrity: the version's `sha256` is written from the storage object's sha256 and re-verified on every `getObject` (a mismatch is refused with `DOC_HASH_MISMATCH`, raises Sev1 `document.integrity` through A13, and never serves the bytes). The optional anchor (product map: `document.publish` is on- and off-chain, "4E; optional setDocument"): `document.publish` payloads carry `anchor: true|false`, and a request with `anchor: true` also carries `custody_vault: V2`, the target token and the A24 `docType` constant, all inside the approved payload hash. The on-chain contract is A24's `DocumentAnchor` (`setDocument(token, bytes32 docType, bytes32 sha256, string uri, uint32 version)`, callable only by the token's owner or an agent of that token, V1 or V2 through A25's `AgentGateway`), already deployed on the local chain by A24's shared deploy; it is not a later node. The mapping from this module's doc types to A24's `docType` constants is data in `anchor-doc-types.ts`: `information_memorandum` -> `IM`, `pds` -> `PDS`, `tmd` -> `TMD`, `constitution` -> `CONSTITUTION`, `valuation_report` -> `VALUATION`, `fee_schedule` -> `FEE_SCHEDULE`; any other doc type with `anchor: true` is refused at submit with `DOC_ANCHOR_TYPE` (A24 reverts `DocTypeUnknown` otherwise). When the version takes effect (at publish, or at the effect switch for a pending version, so the anchor never runs ahead of the resolver), the effector writes an `anchor_request` row and hands a `CustodyOp` for `setDocument` to A28's token-operations service with the same approval id; A28 carries it through A15's sandbox custody policy engine (V2 signing) and A27's chain adapter to A25's gateway, which binds the approval id on-chain and rejects a consumed or mismatched id. `anchor_state` moves `requested -> anchored` only when A27's indexer reports the `DocumentAnchored` event (and the gateway's `Executed(approvalId, ...)`) for that token, doc type, version and sha256; it moves to `failed` on a revert or an A27 stuck-transaction clock, with Sev2 `document.anchor_failed` through A13. No internal HTTP callback sets the state, and there is no `anchor_sandbox` table. An indexed `DocumentAnchored` whose sha256 differs from the version's is refused (`DOC_ANCHOR_MISMATCH`, Sev1 through A13) and leaves `anchor_state = failed`. A20's rule R14 compares A27's chain snapshot (`latest(token, docType)`) with the current in-effect version returned by `getAnchoredVersions(vehicle)` in this module's public interface. A28 must accept the `document.anchor` op kind (a back-edge recorded for A28, see Specify).
- Retention and legal holds: every `document` carries `retention_class` from A10's `retention_policy` rows (this node seeds `min_years = 7` for `disclosure`, `investor_record`, `envelope`, `acknowledgement`, `template`; the classes and periods are `set_with_counsel`). `document.hold.place` and `document.hold.release` (LEGL -> CCO, `4E`, through A14) write A10's `legal_hold` row for the document, call A08's `setLegalHold` on every version's object, and audit `hold.placed` / `hold.released` with A10's codes. No route in this module deletes a version; the only purge path is A102's, which must call this module's `isRetained(version)` (true while inside the retention period or under a hold) and is refused with `DOC_RETENTION_ACTIVE`. Erasure (A102) pseudonymises the investor but keeps every acknowledgement, open and envelope row with its hashes, because they are the evidence that a disclosure was given.

**Acknowledgements, standing consent and G12 (the gate half)**

- **Single G12 record.** This module's `document_acknowledgement` table is the only store of disclosure acknowledgements on the platform. A37's `disclosure_acknowledgements` must become a reference (`order_id` -> `document_acknowledgement.id[]`) or a read-only view onto this table, never a second store written from a client payload; that is a defect recorded against A37 and A19 (see Specify), not something this node edits.
- `document_acknowledgement` row: `id` `ACK-<6 base32>`, `tenant_id`, `investor_id` (the holder), `offering_id`, `context_type` (`quote`, `order`, `listing`, `envelope`, `account`), `context_ref` (the A37 quote id before placement or the order id; one acknowledgement set per order, never reused across orders), `order_ref?` (set when a `quote` acknowledgement is bound to the order at placement, in A37's placement transaction; a quote's set can be bound to exactly one order, and an unbound quote set lapses with the quote's `expires_at`), `document_version_id`, `sha256` (copied from the version at the moment of acknowledgement), `opened_at` (copied by the server from the matching `document_open` row, never accepted from a caller), `acknowledged_at`, `channel` (`ui`, `api`, `mcp`), `actor_principal` (the person, or the token id), `on_behalf_of_id?` (set exactly when the actor is a token or AGNT), `standing_consent_id?` (mandatory when `on_behalf_of_id` is set), `statement_hash` (sha256 of the cooling-off and escrow statement text shown, see below), `regime`, `assertion_id?` (the passkey confirmation that A57 collects on "Confirm and pay" when the acknowledgement and confirmation happen in one step; optional for the acknowledgement itself), `ip_hash`, `user_agent_hash`. Insert-only; a repeat for the same (`context_ref`, `document_version_id`, holder) is idempotent and returns the existing row (200, not 409).
- `POST /v1/documents/versions/{id}/open` records a `document_open` row and returns a presigned download URL from A08 (`presignDownload`, 5 minutes) plus `open_recorded: true|false`. Public documents may be opened without a session (no open row is written for anonymous visitors, `open_recorded: false`; A55 shows them freely); a disclosure that will be acknowledged must be opened while signed in or under a token, so the open row exists. The design's toast "Opens the PDF (G12 acknowledgement recorded)" overstates what happens (only the open is recorded; the acknowledgement happens on INV-02): A55 shows a toast only when `open_recorded` is true, and its wording is a design deviation A55 records in the coverage matrix and rewords (proposed: "Opened. We have recorded that you read this version."), not something this module confirms.
- Which open counts (G12: "the investor opens and acknowledges"): a **human** acknowledgement (session of the holder, `channel: ui`, or the holder's own session through the API) requires an open row by the holder as a human principal (`principal_kind = human`, any of the holder's sessions); an open made only by the holder's token does not count. A **delegated** acknowledgement (under a token) requires that token's own open row (`principal_id` = the token, `on_behalf_of_id` = the holder); an open by the person or by another token of the person does not count. In both cases the open must be of the exact version acknowledged, with `opened_at <= acknowledged_at`, both read from the server's rows.
- `POST /v1/acknowledgements` with `{context_type (quote | order), context_ref, document_version_ids[], statement_hash}` (the HTTP path A57 and agents use before placement, against A37's quote id; A37 binds the set to the order in its placement transaction through `recordAcknowledgements` below). Any `opened_at`, `acknowledged_at` or `sha256` field in the body is rejected by the zod schema (`ACK_FIELD_NOT_ACCEPTED`), so a client cannot assert when it opened a document. The evaluator `evaluateAcknowledgement(input, facts)` in `ack/evaluate.ts` is a pure function over plain objects and returns `{result: pass|fail, reason_codes[], missing[], stale[], unopened[]}`. Checks in order: every required disclosure version for the context (resolved through `getDisclosureSet(offering)` at the current clock: for each type in the regime's `acknowledgement_set`, the document's in-effect version (`current_version_id` after the effect switch; a pending version is never required and never accepted before its `effective_from`), plus any in-effect SPDS) is in `document_version_ids[]`, else `ACK_DOCUMENT_MISSING` naming the type; every listed version is the in-effect version, else `DISCLOSURE_VERSION_STALE` naming the version and the current one (A19's code; one vocabulary); every listed version has an open row that counts under the rule above with `opened_at <= now`, else `ACK_DOCUMENT_NOT_OPENED`; `statement_hash` equals the hash of the statement text this module computed for the offering at this clock, else `ACK_STATEMENT_MISMATCH` (the statement must have been shown; the UI and the SDK obtain it from `GET /v1/offerings/{id}/disclosure-set`); the holder's identity is the context's investor (a quote or order belongs to the holder or the call is 404, `ACK_CONTEXT_NOT_FOUND`). On pass, one row per version is written in one transaction with one A10 event `document.acknowledged` per row; on fail, nothing is written and A10's `recordRefusal` writes `gate.refused` for G12 with the reason codes.
- `recordAcknowledgements(tx, {holderId, offeringId, orderRef | quoteId, documentVersionIds[], statementHash, actor})`, exported from `index.ts` for A37: runs `evaluateAcknowledgement` (and, for a token actor, the delegated path below) against facts read inside the caller's transaction and writes the `document_acknowledgement` rows in that same transaction, deriving every `opened_at` only from `document_open` rows; `actor` is A11's resolved principal (`{kind: human, personId, sessionId}` or `{kind: token, tokenId, onBehalfOfId}`), never a caller-built object. When given a `quoteId` whose set was already acknowledged over HTTP, it binds those rows to `orderRef` (sets `order_ref`) after re-checking that every version is still in effect and the statement hash is still current, else it fails with the same codes. It returns `{result, reason_codes[], ack_ids[]}`; a fail writes nothing and A37 rolls back or leaves the order waiting. A37 passes the list of version ids it showed; it never passes `opened_at`, `sha256` or timestamps.
- `GET /v1/offerings/{id}/disclosure-set` returns the required versions (`document_id`, `version_id`, `version_no`, `doc_type`, `title`, `meta`, `sha256`), the statement text and its hash, `ack_text`, and, when the caller has a session or a token, the caller's own `opened_at` per required version (by the rule above: the person's human opens for a session, the token's own opens for a token) and `all_opened: true|false`, so INV-02's required state "Documents not opened: confirm stays disabled" comes from the server, not from client-side tracking. A contract test for this shape is exported for A57 to reuse. With `as_of` it returns the set current at that instant (see Empty and error states).
- The G12 fact for A19: this module exports `getAcknowledgementFacts(orderRef)` in its public interface (`FactProvider` shape from A19: the required versions, the acknowledged versions with timestamps, the open timestamps, `statement_shown`, the channel and `on_behalf_of` of each acknowledgement, and the standing-consent id where used). A19's G12 evaluator decides pass or fail from those facts; this module never pretends to be the gate. `getAcknowledgementFacts` accepts an order ref or a quote id.
- **One source of truth for standing consent and CQ-02.** Three nodes described it three ways (A19: "A12 mandate flag `standing_disclosure_consent`"; A37: document versions held on A12's mandate record behind its own switch `orders.agent_standing_consent`, answering 428 `documents_required`; this note: its own table). This node fixes the rule: the consent lives only in this module's `standing_consent` table (below); a mandate never carries it and holds no version list; the CQ-02 parameter is one key, spelled exactly as A00's `agent-access.json` `counselQuestions` entry for CQ-02 names it (this note calls it `cq02.delegated_acknowledgement`; A00's spelling wins), with a regime dimension: `{s708_wholesale: allowed_under_consent, au_mis_retail: person_required}` by default, matching A37's current `wholesale_only` default, each value `set_with_counsel`; A19 and A37 read the consent and the parameter only through `getAcknowledgementFacts` and `recordAcknowledgements`, and A37 drops `orders.agent_standing_consent` and the mandate-held version list. There is one refusal code, 428 `ACK_PERSON_REQUIRED`, with a `sub_reason` (`counsel_parameter`, `consent_missing`, `consent_scope`, `consent_predates_version`, `first_purchase`, `agent_not_opened`); A37's `documents_required` becomes a field of its order-waiting payload, not a second code. The orchestrator records these changes in A19's and A37's specs (see Specify); this node does not edit them.

**E-sign adapter and envelopes**

- Interface (`packages/adapters/esign/interface.ts`): `createEnvelope({tenantId, documentVersionId, sha256, signers[] ({principalId, name, email_enc_ref, role, order}), fields[], expiresAt, callbackRef})` -> `{envelopeId, providerRef, state}`; `send(envelopeId)`; `getStatus(envelopeId)` -> `{state, signers: [{state, signedAt?}], completedAt?}`; `void(envelopeId, reason)`; `downloadSigned(envelopeId)` -> stream plus `{sha256, byteSize, certificateRef}`; `webhook(rawBody, signatureHeader)` -> parsed events with replay protection (A09's signed-webhook window); `health()`. States: `created`, `sent`, `viewed`, `partially_signed`, `completed`, `declined`, `voided`, `expired`; the transition table is data and tested exhaustively.
- Who signs: signing happens only at the provider, in a session the signer authenticates there; RealX exposes no API route, SDK method or MCP tool that signs, so no token or agent can sign an envelope for its human. Envelopes carry legal declarations (sponsor terms, the sponsor declaration, wholesale-certificate countersignatures, register certifications), so whether a signer's agent may ever sign is a counsel question to be added to A00's `counselFlagged` list under CQ-01 (a back-edge for A00); until answered, signing is personal. Agents may create, send, read and void envelopes as maker within their human's role.
- Sandbox: signs automatically after `ESIGN_SANDBOX_DELAY_MS` (default 2,000 ms; 0 under test) under the injectable clock, or when the operator presses "Sign now" on ADM-32's sandbox panel (A08's operator hook, available only in `RUN_MODE=local`; the hook and `POST /v1/_test/documents/esign/sign-now` return 404 in every other mode and are absent from the public OpenAPI document and the MCP catalogue), producing a signed PDF = the original bytes plus a deterministic signature page (signer names, roles, the original sha256, the signing timestamps from the clock, a fixed sandbox certificate id) whose sha256 is recorded on the envelope and stored through A08 as a new `document_version` (`source: render`, `doc_type` unchanged, `supersedes` nothing: the signed copy is a distinct document of type `signed_copy` linked to the source version). Magic inputs (A08 convention): a signer name containing `DECLINE` declines, `EXPIRE` lets the envelope expire at `expiresAt`, `SLOW` signs after ten times the delay, `TAMPER` returns a signed file whose sha256 does not match the envelope's original hash (so the mismatch path is testable and must be refused with `ENVELOPE_HASH_MISMATCH`). The sandbox webhook is delivered through A09's outbox to this module's handler with a signed header; a replayed delivery is dropped by the replay window and audited once.
- Envelope service (`esign/` inside the module): `POST /v1/envelopes` (LEGL, CAPM, SP-OWN and SP-OPS for their own vehicles' documents, TP-RE for register certifications) creates and sends; `GET /v1/envelopes/{id}`; `POST /v1/envelopes/{id}/void` (LEGL, or the tenant owner for its own envelopes; screen-level single-role action per the catalogue, reason code mandatory, refused with `ENVELOPE_STATE` once `completed`); `GET /v1/envelopes/{id}/signed` (presigned download, audited). Every state change is one A10 event (`envelope.created`, `envelope.sent`, `envelope.viewed`, `envelope.signed`, `envelope.completed`, `envelope.declined`, `envelope.voided`, `envelope.expired`). Who uses envelopes: sponsor terms at admission (A33, J11), trustee instructions and register certifications (A18, A98), wholesale certificates that need a countersignature (A30), the sponsor declaration at submission (a `sponsor_declaration` document signed in person by an SP-OWN, counted by `getListingDocumentSet` once `signed`), and the sponsor owner's listing sign-off where the policy wants a signature as well as the A14 check (A63). **Deterministic PDF renderer (the documents this module owns: AMMA and tax summaries, notices and memos, board packs, sponsor terms and declarations, IM cover sheets, e-sign signature pages)**

- Ownership split with A47 (recorded so no two modules build the same PDFs or define the same routes): A47 keeps order confirmations, contract notes, payment advices, holding and annual statements, its `portfolio_document` table, its own deterministic renderer files and the whole `/v1/me/documents/*` and `/v1/me/transactions/{id}/confirmation.pdf` namespace; this module never renders those kinds and owns no route under `/v1/me/documents`. Determinism rules, each with a test: fonts embedded from `packages/ui` (Newsreader for headings, Geist for text, Geist Mono for figures; subset tables sorted; the same subset for the same glyph set), PDF `CreationDate` and `ModDate` set to `as_of`, `Producer` and `Creator` fixed strings, no document id randomness (the trailer id derived from sha256 of the canonical inputs), object numbering by a fixed traversal, no compression settings that vary by platform, `en-AU` formatting from `packages/domain` money helpers (A$ with thousands separators, dates `d MMM yyyy`), Australia/Sydney civil dates where the inputs are dated. Each is a `set_with_counsel` row or seed row followed by a re-run of this node's evaluator, statement and retention tests, not a gate on this node. A real e-sign provider (HG-VENDOR), the `DocumentAnchor` contract on mainnet (HG-AUDIT, HG-PROD) and production storage keys (HG-KEYS) arrive later; until then ADM-32 shows every one of them as "sandbox".

Every node also meets the standing pass criteria in [[App Gauntlet]] §4.
