# A75 - Console: AML cases, complaints register, marketing compliance, disclosure library

**The four "Risk & records" screens of the operator console, built on A53's shell over four service modules that already exist: ADM-25 AML cases (the prototype's `adAml` table as drawn, then the alert queue, the case detail with SMR clocks, restriction as act-now-ratify-later, the tipping-off check before any customer RFI, sealed SMR content that only the MLRO ever sees, TTR and IFTI items and the screening hub, all under the MLRO and CCO need-to-know rule so that nothing about a case reaches anyone else through the page, the search box, a badge or a URL); ADM-27 complaints register (acknowledgement and final-response deadlines as the API computes them, mandatory ticket conversion, redress as a maker-checker request with the CFO added above A$5,000, AFCA escalation with AFCA's details shown); ADM-28 marketing compliance (the approvals queue for announcements, campaigns, site copy and listing copy with each blocked phrase highlighted in place and the rule and suggested wording beside it, the claims library and terms versions); and ADM-24 disclosure library (every document with version, effective date, anchored hash and state, superseded versions kept and marked, publish and withdraw as `4E`, legal holds). Every action on the four screens is an API operation a staff member's agent can call under exactly the same rules, except the acts that must be a person's.**

**Build status:** not started. **Milestone:** AM7 (Operator console). **Lane:** Operator console. **Planner:** Opus 5.5 (high). **Builder:** Grok 4.7 (xhigh). **Node QA:** Opus 5.5 (high, every loop). **Graph QA:** Fable 5.1 (high, at milestone close).
**Estimate:** 10-14 agent-hours (build, challenge and verify loops; four screens, about 25 sub-routes and the heaviest privacy probes of the console, comparable with A72). The graph still carries 8-12 and must be raised to 10-14.

**Depends on:** [[A53 - Operator console shell, hardware-key sign-in and approval action pattern]], [[A42 - AML screening, monitoring, cases and SMR clocks (SM-11)]], [[A44 - Support, complaints (SM-12) and Investor 360 read model]], [[A43 - Communications, notifications, tasks and marketing claims (G17)]], [[A35 - Documents, disclosure library, e-sign and acknowledgements (G12)]], [[A51 - Design extension B- operator console screens not in the prototype]]
**Unlocks:** [[A78 - Operator journey J20 end to end in Docker (AM7 exit)]], [[A80 - End-to-end journeys- sponsor and operations]], [[A81 - End-to-end journeys- recovery, AML and planted breaks]]

**Oracle rule:** this node has a hidden oracle (`oracle: yes`; the graph's `oracle` flag for A75 must be `true` too, so the orchestrator schedules the Oracle stage before Build). No money, supply or holdings move in this node's own code, and every rule the four screens show is decided by A42, A43, A44, A35 and A14. But this is the only surface on which authority acts are rendered for M20, M21, M23 and M18 (the `SGL+R` restriction and its ratification, redress approvals, the MLRO's SMR decision and filing), and a regulated secret (an AML case and its SMR) and three regulated clocks are rendered here, so the node QA writes hidden tests and Challenge fixtures to `<workspace>\gauntlet\hidden\A75\` before the build starts ([[App Gauntlet]] §2): Playwright specs against the running Docker stack with the sandbox authenticator, a tipping-off persona sweep (every non-ACL staff role, a sponsor user and each one's agent token) with the strings and ids that must never appear, a sealed-content leak probe, a client-clock-skew fixture, an adversarial announcement-body set for the highlighter, its own crops of the `adAml` region of the prototype and of extension B's ADM-24, ADM-27 and ADM-28 frames, and the agent-parity table for every action on the four screens. The builder never reads that folder; the tests are published into `app/` only after the gate passes.

This note is not legal advice. The SMR clock lengths, the tipping-off checklist, the complaint deadlines, the AFCA wording, the claims ruleset, the 30-day notice period and the retention periods are rows of data owned by A42, A43, A44 and A35 with a `set_with_counsel` marker; this node renders them and never restates them as constants. Filing with AUSTRAC, AUSTRAC enrolment, the AML/CTF program and the MLRO appointment are human acts outside this build.

- **Sealed SMR content.** The filing form's content field is an uncontrolled `TextArea` with `autocomplete="off"`, `spellcheck="false"` (browser spell services can send text off the machine) and no draft autosave; its value is read once at submit, sent in the request body only, and cleared from memory on success, failure or unmount; it is never put in React state that outlives the form, the SDK's query cache, `localStorage`, `sessionStorage`, IndexedDB, the URL, a toast, a console log or the error boundary's report. On a failed submit the MLRO re-types or re-pastes; the page does not keep a copy to retry. After filing the page shows the filing's kind, dates, `external_ref` and state; the CCO sees exactly that (A42: existence, kind, dates and state), and no other role receives the filing at all. **Viewing filed content** (MLRO only): a collapsed "Show sealed content" panel. That call is outside `queries.ts`'s query cache: it is a plain SDK method, or a query with `gcTime: 0`, `staleTime: 0`, no retries, no refetch on focus and excluded from any persister. The value lives only in the panel component's local state and is dropped when the panel collapses, on route change and on unmount. The response must carry `Cache-Control: no-store` (a test asserts the header on the Docker stack), the SDK sends the request with `cache: "no-store"`, and the console's service worker, if one exists, never matches `/v1/aml/*` (a test lists CacheStorage after viewing). The filing list and every other read never carry the content.
