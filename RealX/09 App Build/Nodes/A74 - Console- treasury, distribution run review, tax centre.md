# A74 - Console: treasury, distribution run review, tax centre

**The three money screens of the operator console, drawn over the treasury, receipts, refunds, distributions and tax APIs: ADM-18 Treasury and client money (the three client-money trust accounts and escrow per offering, with the operating account marked separate and never counted in client money; pay-in matching with held receipts by age; pay-outs and withdrawals with their threshold approvals; escrow committed vs received vs released; the bank-vs-ledger reconciliation that must show Δ 0; fees and float interest); ADM-19 Distribution run review (the calculation to the cent, the checks vs last month, vs forecast, snapshot locked and client money Δ 0, the exceptions including "AML hold · no notice", the lines, the payment-file hash line and the approval bound to that hash); and ADM-20 Tax centre (profile gaps, withholding exceptions and rate sets, AMMA batch generation, remittance, CRS/FATCA and the filing and remittance calendar). No money figure is calculated in the browser, no button is decided in the browser (every control comes from the API's `allowed_actions[]`), no approval or bank authorisation is decided outside A53's hardware-key modal, and every action on the three pages is an API operation that a staff member's agent can call under the same rules, except the acts that must be a person's.**

**Build status:** not started. **Milestone:** AM7 (Operator console). **Lane:** Operator console. **Planner:** Opus 5.5 (high). **Builder:** Grok 4.7 (xhigh). **Node QA:** Opus 5.5 (high, every loop). **Graph QA:** Fable 5.1 (high, at milestone close).
**Estimate:** 8-12 agent-hours (build, challenge and verify loops).

**Depends on:** [[A53 - Operator console shell, hardware-key sign-in and approval action pattern]], [[A39 - Treasury- withdrawals, escrow release, client-money reconciliation]], [[A40 - Distributions engine (SM-08)]], [[A41 - Tax engine- profiles, withholding, AMMA and CRS-FATCA]], [[A51 - Design extension B- operator console screens not in the prototype]]
**Graph edges requested (not yet in `final-graph.json`; the graph owner adds them before this node's Specify step):** [[A06 - Seed data and scenario simulator]] (scenarios `cash-delta`, `aml-third-party-deposits`, the new `bay01-in-review`, and the personas below), [[A20 - Three-way reconciliation engine with zero tolerance]] (the R10 results and closing breaks the Δ strip and the "cent of Δ" challenge read), [[A42 - AML screening, monitoring, cases and SMR clocks (SM-11)]] (the restriction that creates `aml_restricted` and `aml_hold`; A39 runs on a `no_alerts` stub until A42 lands), [[A37 - Orders, escrow, allocation and refunds (SM-05)]] and [[A38 - Finalise-and-mint and revert-and-refund pipelines]] (finalised offerings and refund batches), [[A104 - MCP server generated from the OpenAPI document]] (agent challenges run through the MCP server and the manifest test checks MCP exposure), [[A98 - Partner principals- trustee-RE, valuer, property manager, auditor, regulator observer and licensee users]] (the TP-OBS and TP-RE principals used by the read-shaping tests). A later-milestone node may start before an earlier one finishes, so these must be explicit edges, not assumed ancestors.
**Unlocks:** [[A78 - Operator journey J20 end to end in Docker (AM7 exit)]], [[A79 - End-to-end journeys- investor money path]], [[A80 - End-to-end journeys- sponsor and operations]]

**Oracle rule:** this is not an oracle node (`oracle: no`): the money rules this page shows (withdrawal thresholds, the manual-match threshold, escrow release preconditions, the distribution calculation, withholding rates, the file-hash binding, Δ 0) are decided and oracle-tested in A16, A17, A37, A38, A39, A40, A41 and A14, and the page moves nothing by itself. Money is on screen, though, so the node QA still writes hidden tests and Challenge fixtures to `<workspace>\gauntlet\hidden\A74\` before the build starts ([[App Gauntlet]] §2): Playwright specs against the running stack with the sandbox authenticator and the sandbox bank; a figure-equality check that compares every rendered amount, Δ and hash with the API response it came from, byte for byte; the `cash-delta`, `aml-third-party-deposits` (as extended by the A06 loop below), `bay01-in-review` and a tampered-line scenario from A06's simulator; a tipping-off DOM sweep per persona; a threshold-boundary set whose values and expected outcomes are derived at Specify from A14's `applies_when` rows and A16's config keys, never typed as literals (manual matches one cent below, at and one cent above `ledger.deposit.manual_review_cents`; withdrawals at A$25,000.00, A$25,000.01 and A$50,000.00, each for a different investor with no same-day withdrawal history, because A16's same-day-sum rule would otherwise change each other's policy code); its own crops of the `adTreasury` region of the prototype and of extension B's ADM-19 and ADM-20 frames; and an agent-parity table for every action on the three pages. The builder never reads that folder; the tests are published into `app/` only after the gate passes.

This node draws screens. It holds no business rule: who may match, return, release, fund, approve, authorise, generate or file, at what threshold, and whether Δ is 0, are decided in the API (A39 for treasury, A17 for receipts and payouts, A37 for refund batches, A38 and A39 for escrow release, A40 for runs, A41 for tax, A14 for every approval, A11 and A12 for principals, tokens and agent confirmation). The page shows what the API decided, cites the rule or code the API names, renders every amount exactly as the API's en-AU string, maps every tone from an API-supplied state or band through `toneFor`, and never lets a person believe money has moved before the API says so. This note is not legal advice; the client-money, float-interest, TTR, unclaimed-money and tax questions are recorded under Human gates and change API data, not this page.
