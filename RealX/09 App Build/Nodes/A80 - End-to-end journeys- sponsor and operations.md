# A80 - End-to-end journeys: sponsor and operations

**The operations half of RealX proven end to end through the built screens, in two forms. First, the two journeys no earlier suite walks in full: J06, a monthly distribution taken from the property manager's rent roll to money in investors' AUD wallets (paid equals approved, every one of the 19 SM-08 transitions reached, including a rejected run, a failed payment line, a manual payout and a reconciliation mismatch) plus the AMMA batch by 30 September; and J21, the wind-down of a failing trust (distress, a time-boxed halt that must carry reopening criteria and an end date, an inflow-freeze kill switch whose 2-hour ratification is allowed to lapse so the escalation ladder is proven, a court-directed sale, the final waterfall, a burn that equals supply to the unit, a closed register and a 7-year retention flag). Second, an "operating month": one continuous run on the clock from Wednesday 23 September to December 2026 in which J11 (a new sponsor admitted to a live tenant), J12 (a listing from property to a deployed token and a public page, plus the designed Marine Parade listing returned and fixed), J13 (a six-monthly valuation with a move above 10 percent refused without comparables), J14 (a reporting breach with the public amber flag and the distressed state), J19 (a sponsor's month-end), J06 and J21 happen in the order a real month would, every RealX-side step is taken on the console screens, and J20, the operator's daily run, is walked on each scripted morning and must find the traces the day before left. Checkpoint figures are exact to the cent and the unit, every agent-delegable step is repeated under a token with the same gate results, and the three designed screens (`spNew`, `spDist`, `adCmd`) are captured beside the prototype.**

## Build brief

This node writes no product behaviour, no product screen and no API. It owns a Playwright and Vitest suite, an operating-month scheduler, a checkpoint library, an agent-shadow suite, a capture configuration, an evidence writer and a one-page README, all under `<workspace>\app\e2e\operations\`. Browser steps go through the sponsor and partner route groups of `apps/web` (`http://localhost:3000`) and through A53's console origin (`CONSOLE_ORIGIN`, default `http://console.localhost:3001`) as the persona the owning policy row names. Reads that check what a screen showed go through `packages/sdk` (A09) as the same persona. Agent steps go through `packages/mcp` (A104) and the SDK under tokens. Nothing in `e2e/operations/` imports from `services/*`, `packages/db`, an adapter, or any `apps/*` source file, with three read-only exceptions: the page objects that a UI node exports for journey nodes (`apps/*/src/features/*/testing/page-objects.ts`; today only A66, A74 and A105 promise them, and A78 uses its own), A65's `e2e/sponsor/` harness files named in §1, and A78's `e2e/operator/operator-steps/console.ts`. Where a screen's owning node exports no page object (A62, A63 and A64 for SPN-01 to SPN-16, and any of A67 to A77 that does not), this node drives the screen through its own locator module `lib/screens/<screen>.ts`, written against accessible roles, labels and the `data-testid` values the owning node's spec names, never against that node's source files; each such screen is also recorded as a fix item on the owning node ("export `testing/page-objects.ts`"), and when the export lands the locator module is replaced by it. A lint in `npm run verify` fails on any other import, and a second lint fails on any SDK write outside `parity/` and `month/orders/` (writes in the journeys happen through screens only; `month/orders/` may call only the order-placement and order-funding operation ids of A37 and the bank panel's inbound-payment verb, as simulated investors, see §6).

- **Clock.** Only A09's clock is used. One write per journey is replayed with the same idempotency key through the SDK in `parity/` and must return the first result with no second row.
- Tooling errors, each stopping the run at once with one line: `STACK_NOT_UP` (within 10 s), `CONSOLE_NOT_UP`, `PERSONA_MISSING <role>` (spec point (a)), `OPS_E2E_DIRTY_STATE` (an isolated spec started without a reset), `OPS_E2E_SCREEN_MISSING <code> <owning node>`, `OPS_E2E_STUB_ROUTE <operationId>` (a route still answering `x-realx-status: stub`), `OPERATOR_STEPS_NOT_CONSOLE`, `CLOCK_BACKWARDS`, `MONTH_STEP_OUT_OF_ORDER`, `DESIGN_FOLDER_CHANGED <file>`.
