# A08 - Sandbox adapter framework, config and phase flags

**The frame that keeps every third party behind an interface, keeps the whole build in sandbox mode, and makes the Q12 swap points explicit: `packages/adapters/core` (registry, per-partition instances, conformance harness with scenario drivers, magic-input markers, health, operator hooks, the adapter lint rules), `packages/config` (zod env schema with per-node config sections, `RUN_MODE=local`, phase flags P1/P2/P3 and kill-switch defaults, the chain allow-list, the "no production selector" test), plus the two adapters everything else stores secrets and files through: `kms` (with a key-use policy) and `storage` (with per-owner references).**

**Build status:** not started. **Milestone:** AM0 (Foundations). **Lane:** Platform. **Planner:** Opus 5.5 (high). **Builder:** Grok 4.7 (xhigh). **Node QA:** Opus 5.5 (high, every loop). **Graph QA:** Fable 5.1 (high, at milestone close).
**Estimate:** 8-12 agent-hours (build, challenge and verify loops).

**Depends on:** [[A01 - Repo scaffold, toolchain and verify command]], [[A02 - Domain ids, money and unit math]]
**Unlocks:** [[A04 - Database schema, migrations and row-level security]], [[A09 - API and worker skeleton with OpenAPI-generated SDK]], [[A15 - Custody sandbox adapter and policy engine P1-P10]], [[A17 - Bank rail sandbox adapter (NPP-PayID-PayTo) and receipt matching]], [[A21 - Licences, feature flags and licence perimeter (G21)]], [[A22 - Identity-DVS and sanctions sandbox adapters]]

**Oracle rule:** The node QA writes hidden oracle tests from this spec to `<workspace>\gauntlet\hidden\A08\` before the build starts ([[App Gauntlet]] §2). The builder never reads that folder; the cases are published into the repo only after the gate passes. This is an oracle node because `kms` holds authority: the approval attestation key that binds an approval ID to a custody signature, the V1-V3 vault keys, the V7 paymaster signer, the deployer and the RealX guardian key all sit behind its interface. The oracle scope is fixed: (1) kms known-answer vectors (AES-256-GCM, secp256k1, P-256); (2) AAD and tenant isolation; (3) the key-use policy (a module that is not an allowed caller cannot sign with the attestation key or decrypt another purpose's data, at runtime and at lint); (4) no private key or master key material in any output; (5) the no-production plants (§2). The node QA also writes non-oracle challenge suites for storage limits and cross-tenant isolation, the flag-default snapshot, and the conformance harness's broken fixtures.

## Build brief

Why this node exists: the architecture brief (§5, §8.4) and the requirements catalogue (Appendix C, non-functional N15) say every vendor is an adapter with a sandbox and a conformance suite, that `.env` is validated at start and a production adapter is refused while `RUN_MODE=local`, and that the Q12 option-1 swap points are written down where a builder will find them. Later adapter nodes (A15 custody, A17 bank, A22 identity and sanctions, and the registry, e-sign, email/SMS, chain, bundler nodes) implement *their* interface on *this* frame; they do not re-invent selection, health, scenario or config conventions. Because many later nodes need config keys, flag reads, markers and key purposes, this node defines explicit extension points for each (§1, §2, §3) so no later node edits A08's owned paths or reads `process.env` itself.

### 1. `packages/adapters/core` (the frame)

- **Adapter definition.** `defineAdapter<I>({ name, version, interface: zodContract, implementations: { sandbox: (ctx) => I }, markers?: MarkerDef[], reconfigure?: true, swap: { humanGates: HumanGateId[], candidates: string[], whatChanges } })`. `name` is lower-case (`identity`, `sanctions`, `bank`, `custody`, `registry`, `esign`, `email`, `sms`, `chain`, `bundler`, `paymaster`, `valuation-feed`, `property-data`, `stablecoin`, `kms`, `storage`). The factory context `ctx` is `{ config, clock, random, partition, log }`. Each adapter package exports one `manifest.ts` that calls it; the manifest is data, so tests and docs can read it.
- **Registry, selection and partitions.** `getAdapter('bank', { partition? })` reads `ADAPTER_BANK` from the validated config (see §2). Value `sandbox` is the default when the variable is absent. Any other value must (a) name an implementation registered in that manifest and (b) be allowed by `RUN_MODE`; in this build the only registered implementation of every adapter is `sandbox`, and `RUN_MODE=local|test` refuses any other selector at start-up with an error that names the variable and the offending value. Vendor candidates appear in `swap.candidates` as strings only, never as code. `partition` is `live` (the default) or a sandbox owner's principal id (the `sandbox_of` value of D04's per-user sandbox, [[A99 - Developer surface- API versioning, reference docs, per-user sandbox and SDK-MCP packaging]]). The registry holds one instance per `(adapter, partition)`, created lazily, each with its own state (sandbox files under `STORAGE_SANDBOX_ROOT/partitions/<partition>/<adapter>/`). `sandboxControls({ partition })` returns only that partition's controls, and `reset(seed)` in one partition leaves every other partition's state untouched. `evictPartition(partition)` drops the instances and their state (used by A99's purge).
- **Reconfigure.** An adapter that declares `reconfigure: true` implements `reconfigure(values)`, where `values` is validated against the overlayable subset of that adapter's config section (§2) before it is applied; an invalid value leaves the running configuration unchanged and returns `CONFIG_INVALID` naming the variable. This is the hook [[A46 - Job scheduler, integrations health and webhooks]] uses to apply an approved `integration_config_version` without a restart.
- **Instance metadata.** Every adapter instance carries `{ name, implementation, environment: 'sandbox' | 'live', partition, version, startedAt }`. `environment` is `sandbox` for every implementation registered in this build; `live` is reserved and no code path can construct it here.
- **Health.** Every adapter implements `health(): Promise<AdapterHealth>` with `{ name, implementation, environment, status: 'ok' | 'degraded' | 'down', latencyMs, lastCheckAt, lastError?: { code, message, at } }` (PII-free). `adapterHealth()` in core probes all registered adapters of the `live` partition in parallel with a per-adapter timeout `ADAPTER_HEALTH_TIMEOUT_MS` (default 2000) and returns the array plus `checkedAt`. Status rule: `down` when the probe times out (`lastError.code = HEALTH_TIMEOUT`) or throws; `degraded` when it answers within the timeout but `latencyMs` is above `ADAPTER_HEALTH_DEGRADED_MS` (default 1000), or when the adapter itself reports `degraded`; otherwise `ok`. This is the feed for ADM-32 Integrations and jobs (drawn by [[A76 - Console- regulatory calendar and data room, sponsor performance, integrations and jobs]] on the integration rows and probe job of A46) and for the API's `/internal/health/adapters` route that [[A09 - API and worker skeleton with OpenAPI-generated SDK]] exposes. Health is never cached across probes; a stopped sandbox shows `down` on the next probe.
- **Conformance harness and scenario drivers.** `runConformance(manifest, makeImpl, options)` is a Vitest `describe` factory, where `makeImpl()` returns `{ impl, driver: ScenarioDriver }`. `ScenarioDriver` is `{ supports(scenario): boolean, force(scenario, input): Promise<input'> }`: the sandbox driver produces a scenario by applying the marker builders (below) to the input; a future vendor driver produces it with the vendor's own test fixtures (test accounts, test names, test amounts). Each adapter package ships `conformance/*.conf.ts` written against the *interface*, not the sandbox, and forces error and scenario cases only through `driver.force(...)`, never by writing a marker directly, so the same suite runs unchanged against a vendor. Rules: every verb in the interface contract must have at least one conformance case (the harness fails with the verb name if a verb is uncovered or the implementation lacks it); every scenario the manifest declares must be producible (the harness fails naming the verb and the scenario when `driver.supports` is false; nothing is skipped); return values are validated against the zod contract; determinism cases call `reset(seed)` twice and assert identical outputs; error cases assert the typed error codes in the contract. The sandbox must pass its own suite; a real vendor implementation must pass the same suite later, under HG-VENDOR, before it may be registered.
- **Magic-input markers.** Two files with different reach. `markers.ts` exports *builders* (`withNameSuffix(name, 'REFER')`, `simReference('DELAY', 30)`, `amountWithCents(base, 'returned')`, `exactValue('bank', 'bsb', 'invalid_account')`) that tests, `packages/sim`, e2e and scenario drivers may import anywhere; they only build inputs. `scenario.ts` exports the single parser `scenarioOf(adapter, input): Scenario[]`, which may be imported only inside a `sandbox/` folder, so a vendor implementation can never honour a marker. Marker definitions are data: `MarkerDef = { token, kind: 'name-suffix' | 'reference-prefix' | 'amount-cents' | 'exact-value', field?, scenario, description }`. Core ships the shared set: name suffixes ` REFER`, ` REJECT`, ` PEP`, ` SANCTION`, ` SLOW`; reference prefixes `SIM-DELAY-<seconds>`, `SIM-RETURN` (returned payment), `SIM-MISMATCH` (payer-name mismatch), `SIM-DRIFT-<units>` (registry drift), `SIM-REJECT`; amount cents `.13` = delayed, `.99` = returned, `.77` = partial. Each adapter manifest adds its own through `markers` (for example A22's ` FRAUD`; A17's `SIM-DUP`, `SIM-CASH`, BSB `000-000` and account `99999999`; A15's `SIM-REVERT`) without editing core. At start-up core merges the shared set with every manifest's markers and refuses a duplicate token, or a token that is a prefix of another of the same kind, with `MAGIC_MARKER_DUPLICATE` naming both owners. `packages/adapters/core/MAGIC-INPUTS.md` is generated from the merged set, one table per adapter.
- **Sandbox operator hooks.** Interface `SandboxControl { listScenarios(), trigger(event, payload), advance(duration), reset(seed), state() }`. Every sandbox registers one per partition; core exposes `sandboxControls({ partition })` so A09 can mount `/sandbox/<adapter>/*` routes only when `RUN_MODE` is `local` or `test`, A46 can forward the ADM-32 sandbox panel's buttons to `trigger` with its permission check and audit event, and A76 can draw that panel ("receive a payment", "return a payment", "ack an instruction", "drift the register"). Live implementations have no control object; core throws if one is registered outside `sandbox/`.
- **Clock and randomness.** Core defines `Clock { now(): Date }` and `SeededRandom`; sandboxes receive both by injection and never call `Date.now()` or `Math.random()` directly (lint rule below). A09 owns the injectable clock service that advances time; this node only defines the interface and a default real clock.
- **Call log.** A wrapper around every adapter instance logs `{ adapter, implementation, environment, partition, verb, durationMs, outcome: ok|error, errorCode, correlationId }` through pino, never arguments or results (they may hold PII). The correlation id comes from the caller (request id or job id). The wrapper does no principal, token or flag checks: refusing agent traffic when `agents.traffic` is off is A12's gateway middleware and A48's `KillSwitchProvider` tier, before any adapter is reached.
- **Reference adapter.** A tiny `echo` adapter (interface: `ping`, `echo`, `fail(code)`, `slow(ms)`; one declared scenario `fail-on-marker` with its own marker ` ECHO-FAIL`) proves the frame end to end and is the fixture for the harness's own tests, including the deliberately broken implementations (missing verb, wrong return shape, non-deterministic after `reset`, and a driver that cannot produce a declared scenario).
- **Lint rules (home and wiring).** The rules live in A08's own path as a local ESLint plugin, `packages/adapters/core/eslint/` (`plugin.js`, one file per rule, fixture tests per rule), with its own flat config `eslint.adapters.config.js` that applies the plugin to the whole `app` tree. It is run as A08's registered verify step (group `lint`) through A01's `realx.verify` block in `packages/adapters/core/package.json`, so A01's root `eslint.config.js` is not edited. Rules: `realx/no-magic-outside-sandbox` (imports of `scenario.ts` or `@realx/adapters-core/scenario` only from a path with a `sandbox` segment); `realx/adapter-via-registry` (no import of any `packages/adapters/<name>/src/sandbox/**` except from that adapter's own `manifest.ts` and tests; everything else calls `getAdapter`); `realx/no-nondeterminism-in-sandbox` (no `Date.now`, `new Date()` without argument, `Math.random`, `crypto.randomUUID` inside `sandbox/`); `realx/kms-capability-boundary` (§3); `realx/no-process-env` (§2). Path matching normalises separators and compares segments case-insensitively, so `Sandbox/`, `SANDBOX\` and mixed-case Windows paths are treated alike; relative paths, `@realx/*` aliases, `require()` and dynamic `import()` are all resolved.
- **Swap points document.** `packages/adapters/core/SWAP-POINTS.md` is generated from the manifests plus one core-declared non-adapter row, `token-contracts` (Q12): one row per swap point with sandbox behaviour, production candidates (from the research pack: Equifax/Sumsub/Averer for identity, Monoova/Zepto for bank, Fireblocks/BitGo/Dfns for custody, IQ-EQ/Automic/Boardroom-type for registry, DocuSign/Dropbox Sign for e-sign, Postmark/SES and Twilio, Alchemy/QuickNode/Redbelly RPC, Pimlico/Alchemy bundler, AUDM/AUDD stablecoin in P3, cloud KMS/HSM, any S3-compatible store), the human gates that unlock the swap, and "what changes" (client only / key references only / file mapping / signer of gateway calls). A row may carry several gates; every gate id must be in `HUMAN_GATE_IDS`, a constant in core whose values the node QA checks against the [[Human Gates]] note at Challenge. Gate assignments: token contracts = HG-LEGAL (the T-REX GPL-3.0 opinion) + HG-AUDIT + HG-PROD; custody = HG-VENDOR + HG-KEYS + HG-PROD; bundler and paymaster = HG-VENDOR + HG-KEYS + HG-PROD; chain RPC = HG-VENDOR + HG-PROD; stablecoin = HG-LEGAL + HG-VENDOR; kms = HG-KEYS; identity, sanctions, bank, registry, e-sign, email, sms, valuation feed, property data and storage = HG-VENDOR. The Q12 token-layer line reads: T-REX contracts ↔ a Tokeny-style platform API behind the `chain` and `custody` interfaces, with register, ledger, recon and rules unchanged. Core also exports `swapPoints()` (the same rows as data), which is what ADM-32 and A46 read for the open-gate list. A test fails if a manifest row is missing from the doc, the doc names an adapter with no manifest, or a gate id is not in `HUMAN_GATE_IDS`.

### 2. `packages/config`

- **Env schema and config sections.** `packages/config` is the only reader of `process.env` in `packages/`, `services/` and `apps/`. It owns the core section (below) and an extension point, `defineConfigSection(name, zodShape, { consumer, secret?: string[], overlayable?: string[] })`. A node that needs its own variables writes a `config.section.ts` in *its own* path and names it in its workspace `package.json` under `realx.configSection` (the same `realx` block A01's `scripts:sync` reads). `loadConfig({ overlay? })` discovers every declared section from the workspace `package.json` files, merges them with the core section into one zod object, parses once at start, reports *every* error of every section at once (each naming the variable and the owning node), and exits non-zero before any database, chain or network call. Two sections declaring the same variable fail with `CONFIG_KEY_COLLISION` naming both. The parsed result is typed per section (`config.core`, `config.<section>`). Expected sections include A09 (rate limits, ports), A11 (`STAFF_AUTHENTICATOR_AAGUIDS`, relying-party origins), A12 (rate ceilings), A15 (AgentGateway placeholder address), A16 (withdrawal settings), A23 (`OTEL_EXPORTER_OTLP_ENDPOINT`, `MCP_PORT`, `PANEL_PORT`), A29 (`WALLET_EAGER_DEPLOY`, guardian waiting period), A33, A37 and A05 (design path); A08 does not declare their variables. Exemptions from the `process.env` rule, stated in the lint config: `contracts/hardhat.config.ts` (A07 loads outside the app loader), `scripts/` (A01) and `infra/`.
- **Core section variables.** Documented in `packages/config/README.md`, generated from the merged schema (all sections) with type, default, secret flag, overlayable flag and consuming node: `RUN_MODE` (`local` | `test`; no other value exists in this build; adding `staging` or `production` is a change under HG-PROD), `PHASE` (`P1` | `P2` | `P3`, default `P1`), `DATABASE_URL`, `CLOCK_AS_OF` (optional ISO date for the injected clock's start, used by A06 and A23), `CHAIN_ID`, `CHAIN_RPC_URL`, `TESTNET_OPT_IN` (absent or exactly `A86`), `ADAPTER_<NAME>` for every manifest name, `ADAPTER_HEALTH_TIMEOUT_MS`, `ADAPTER_HEALTH_DEGRADED_MS`, `KMS_SANDBOX_MASTER_KEY_FILE`, `KMS_SANDBOX_CREATE_MASTER` (default `false`), `STORAGE_SANDBOX_ROOT`, `STORAGE_MAX_OBJECT_BYTES` (default 26214400), `FLAG_<KEY>` overrides, log level.
- **Chain allow-list.** One exported constant, `CHAIN_ALLOW_LIST`, is the single source that `CHAIN_ID` and `CHAIN_RPC_URL` are validated against, that A07's `contracts/TOOLCHAIN.md` must equal, and that A23's static test compares with. Hosts are exact, never wildcards. Default (no opt-in): `CHAIN_ID=31337` with an RPC host in `{ localhost, 127.0.0.1, ::1, chain }` (`chain` is the compose service). Testnet: `CHAIN_ID=84532` with host `sepolia.base.org` or a host listed in A07's `TOOLCHAIN.md` Base Sepolia list, accepted only when `TESTNET_OPT_IN=A86` is also set (A86's opt-in profile); without the opt-in, 84532 or a non-local host fails with `CHAIN_RPC_NOT_LOCAL`. Every other chain id fails with `CHAIN_ID_NOT_ALLOWED`; `mainnet.base.org`, any `*.alchemy.com`, `*.quicknode.pro` or Redbelly mainnet host fails even with the opt-in. A08 checks config only; A86's preflight (the RPC's real `eth_chainId`, key checks) stays A86's.
- **Overlay.** `loadConfig({ overlay })` lets A46 apply an approved `integration_config_version` after `.env`: the overlay may set only variables a section marks `overlayable`, the merged result is re-validated by the same schema (allow-lists included), and `RUN_MODE`, `PHASE`, `TESTNET_OPT_IN` and every `secret` variable are never overlayable (`CONFIG_NOT_OVERLAYABLE` naming the variable).
- **Secrets hygiene.** Config values marked `secret` are never logged or included in `redactedConfig()`, which is what health and evidence use. `.env.example` is generated from the merged schema (every section); `.env` is gitignored (A01 already enforces scanning).
- **Phase flags.** `flags.ts` declares the flag table as data: `{ key, phase, kind: 'phase' | 'kill-switch' | 'licence-bound', default: 'on' | 'off', defaultScope: 'global' | 'all-sponsors' | 'all-trusts', description, licenceBinding: null }`. `defaultScope` renders on ADM-34 as "Global", "All sponsors" or "All trusts". The frozen table:

| Key | Phase | Kind | Default | Default scope | Description |
|---|---|---|---|---|---|
| `offers.wholesale` | P1 | licence-bound | on | All sponsors | Wholesale offers of sponsors' trusts may open (bound by A21 to the CAR appointment) |
| `offers.retail` | P2 | licence-bound | off | All sponsors | Retail offers under a PDS and TMD in the registered MIS |
| `resale.board` | P2 | licence-bound | off | All trusts | Guarded resale board |
| `governance.votes` | P2 | licence-bound | off | All trusts | On-platform unitholder votes |
| `wallets.external` | P2 | phase | off | Global | Linking a self-custodied external wallet (A29) |
| `payouts.stablecoin` | P3 | licence-bound | off | Global | AUD stablecoin payouts |
| `platform.inflow_freeze` | P1 | kill-switch | off | Global | On = no new money is accepted (SGL+R, A48) |
| `platform.marketplace_suspend` | P1 | kill-switch | off | Global | On = nothing is offered, sold or traded (SGL+R, A48; ADM-34's "marketplace suspend") |
| `agents.traffic` | P1 | kill-switch | on | Global | Off = every API-token, MCP and session-key call is refused platform-wide (D04, G22, ADM-35) |

  `foreign.allowed` is not an A08 flag: it is a per-listing field with a country list (A24's deploy params; carried on the offering by A36). New flag keys are added only by reopening this spec (a one-row data change plus the snapshot update); A21 and other nodes never add keys.
- **`isEnabled(key, ctx)`.** `ctx` is `{ tenantId?, vehicleId? }`. An unknown key throws `FLAG_UNKNOWN`. Resolution order, first answer wins: (1) the env override `FLAG_<KEY>=on|off` (honoured only in `RUN_MODE=local|test`, which is every run mode in this build; an override of an unknown key is a config error); (2) the registered `OverrideSource` (A21's database source, resolving vehicle, then tenant, then platform scope); (3) the static default. The **phase guard** then applies to every answer except the env override: a flag whose `phase` is later than `PHASE` is `off`, whatever the source says, and a source answer that was guarded is logged once per key as `FLAG_PHASE_GUARDED`. `isEnabled` returns only the flag's own value; what a kill switch means for other flags or calls (for example `platform.marketplace_suspend` pausing offers) is the consumer's rule (A48, A12, A36), not combined here. Every env override in effect is written to the start-up log, so a test run that turned a P2 flag on says so.
- **No production selector test.** `packages/config/test/no-production.test.ts` asserts, over the whole `<workspace>\app` tree (every workspace, nested workspaces and dev-dependencies included): every adapter manifest registers exactly the implementation set `{ sandbox }` (set equality, so `sandbox2`, `Sandbox` or `sandbox-live` fail); no `package.json` depends on a vendor SDK from the block list (`fireblocks-sdk`, `@fireblocks/*`, `@bitgo/*`, `@dfns/*`, `monoova`, `zepto`, `@sumsub/*`, `equifax`, `docusign-esign`, `@docusign/*`, `postmark`, `@aws-sdk/client-ses`, `twilio`, `@alchemy/*`, `@pimlico/*`); no mainnet chain id (`1`, `8453`, `151` Redbelly mainnet) in a chain-id position, meaning a `chainId` / `CHAIN_ID` / `chain_id` key in TS, JSON, YAML or `.env*` files, an adapter manifest, a deployment JSON or `deploy/**/out/<chainId>/` folder name, a Hardhat `networks` entry, or a `viem/chains` import of `mainnet`, `base` or a Redbelly mainnet export; no RPC, bundler or paymaster URL anywhere in source, config or compose whose host is outside `CHAIN_ALLOW_LIST`, or that carries an API-key-shaped path or query segment (`/v2/<key>`, `/rpc?apikey=`, `?key=`); no `RUN_MODE` enum value other than `local` and `test`; and no file outside `packages/config` and the stated exemptions reads `process.env`. The test must *fail* when the node QA plants any of these, which is how it is verified.

### 3. `packages/adapters/kms`

- **Interface and capability handles.** The raw adapter exposes only non-sensitive verbs: `publicKey(keyRef)`, `verify(keyRef, digest, sig, alg)`, `listKeys(filter)` (never material), `health()`, and `forCaller(identity)`. Every sensitive verb is on the capability handle that `forCaller` returns: `createKey({ purpose, algorithm, tenantId? })` → `keyRef`, `generateDataKey(keyRef)` → `{ plaintextKey, wrappedKey }` (envelope), `encrypt(keyRef, plaintext, aad)`, `decrypt(keyRef, ciphertext, aad)`, `sign(keyRef, digest, alg)`, `rotateKey(keyRef)`, `getSecret(ref)` (secret values of purpose `secret-value` only; never a signing or data key). Key refs are opaque `kms://<impl>/<partition>/<tenant|platform>/<purpose>/<version>`. Algorithms: AES-256-GCM for encryption; `secp256k1` and `P-256` for signing. There is no verb that returns private key material, and the TypeScript types make one unrepresentable.
- **Key-use policy.** `packages/adapters/kms/src/key-use.ts` is a closed table (data, owned here) of purposes and the caller identities allowed to use them; `createKey` records `purpose` and `allowedCallers` from it, and the handle checks them on every call. Initial table: authority purposes `approval-attestation`, `vault-v1`, `vault-v2`, `vault-v3`, `identity-agent-v4`, `deployer`, `guardian` → `sign` by `custody` only; `paymaster-v7` → `sign` by `custody` and `paymaster`; data purposes `db-column` → `db`, `storage-data` → `storage`, `webhook-secret` → `webhooks` (encrypt, decrypt, generateDataKey); `bootstrap` (A23's key generation report) may call `createKey` and `publicKey` only. A disallowed call fails with `KEY_USE_NOT_PERMITTED` and writes a `kms.use_refused` log line (key ref, purpose, caller, verb, correlation id, no payload). Lint rule `realx/kms-capability-boundary` maps each identity to its only permitted path (`custody` → `packages/adapters/custody/`; `paymaster` → the paymaster module the wallet node names; `db` → `packages/db/`; `storage` → `packages/adapters/storage/`; `webhooks` → A46's module; `bootstrap` → `infra/stack/`), refuses `forCaller` with a non-literal argument, and refuses an identity literal outside its path. Adding a purpose or caller identity reopens this spec.
- **Sandbox.** A local encrypted store under `STORAGE_SANDBOX_ROOT/partitions/<partition>/kms/` (a docker volume in compose, `realx_kms`). The dev master key lives by default at `%LOCALAPPDATA%\RealX\kms\dev-master.key` on the host and as the docker secret `realx_kms_master` in compose; `KMS_SANDBOX_MASTER_KEY_FILE` may point elsewhere but never inside `app/` (a path under `app/` is a config error). The file is read if present; it is created only when `KMS_SANDBOX_CREATE_MASTER=true`, and starting without it and without that permission fails fast with `MASTER_KEY_MISSING`. Every key is wrapped by the master key; every ciphertext is `version || nonce || tag || body` with the AAD bound in; the tenant id and purpose are part of the AAD so a ciphertext cannot be decrypted under another tenant's or purpose's key ref. Rotation creates version n+1 and keeps n decryptable; `listKeys` never returns material. Every `sign` and `decrypt` call is logged with key ref, purpose, caller identity, caller correlation id and outcome (no payload). Keys carry no value and can be regenerated.
- **Who uses it.** [[A04 - Database schema, migrations and row-level security]] envelope keys for `_enc` columns (one key per tenant per purpose, caller `db`); A15 keystore (caller `custody`); the paymaster signer (caller `paymaster`); storage's per-tenant data keys (caller `storage`); A46's webhook secrets (caller `webhooks`).
- **Swap.** Cloud KMS or HSM under HG-KEYS: the implementation changes, key refs change prefix, the key-use table becomes the KMS's key policy (IAM conditions on the calling service), and callers do not change.

### 4. `packages/adapters/storage`

- **Interface.** `putObject({ tenantId, ownerRef, classification, contentType, bytes | stream })` → `{ objectId, sha256, size, contentType, storedAt }`; `getObject(tenantId, objectId)` → stream plus metadata; `headObject(tenantId, objectId)`; `presignUpload({ tenantId, ownerRef, classification, maxBytes, allowedTypes, expiresIn })` → `{ uploadToken, uploadUrl, expiresAt }` and `completeUpload(uploadToken)`; `presignDownload(tenantId, objectId, expiresIn)`; `setLegalHold(tenantId, objectId, held)`; `deleteObject(tenantId, objectId)` (refused while held); `scan(tenantId, objectId)` → `clean | infected | pending`; `health()`.
- **References and blobs.** `objectId` is a *reference*: a new unguessable id (`obj_<ulid>`) for every put, bound to one `tenantId`, `ownerRef` and `classification`. `sha256` addresses the *blob*: identical bytes within one tenant are stored once, and several references may point at one blob, each keeping its own owner and classification. Legal hold and delete act on a reference; the blob is purged only when no reference to it remains, and a held reference keeps its blob. Across tenants blobs are never shared; `headObject`/`getObject` with another tenant's `objectId` returns the same `OBJECT_NOT_FOUND` as a missing object (no existence leak).
- **Sandbox.** Blobs under `STORAGE_SANDBOX_ROOT/partitions/<partition>/objects/<tenant>/<sha256[0:2]>/<sha256>` on a docker volume, encrypted at rest with a per-tenant data key from the kms adapter (caller `storage`, envelope; wrapped key stored beside the blob); references in an index file beside them. Limits: `STORAGE_MAX_OBJECT_BYTES` (default 25 MiB) enforced on the stream, not the declared length; allowed types default `pdf, png, jpg, jpeg, csv, xlsx, docx, zip(evidence only)`, decided by magic-byte sniffing, never by extension or declared `contentType`; mismatches are refused with `TYPE_MISMATCH`. Presigned upload tokens are single-use, bound to tenant, owner, classification, limits and expiry, and the sandbox serves the upload URL itself (A09 mounts it). Malware-scan stub: `clean` for everything except the EICAR test string or a name containing `EICAR`, which is quarantined (`infected`, not retrievable, audit event). Retention: `deleteObject` on a held reference returns `LEGAL_HOLD`. Whether a tenant is suspended is not known here; refusing uploads for a suspended tenant is the caller's check (A33 tenancy, A35 documents).
- **Who uses it.** Every uploaded document and generated PDF: KYC documents, deeds and title extracts, certificates, valuation reports, rent rolls, proof-of-property evidence, marketing items, the deterministic PDFs from A35, licence evidence for A21, the single-use upload links valuers and property managers use from SPN-04/10/11 ([[A63 - Sponsor console- new listing wizard SPN-03 to SPN-06 and offer monitor SPN-07]], [[A64 - Sponsor console- register, distributions, property reporting, valuations, announcements]] and [[A98 - Partner principals- trustee-RE, valuer, property manager, auditor, regulator observer and licensee users]]), and gauntlet evidence files that are not secrets.
- **Swap.** Any S3-compatible object store: presign becomes the store's presigned URL, the interface is unchanged, the reference/blob model and the envelope encryption stay RealX's.

### 5. Error and empty states

- Missing or invalid env (any section): process exits code 1 with the full list of problems, each naming the variable and owning node; nothing partial starts.
- Unknown adapter name in `getAdapter`: typed error `ADAPTER_UNKNOWN` at start-up (registry is validated eagerly, not on first call). Duplicate marker: `MAGIC_MARKER_DUPLICATE`. Config: `CONFIG_KEY_COLLISION`, `CONFIG_NOT_OVERLAYABLE`, `CONFIG_INVALID`, `CHAIN_ID_NOT_ALLOWED`, `CHAIN_RPC_NOT_LOCAL`. Flags: `FLAG_UNKNOWN`.
- Adapter `down`: callers get `ADAPTER_UNAVAILABLE` with the adapter name; health shows `down` with `lastError`.
- Empty registry health (no adapters registered): returns `[]` with `checkedAt`, never throws; ADM-32 renders its empty state.
- Storage: `OBJECT_NOT_FOUND`, `OBJECT_TOO_LARGE`, `TYPE_MISMATCH`, `TYPE_NOT_ALLOWED`, `UPLOAD_TOKEN_INVALID` (used, expired, wrong tenant), `LEGAL_HOLD`, `QUARANTINED`. KMS: `KEY_NOT_FOUND`, `AAD_MISMATCH`, `TENANT_MISMATCH`, `MASTER_KEY_MISSING`, `ALGORITHM_UNSUPPORTED`, `KEY_USE_NOT_PERMITTED`.

## Node-specific challenges (node QA)

- **A vendor gets in.** `ADAPTER_BANK=monoova RUN_MODE=local` starts the API and serves requests; or an implementation named `sandbox2`, `sandbox-live` or `Sandbox` slips past the no-production test because the check is a string equality rather than "the set is exactly `{sandbox}`"; or a vendor SDK is added under a dev-dependency or a nested workspace and the block-list scan only reads root `package.json`.
- **Production run mode by another door.** A package reads `process.env.NODE_ENV=production` or its own `REALX_ENV` to switch behaviour; or `CHAIN_ID=8453` is accepted because the schema validates type but not the allow-list; or `CHAIN_RPC_URL=https://mainnet.base.org` with `CHAIN_ID=84532` passes because the host check is a suffix match; or `sepolia.base.org` is accepted without `TESTNET_OPT_IN=A86`; or the P2 flag `resale.board` forced on by `FLAG_RESALE_BOARD=on` in `RUN_MODE=test` is still on after the config is re-loaded as `local` without the override; or a stub `OverrideSource` returning `on` for `resale.board` under `PHASE=P1` turns it on.
- **Extension that bypasses the frame.** A later node's section variable is read with `process.env` instead of a config section; a section error is reported only after the core section passes; a second adapter's marker needs an edit to core; two adapters register the same marker token and the second silently wins; an overlay sets `RUN_MODE` or a secret.
- **Wrong launch state.** `platform.inflow_freeze` or `platform.marketplace_suspend` defaults to on (nothing can be funded or offered) or `offers.retail` defaults to on in P1 (a retail order path opens without a PDS); `agents.traffic` overridden off still reads `on` through `isEnabled`. (Refusal of agent calls when it is off is challenged in A12, A48 and A101, not here.)
- **Key material leaks and authority bypass.** `getSecret` on a signing key ref returns the private key; `listKeys` or a debug `state()` hook serialises the master key; `decrypt` succeeds with a ciphertext produced under tenant A when called with tenant B's key ref (AAD not bound); a module outside `packages/adapters/custody` obtains `forCaller('custody')` or calls `sign` with the attestation key through the `storage` identity and succeeds; a `sign` call leaves no log line; the master key file is created inside `app/` where `git add -A` would commit it, or is created without `KMS_SANDBOX_CREATE_MASTER=true`; rotation makes version n unreadable and A04's `_enc` columns become garbage.
- **Storage limits and isolation.** A Windows executable renamed `deed.pdf` is accepted because the type check trusts the extension; a 25 MiB + 1 byte stream passes because the check reads `content-length`; `headObject` on another tenant's object returns 403 rather than 404 (existence leak); a presigned upload token is reused within its window; an EICAR fixture is stored retrievable; a held object is deleted through `deleteObject` on a different tenant id; two owners upload the same bytes and one owner's delete removes the other's document.
- **Harness that passes anything.** The conformance harness skips verbs the implementation does not define, or skips a scenario its driver cannot produce, instead of failing; determinism cases pass because `reset(seed)` is a no-op and the sandbox is stateless anyway; magic inputs are honoured by a non-sandbox file because the lint rule matches folder names case-sensitively on Windows; a `reset` in one partition clears another partition's sandbox state.
- **Health that lies.** `adapterHealth()` returns the last known `ok` after a sandbox is stopped, or hangs on one slow adapter so ADM-32 never loads; `lastError.message` carries a payer name from the failing call.
- **Docs drift.** `SWAP-POINTS.md` is hand-edited and omits the `bundler`, `stablecoin` or `token-contracts` rows, or names Fireblocks as a registered implementation; the token-contracts row lacks HG-LEGAL; a gate id appears that is not in `HUMAN_GATE_IDS`.
