# A61 - Docker Desktop preview of the investor app (AM5 exit)

**One `preview` compose overlay on A23's stack that the user starts from Docker Desktop with one command (`npm run preview:up`). It adds the built investor web app, a read-only server for the prototype and a small developer landing page to A23's Postgres, API, worker, Hardhat chain, sandbox bank and identity panels and MCP server, and seeds the design dataset. The user can then walk from visitor to investor: browse the offers, sign up and onboard as Alex Morgan, pay in through the sandbox bank panel, buy Kent Street Terrace tokens and see the order held in escrow. Playwright runs J01, J02 and J04-to-escrow over the same profile as the AM5 exit check, and a scripted MCP agent repeats the J04-to-escrow path under a mandate with the same gate results. Every designed visitor and investor screen is captured beside the prototype at 1280 px and 375 px for the evidence. A one-page guide lists the sandbox "magic inputs". The human step HG-REVIEW follows: the user opens the preview, and each piece of feedback becomes a fix item on the node that owns the behaviour, or a proposed new node, never a patch here. The node deliberately does not wait for the wallet, account and information pages (A55, A59, A60), so its software gate lands one gauntlet earlier. The set of pending steps is frozen at Specify, and AM5 is closed only after a full re-run of this node once A55 and A59 have passed (Gate).**

## Build brief

This node writes no product behaviour and no product screen. It owns a compose overlay, a developer landing page, a read-only prototype server, a Playwright and Vitest suite, a screenshot comparer, an operator-step helper, an evidence writer and a guide. Every call the suite and the helpers make goes through `packages/sdk` (A09) or `packages/mcp` (A104) against the running `api` and `mcp` containers, or through the browser against the running `web` container. Nothing in `e2e/preview/` or `infra/preview/` imports from `services/*`, `packages/db`, any adapter or any `apps/web` source file, and a lint in `npm run verify` fails if it does. Human acts (passkey sign-in and step-up for seeded personas, staff hardware-key decisions, the certificate decision) go through A11's local simulated authenticator (`/__test/*`, mounted only in `RUN_MODE=local|test`). The fresh sign-up uses a WebAuthn virtual authenticator in Playwright, or the user's own browser passkey on `localhost` during the walk. Every action therefore reaches the same routes, gates and maker-checker rows a person would.

**1. Compose overlay (`<workspace>\app\infra\preview\`)**
- `compose.preview.yml` is an overlay on A23's `infra/stack/compose.yml` (`include:`, never a copy; compose project `realx`, so only one Postgres ever runs). It changes no A23 service, port, image, restart policy or environment value. Every `ADAPTER_*` stays `sandbox`, `RUN_MODE` stays `local`, `PHASE` stays `P1`, and `CHAIN_ID` stays 31337. A23's static no-live test already scans every compose file under `infra/`, so this folder is covered without any registration. This node adds its own test on the resolved configuration (`infra/preview/test/resolved-config.test.ts`, run by `verify:preview`): it runs `docker compose config` for the `preview` profile and fails on any `ADAPTER_*` value other than `sandbox`, any `RUN_MODE` other than `local`, any chain id other than 31337, any published port not bound to 127.0.0.1, or a design-folder mount that is not `:ro`. A23's `core`, `sandbox` and `otel` profiles keep running: postgres, migrate, seed (A06's `seed:design`), chain, deploy, api, worker, sandbox-panel (bank and identity pages, plus sanctions, registry, custody and kms) and mcp (A104, HTTP transport on `MCP_PORT` 4010).
- It adds three services under the profile `preview`:
  - **`web`**: `apps/web` built by a multi-stage Dockerfile in `infra/preview/web/` from the monorepo (`npm ci`, `next build` with `RUN_MODE=local`, then `next start`) on `WEB_PORT` 3000. It is healthy when `/` returns 200 and `GET /v1/meta` answers through the app's SDK factory. The image is labelled `realx.run_mode=local`, and the check refuses to start a `web` image built with any other run mode. **Build source.** A55, A59 and A60 may be building in parallel in the same repository, so in the gauntlet the `web` image (and A23's service images for the run) are built from a `git worktree` of the orchestrator's last gated commit, not from the shared working tree. The build context comes from `PREVIEW_BUILD_ROOT` (default: a gitignored worktree under `infra/preview/.build/` created by `preview:up --from-commit <sha>`, where `<sha>` defaults to the last gated commit). The commit id is recorded in `A61.json` as `buildCommit` and printed on the landing page. The preview's own tooling (this node's owned paths) runs from the working tree. A `web` image whose `realx.commit` label differs from the recorded commit fails `preview:check` with `PREVIEW_BUILD_MISMATCH`.
  - **`prototype`**: a tiny static server (`infra/preview/prototype/`, `node:24` slim) on `PROTOTYPE_PORT` 4040. It serves `<workspace>\design\` through a read-only bind mount (`:ro`) so the dc file runs with its own `support.js` exactly as the design team sees it. It also serves A50's extension file from `app/design-ext/` read-only for the undesigned states. Before every run and after every run, the SHA-256 of every file in the design folder is compared with the hashes recorded in `infra/preview/design.hashes.json`. Any difference fails the run.
  - **`preview-home`**: a small Node service on `PREVIEW_HOME_PORT` 4030. It serves one plain HTML page with the fixed banner "RealX developer sandbox, not a product screen". It uses no font, colour token or component from `packages/ui` and exists only in `RUN_MODE=local|test`. It shows links to the app (`http://localhost:3000`), the sandbox panel's bank and identity pages (`http://localhost:4020`), the MCP endpoint, the prototype, and the guide rendered as HTML. It also shows the captured email and SMS inbox from A43's `GET /v1/_sandbox/inbox` (so the user can open the verification email), the seeded personas with what each one is for, the last `preview:check` report, and the current clock (`/v1/meta`) with the KST01 close date beside it.
- Image digests for the three added images live in `infra/preview/images.lock.json` under the same rule as A23's lock file (a compose file that references a tag not in a lock file fails verify). Shared base images reuse A23's recorded digests by reference, never by copy.
- Configuration: `infra/preview/.env.example` (committed, local-only values) is copied to `.env` (gitignored) on first run. It holds only the added ports (`WEB_PORT`, `PROTOTYPE_PORT`, `PREVIEW_HOME_PORT`), the web relying-party origin `http://localhost:3000` with RP ID `localhost` (A11's `packages/config` web origin), and the paths of the read-only mounts. Nothing in this folder is a secret, and A01's secrets scanner covers it.
- **Clock.** The preview runs on A09's `DbClock` exactly as A23 configures it: the seed sets the offset so that the platform's "now" is A06's as-of date (Wednesday 23 September 2026) at boot, advancing with wall time. KST01's offer therefore stays `live` (it closes 14 Oct 2026) whatever the real date is when the user opens the preview. `preview:check` asserts that clock-now is before KST01's `closes_at` and prints both. The clock-advance control stays in the sandbox panel. The guide warns that moving past 14 Oct 2026 closes the offer, which belongs to A79's journeys, not to this walk.
- **Clock across a resume.** `DbClock` is real time plus an offset, so without care a user who comes back three weeks later would find KST01 closed and their 72-hour orders expired. The rule for the preview: platform time advances only while the stack runs, and never moves backwards. `preview-home` writes a heartbeat to `preview_state.json` every 60 seconds (last platform now, last real now), and `preview:down` writes a final one. At `preview:up` on kept volumes, the gap between the recorded real time and the current real time is taken out of the offset, so platform now resumes at the recorded platform now (never earlier than any time already shown). A09's `POST /__test/clock/advance` accepts only positive seconds, so this needs a test-controls-only "resume" operation (set the offset so that now equals a given instant, refused if that instant is earlier than the last recorded platform now). That is opened as a fix item on A09, with the matching `preview:up` hook requested from A23; it is not built here. Until it lands, a resume whose gap would carry the clock past KST01's close stops with `PREVIEW_CLOCK_PAST_CLOSE` and tells the user to run `preview:reset --yes`.
- Commands, registered under A01's script-registration convention (never a hand edit of the root `package.json`). All scripts are TypeScript run with `tsx`, work in PowerShell and Git Bash, and every file is LF.
  - `preview:up`: copy `.env` files if missing, run `stack:up`, bring up the `preview` profile with `docker compose up --wait`, then run `preview:check` and print the URLs. This is the one command. The guide also prints the equivalent plain `docker compose` line for users who prefer Docker Desktop's terminal. After the first run, the project appears in Docker Desktop's Containers view as `realx` and can be stopped and started there.
  - `preview:check`: A23's `stack:check` plus the lines for `web`, `prototype` and `preview-home`, the clock line, the design-folder hash line and the persona line (the seeded personas exist and sign in through the simulated authenticator). It exits non-zero on the first red line.
  - `preview:journeys [--seed <s>]`: Playwright and Vitest suites of §3 and §4.
  - `preview:shots`: the side-by-side captures and the app-only gallery of §5. It refuses to run (`PREVIEW_NOT_BASELINE`) unless the last command against the volumes was `preview:reset`, because the captures gate on the seeded Alex Morgan's figures (for example A$3,420.18 and his activity rows), which a walk or an agent order would change.
  - `preview:operator <step>`: the staff steps of §2.
  - `preview:window <persona>`: opens a separate headed Chromium window (a fresh temporary profile, deleted on close) on the signed-out public home, whose WebAuthn virtual authenticator holds only that persona's sandbox passkey from A06's gitignored `credentials.json`. It never signs in, sets no cookie and calls no API; the user clicks "Log in" and completes the real ceremony (D20: there is no role switcher). It refuses unless `RUN_MODE` is `local` and the URL is on 127.0.0.1. A89's `launch:window` extends it to every persona and to the console.
  - `preview:agent-token [--persona <id>]`: see §4.
  - `preview:reset`: A23's `stack:reset` plus the preview services, so the walk starts from the baseline.
  - `preview:down`: stop, keep volumes.
  - `preview:evidence`: rebuild `app/evidence/A61.json` from the last run.
  - `verify:preview`: `preview:reset`, `preview:up`, A06's `seed:verify` on the fresh baseline, then `preview:journeys` three times with three different `--seed` strings (a reset and a fresh `seed:verify` between runs), the resolved-config test, `preview:reset`, `preview:shots`, `preview:down`. It needs Docker Desktop and is what the gauntlet runs.
  - `npm run verify` stays Docker-free. It runs only this node's static checks: the import lint, the lock-file rule, the guide link check, the regions schema and the checkpoint-table schema.
- **Resume keeps the walk.** `preview:up` on kept volumes must bring the stack back with the user's walk intact. Postgres already survives: A23's `seed` service checks its seed marker, prints `SEED_PRESENT` and writes nothing. **The chain does not survive today:** A23 recreates the Hardhat chain on every boot (`realx_chain` holds nothing persistent) and re-runs `deploy`, so the walk persona's smart wallet, its `registerIdentity` claims and anything else written on-chain during the walk would be lost while Postgres keeps the walk. Two fix items are opened at Specify, not patched here: on A23 and A07, persist the chain state across a kept-volume restart (or restore it from a recorded state dump) and skip `deploy` when the recorded addresses already hold code. The preview writes a `preview_state.json` on A23's run-state volume (persona ids created by the walk, the last journey run, the feedback file path, the clock heartbeat). The landing page reads that file to show "your walk so far". After every resume, `preview:check` runs a post-resume probe: the walk persona's wallet still reads "Linked" on ONB-08 and ONB-10 (the identity registry still verifies the wallet), the deploy addresses equal the recorded ones, the walk's orders and cash are unchanged through the SDK, and A20's reconciliation for KST01 is clean. A failed probe prints `PREVIEW_RESUME_LOST_CHAIN` and escalates to A23 and A07. `preview:reset` is the only command that discards a walk, and it asks for `--yes` when a walk exists.
- **Secure context.** WebAuthn needs a secure context, and `http://web:3000` inside the Docker network is not one. So the browser journeys run from the host against `http://localhost:3000`, the same origin and RP ID the user walks. The `playwright` container of A23's `tools` profile is used only for the non-WebAuthn smoke (the public pages and the prototype). The same rule is written into the guide's troubleshooting list.
- Error and empty states of the tooling: Docker Desktop not running gives `DOCKER_NOT_RUNNING` in one line. A busy port names the port and its variable (`PORT_IN_USE`). A `web` build failure stops at a named red line with the last 50 lines of the build log. A design-folder hash mismatch gives `DESIGN_FOLDER_CHANGED` and names the file. A clock past KST01's close gives `PREVIEW_CLOCK_PAST_CLOSE`, with the offset reset explained. A `web` image built from a different commit gives `PREVIEW_BUILD_MISMATCH`. Captures asked for on a walked volume give `PREVIEW_NOT_BASELINE`. A resume that lost chain state gives `PREVIEW_RESUME_LOST_CHAIN`. `preview:check` against a stack that is not up exits within 10 seconds with `STACK_NOT_UP`. A missing A23 report gives `STACK_CHECK_MISSING`.

## Node-specific challenges (node QA)

- **Green by mocking (quality, money).** The journeys pass because a Playwright route handler, an MSW worker or a `__test` shortcut fakes the quote, the deposit credit or the order state, or because `checkpoints.ts` reads the figures from the page it is checking. The node QA's import and network scan must find only real calls to `web`, `api`, `mcp` and the sandbox panel. The checkpoint figures must be re-derived from SDK reads and match its independent table to the cent, including A$23,959.20, A$2,395.92, A$2,604.08, the move from 6,400 to 6,500 units and escrow Δ 0.
- **The deposit that credits itself (money, G14 through G11).** A deposit of A$23,959.20 is credited without the manual match because the helper runs TRSY and CFO as one persona, the panel's receive form bypasses A17's threshold, or the payer name "Alex Morgan" is matched against the seeded `INV-00841` instead of the walk persona. The order must stay `awaiting_funds` until two different humans act. A `SIM-MISMATCH` deposit must never be credited. The PayID must route only to the walk persona's account.
- **Tipping-off in the preview (compliance, G02).** The ` SANCTION` persona's screens differ from the ` REFER` persona's in a word, a pill tone, a timing, a missing notification, or the landing page's "your walk so far" panel showing a different state. Any difference on any surface the user or the persona can see fails, and the landing page must show both as "reviewing".
- **Skip the queue in the browser (compliance, G01, G04).** With a ` REFER` persona, and separately with a certificate under review, the node QA types `/portfolio`, `/invest/KST01/buy` and `/invest/orders/<id>`, uses Back after an earlier visit, fetches the RSC payload directly, and looks for any role switcher or sign-in shortcut (`?dev=1`, `?as=`, a stored `role` or `persona` value). - **Agent does more than its person, or less (D04, G22).** Through MCP the agent orders 25 units (above the per-action cap), 16 units (over the daily cap), ANN01, replays an idempotency key, and acts after revocation; through MCP and REST it attempts sign-up, identity verification, token creation, wallet creation and the bank-account change. The results must be `428 CONFIRMATION_REQUIRED` naming the per-action cap, `G22_LIMIT_EXCEEDED` (daily), `G22_VEHICLE_NOT_ALLOWED`, the first result on replay, `TOKEN_REVOKED`, `MCP_UNKNOWN_TOOL` through MCP and `AGNT_NOT_ALLOWED` through REST, each with no order row. The agent's 10-unit order, from the same starting state as the passkey order, must match its gate verdicts and reason codes (G12's evidence source, actor, `on_behalf_of`, channel and the G22 row aside). A false "parity break" caused by a missing signing key or standing consent is a finding against this node, not against A12. A difference in verdicts, or an agent order without `on_behalf_of` in A10's chain, fails. A CFO agent token deciding the manual-match approval must be refused `G22_AGENT_NEVER_CHECKER` with no decision row.
- **Design fidelity by excuse (design).** A region fails computed-style checks but the pixel difference is waved through with a vague note, or the app side is captured with the coral product-map look, a fallback font (Newsreader not loaded in the container) or the dev role bar unmasked on one side only. Every pixel-difference justification must cite a specific design-analysis item, a named item in A54's or A57's composition notes or a design-bug number; "A50 drawing" is refused for states A50 does not draw. At 375 px, a region that fails a layout metric is recorded, never excused as a token or text failure. The fonts must be the design's on both sides, and the role bar must be masked on both.
- **The design folder is touched (governance).** The `prototype` service mounts the folder read-write, the driver's clicks cause the dc runtime to write a file, or a helper copies `support.js` into the design folder. The before and after hashes must be identical on every run, and the mount must be `:ro` in the resolved `docker compose config`.
- **The real date leaks in (determinism).** With the host clock set to 1 Nov 2026, the preview shows KST01 as closed, the order is refused `ORD_OFFERING_NOT_LIVE`, or the ONB-06 certificate date check uses the host date. The clock line must show the seed's as-of time plus elapsed time, and every date on screen must come from A09's clock.
- **Resume wipes the walk (usability).** After the user's walk, restarting Docker Desktop and running `preview:up` re-seeds and loses the walk persona and the order, leaves the stack half up because `seed` failed on a walked volume, recreates the chain so the wallet is no longer "Linked", or, after weeks away, closes KST01 and expires the walk's orders because real time kept running. The walk must survive with `SEED_PRESENT`, the same chain state and a platform clock that resumes where it stopped. Only `preview:reset --yes` may discard it.
- **Secrets on the landing page (security).** The landing page or the helper prints the agent token after first display, the walk persona's full TFN or licence number, a passkey credential id, or kms material, or the captured inbox shows another persona's messages. A scan must find none of them. The inbox must show only messages addressed to the personas of the current walk and the seeded personas the guide names.
