# A21 - Licences, feature flags and licence perimeter (G21)

**The register of who is licensed to do what, and the switchboard that only lets a feature run while a licence covers it: AFSL, RE authorisation, relief and platform licence records plus the CAR register, with authorisations, conditions and expiry alerts at T-90/30/7; feature flags bound to a licence record and auto-reverted the moment the binding lapses; toggles as 4E (SUPER to CCO) that are refused without a binding, both when submitted and again when executed; the DAF Act low-value exemption meter (A$10m trailing 12 months, A$5k per client, Sev2 at 80 percent) with TCP/DAP status; the launch state with resale, retail and stablecoins off; a configurable listing visibility mode; and the single G21 evaluator that every offering, order, listing, venue and public page asks before it shows or does anything.**

**Build status:** not started. **Milestone:** AM1 (Money, register, approvals and agent-access core). **Lane:** Compliance core. **Planner:** Opus 5.5 (high). **Builder:** Grok 4.7 (xhigh). **Node QA:** Opus 5.5 (high, every loop). **Graph QA:** Fable 5.1 (high, at milestone close).
**Estimate:** 8-14 agent-hours (build, challenge and verify loops): two local lifecycles, about 30 endpoints, three jobs, two large property tests, the full permission matrix and the A14 and A13 wiring plus the `evaluateG21` export for A19.

**Depends on:** [[A14 - Approvals engine and maker-checker (SM-00)]], [[A08 - Sandbox adapter framework, config and phase flags]], [[A13 - Alerts and SLA-clocks service]]
**Unlocks:** [[A23 - Whole-stack Docker boot (AM1 exit)]], [[A36 - Offerings- offer terms, listing review, raise monitor (SM-04)]], [[A45 - Reporting, regulatory calendar, filings and metric governance]], [[A48 - Halts, kill switches and wind-down]], [[A69 - Console- sponsor admission, licences, sponsors and guardrails, feature flags, entities register]], [[A91 - P2- resale board market module (SM-09)]]
**Graph direction (settled 24 Sep 2026).** The graph keeps A21 → [[A19 - Rules engine- gates G01-G22, rule packs, threshold monitors, simulator]]: A19 depends on this node and calls A21's exported `evaluateG21`, whose signature A19 freezes. The edge A19 → A21 that this note first asked for was declined, because it would close a cycle (graph note, declined list). So A21 does not register into A19's evaluator registry: it exports `evaluateG21` from its `index.ts`, and A19 wires it into its registry as the one G21 path. The `daf.*` keys are read from A08's config (`packages/config`), and when A19 calls the evaluator it may pass the rule-pack values in as arguments; A21 never imports A19. A21 never ships a second G21 path. The edge A21 → [[A33 - Sponsor tenancy, entities, licences of sponsors and admission pipeline]] (A33's `tenant.create` effector calls `initTenantFlags`) is in the graph.

**Oracle rule:** not an oracle node (`oracle: no`): no money, supply or holdings move here, although what this node switches on decides whether they may move elsewhere. The node QA still writes hidden tests from this frozen spec to `<workspace>\gauntlet\hidden\A21\` **before the build starts** ([[App Gauntlet]] §2): the binding and toggle matrix, the stale-approval and effector re-check vectors, the auto-revert timing vectors, the expiry-instant and T-90/30/7 vectors, the kill-switch bypass probes, and an independent reference implementation of the exemption meter and of `evaluateG21` over a snapshot. The builder never reads that folder, and the tests are published into `app/` only after the gate passes, so that A36, A37, A48, A69 and A91 can re-run them as regression.

This note is not legal advice. Which activities need which authorisation, whether RealX needs a TCP or DAP licence or relies on the DAF Act low-value exemption, the exemption's thresholds, window, per-client measure and what it counts, the expiry instant of a licence, and the wording of the public CAR disclosure are counsel questions (HG-LEGAL). Every such fact is a row of data with a default and a `set_with_counsel` marker; counsel's answers change rows, not code. The seed uses the design's sample licensee ("Example Licensee Pty Ltd, AFSL 000 000") and nothing real.

## Build brief

**Scope and placement**

- Module `perimeter` in the API (`services/api/src/modules/perimeter/`) following the A09 module pattern: a public `index.ts` (the only import other modules may use, enforced by the boundary lint), zod schemas that feed the OpenAPI document from the first commit, Drizzle schema and migration in the module's own folder registered with A04's per-module registry, and job definitions exported from the module and registered with the worker through A09's job registration (this node owns no worker folder; the worker only imports the module's `jobs` export). The only source of time is the injectable clock from A09; `Date.now()` and argument-less `new Date()` are forbidden in the owned path and `npm run verify` greps for them.
- Everything here is the data behind surfaces owned by other nodes: ADM-04 Licences and permissions and ADM-34 Feature flags and kill switches ([[A69 - Console- sponsor admission, licences, sponsors and guardrails, feature flags, entities register]]), the kill-switch banner and actions ([[A48 - Halts, kill switches and wind-down]]), the public footer disclosure ([[A52 - Web app shells, routing and passkey sign-in (public, investor, sponsor)]]) and the "Wholesale · P1" pill, hero eyebrow and "Wholesale investors only" aside ([[A54 - Public site- home, investments, property page, sponsor profile, fees]]). This node fixes the record shapes, column names and reason codes so those nodes render without translation.

**Tables and ownership (one table, one vocabulary)**

- A21 creates neither `licence` nor `feature_flag`. A04 creates both as core tables and names A21 as their shaper; A21 adds its columns through a migration in its own folder registered with A04's registry (`registerModuleSchema({ node: 'A21', migrationsDir })`, column additions and CHECKs only on those two core tables). If A04's registry refuses column additions on a core table, the column lists below are applied as an A04 data change at Specify (A04.1), not as a second table.
- Columns A21 adds or constrains on `licence`: `kind` (the union of both nodes' lists: A21's `afsl`, `re_authorisation`, `market_licence`, `custody_authorisation`, `asic_relief`, `trustee_appointment`, `other`, and A33's `sponsor_afsl`, `trustee_licence`, `authorised_rep`), `number`, `issuer` (`ASIC`, `AUSTRAC`, `licensee`, `court`, `other`), `authorisations[]` (activity codes from the vocabulary below), `conditions` (each with `code`, `text`, `expires_on?`, `evidence_doc_ids[]`), `granted_on`, `expires_on?`, `review_on?`, `state` (the lifecycle, owned by A21: `draft`, `active`, `suspended`, `expired`, `revoked`), `verification_state` (owned by A33, written only by A33: `declared`, `verified`, `unverified`; null on platform rows), `jurisdiction` (data column, `AU`, CHECK `= 'AU'` in this build), `evidence_doc_ids[]` (A08 storage objects), `snapshot_version`, `approval_id`, `set_with_counsel`. Every change to an active row is versioned in A21's own `licence_version` table (`as_of`, `sha256` of the canonical row) so a G21 evaluation can name the licence version it used.
- Columns A21 adds or constrains on `feature_flag`: `key` (a key of A08's flag table; unknown keys refused at insert), `phase`, `kind` (`phase`, `kill-switch`, `licence-bound`, copied from A08), `scope` (`platform`, `tenant:<id>`, `vehicle:<id>`), `state` (`on`, `off`), `effective_from`, `auto_reverted_at?`, `auto_revert_reason?`, `version`. A21's `licence_binding_id` is A04's existing `licence_bound_to` column (a reference to a `flag_binding` row, not a new column); A21's `changed_by_approval_id` is A04's `approval_id` column. A21 sets A04's `requires_licence` to exactly `kind = 'licence-bound'` with a CHECK, so A04's existing CHECK (`NOT (state = 'on' AND requires_licence AND licence_bound_to IS NULL)`) bites on licence-bound flags only; `agents.traffic`, the other kill switches and phase-kind flags such as `wallets.external` switch without a licence, as A04's plant test expects.
- Tables wholly A21's, registered through A04's registry: `licence_version`, `car_appointment`, `flag_binding`, `flag_change` (insert-only history of every flag write with `approval_id UNIQUE`), `exemption_event`, `perimeter_setting`, `perimeter_parameter` (the `set_with_counsel` rows below) and `perimeter_state` (one row, `version` bigint bumped in the same transaction as every licence, CAR, binding, flag and setting write).
- Ownership of rows in the shared `licence` table: A21 seeds and writes platform rows (the licensee's AFSL, the hired RE's authorisation, relief and market records). A33 inserts sponsor-held rows (kinds `sponsor_afsl`, `trustee_licence`, `authorised_rep`) and owns their `verification_state`; A33 inserts them with lifecycle `state = active` (the licence exists in the world; whether RealX has verified it is `verification_state`). A21 owns every lifecycle transition of every row after insert, including sponsor rows (expiry, suspension, reinstatement, revocation), because it reads the shared table directly, not through A33's module. A21 seeds no sponsor row and asserts no sponsor design fact; those assertions ("Own AFSL", "Trustee: hired RE") belong to A33's seed and contract tests and to A69's screen tests. A33 keeps its listing pause on sponsor licence expiry but reacts to A21's `state = expired` rather than running a second expiry transition, so there is one expiry sweep and one Sev2 per lapse (an A33 change, flagged).

**Licence and CAR register (module M02 half)**

- `licence` row id `LIC-<6 base32>`; `holder_entity_id` is an `Entity` from A04 (RealX, a licensee, a sponsor, a trustee, the hired RE, a custodian).
- `car_appointment` row (the only model of a CAR; there is no `car_appointment` licence kind): `id` (`CAR-<6 base32>`), `representative_entity_id`, `licensee_licence_id` (must be an active `afsl`), `appointment_number`, `authorisations[]` (a subset of the licensee's authorisations; a superset is refused with 422 `G21_CAR_EXCEEDS_LICENSEE`), `effective_from`, `effective_to?`, `state` (`active`, `ended`), `evidence_doc_ids[]`, `approval_id`. The CAR register is the list of these rows; the design's footer sentence is generated from the active one whose representative is the platform entity.
- Activity vocabulary (`activities.ts`, data, extendable only by a data change and a seed test): `arrange_wholesale_units` (RealX as CAR, P1), `issue_wholesale_units` (a sponsor trustee under its own AFSL, or a hired RE, P1), `deal_retail_units` (P2), `operate_registered_scheme` (the RE, P2), `issue_pds` (P2), `operate_market` (venue mode, P2/P3), `hold_client_money`, `custody_of_assets`, `provide_general_advice`, `digital_asset_platform` (DAF Act DAP) and `tokenised_custody_platform` (DAF Act TCP), each of the two DAF activities with a `daf_status` (`licence`, `low_value_exemption`, `not_required`) that is a `set_with_counsel` row defaulting to `low_value_exemption` so the stricter behaviour is what the build tests, and `stablecoin_payments` (P3). Each activity carries its phase and the flag keys it can bind.
- Activity to flag map (`activity_flag_map`, seeded, readable at `GET /v1/perimeter/activities`): `arrange_wholesale_units` -> `offers.wholesale`; `deal_retail_units` + `issue_pds` + `operate_registered_scheme` -> `offers.retail`; `operate_market` -> `resale.board`; `operate_registered_scheme` -> `governance.votes`; `stablecoin_payments` -> `payouts.stablecoin`. A flag may bind only to a licence that holds every activity the map requires for it. The set of licence-bound keys is read from A08's flag table by `kind`; a licence-bound key with no map entry fails the seed test, so a new A08 key cannot be forgotten here.
- Sponsor licence rows are tenant-scoped through row-level security: SP-OWN reads its own rows and may upload a renewal document (which creates a `draft` version for CCO review); only CCO and LEGL move a licence between lifecycle states. `GET /v1/licences/summary?entity=` is the read model of an entity's rows (lifecycle state and verification state side by side, each with its own `display_tone`).
- Expiry instant: a licence, condition or CAR appointment with `expires_on` (or `effective_to`) of day D stops being in force at **00:00 `Australia/Sydney` at the start of D**, so the named day is not covered (the fail-closed reading; `expiry_instant_rule` is a `set_with_counsel` row with this default). Every reader (`isEnabled` through A21's source, `evaluateG21`, `binding_sweep`, `/perimeter/public`) treats `clock >= expiry instant` as expired whatever the stored `state` says, and the first reader or sweep to see it performs the stored transition.
- Lifecycle transitions (exhaustively tested; any other pair returns 409 `LIC_TRANSITION_NOT_ALLOWED` with the current state):

| From | To | Trigger | Action code and policy |
|---|---|---|---|
| `draft` | `active` | approval | `licence.activate`, 4E, CCO → LEGL |
| `active` | `active` (new version) | condition added or changed | `licence.condition_change`, 4E, CCO → LEGL |
| `active` | `suspended` | protective act | `licence.suspend`, SGL+R protective: CCO or LEGL acts, the other ratifies within 2 hours |
| `suspended` | `active` | approval | `licence.reinstate`, 4E, CCO → LEGL |
| `active` | `expired` | system, clock at the expiry instant | none (system) |
| `suspended` | `expired` | system, clock at the expiry instant | none (system) |
| `active` or `suspended` | `revoked` | approval, irreversible | `licence.revoke`, 4E, CCO → LEGL |

- CAR transitions: record (`car.record`, 4E, CCO → LEGL) and end (`car.end`, 4E, CCO → LEGL). Ending a CAR is the record of a legal event, not an emergency stop; the urgent path is `licence.suspend` (SGL+R) or A48's kill switches. An `active` appointment whose `effective_to` instant passes ends by system under the clock.
- Expiry alerts: a job `perimeter.expiry_sweep` (daily 06:00 `Australia/Sydney`, and on every licence or CAR write) opens A13 clocks so that `licence.expiry` (Sev3, CCO + LEGL, target ADM-04) is emitted exactly once at T-90, T-30 and T-7 days before the expiry instant of every row in the shared `licence` table (platform and sponsor rows alike), of every CAR appointment and of every condition, with dedup keys `licence:<id>:T90|T30|T7` so re-running the sweep never duplicates. Editing `expires_on` to a later date cancels the pending clocks and re-arms at the new dates. Conditions with their own `expires_on` alert the same way and, on expiry, lapse only the flags whose binding names that condition.

**Feature flags bound to licences (module M27 half)**

- This node ships the database-backed `OverrideSource` that A08's `isEnabled(key, ctx)` consults. For keys of kind `licence-bound` and `phase` it always answers (it never returns "no answer", so A08's static default, which is `on` for `offers.wholesale`, is never reached): a missing platform row is `off`; the answer is `on` only when the effective state is `on` and, for `licence-bound`, a `valid` binding exists whose licence is `active` and before its expiry instant at the current clock (and, for `offers.wholesale`, whose CAR appointment is in force). Kill-switch keys are answered from their row, falling back to A08's default.
- Scope resolution: the effective state of a key for `{tenantId?, vehicleId?}` is the AND of the platform row, the tenant row and the vehicle row, so narrower scopes can only restrict; a missing tenant or vehicle row is neutral, a missing platform row is `off`. A tenant or vehicle row may be `on` only with a valid platform binding **and** a binding to that tenant's issuing licence (a sponsor row with `state = active` and `verification_state = verified`, or the hired RE's `re_authorisation`). Jurisdiction is the `AU` data column, not a scope. The scope matrix (platform × tenant × vehicle row present or absent, on or off, binding valid or lapsed) is part of the generated binding test.
- Tenant flags at admission (J11 step 5): `initTenantFlags({tenantId, issuingLicenceId, approvalId})` in `index.ts`, called by A33's `tenant.create` effector under the `tenant.create` approval id (needs graph edge (2)); it writes a tenant-scope `offers.wholesale` row `on`, bound to the tenant's issuing licence, and a tenant-scope `off` row for every other licence-bound key. It refuses (and writes nothing) when the issuing licence does not meet the rule above or the approval id is not an `approved` `tenant.create` request for that tenant.
- Env overrides: `evaluateG21`, the A14 perimeter guard, the effectors and `/perimeter/public` read the database state through `perimeterFlagState()` and ignore `FLAG_<KEY>` in every run mode. For `isEnabled` itself, A08's resolution order puts the env override first; this spec needs A08 to restrict it (A08.1, flagged): for kinds `licence-bound` and `phase` an override may only force `off`, except in `RUN_MODE=test`, where it may force `on` for consumer unit tests and is written to the start-up log.
- Caching: reads of licence-bound and phase flags compare the cached entry's `perimeter_state.version` with the live row on every call (one indexed read) and reload on mismatch, and never serve an entry past the earliest expiry instant it depends on; every process (API and worker) also listens on Postgres `LISTEN perimeter_changed`, which every write, including the worker's auto-revert, notifies in the same transaction. Kill-switch reads use the same mechanism. There is no time-based cache on a licence-bound flag, so a lapse reaches every module on the next read.
- `flag_binding` row: `id`, `flag_key`, `scope`, `licence_id`, `licence_version`, `car_appointment_id?` (required for `offers.wholesale`: its binding names the licensee's AFSL version plus the CAR appointment id), `activities[]` (the map's required set, checked at bind time), `condition_codes[]?` (conditions the binding depends on), `bound_by_approval_id`, `state` (`valid`, `lapsed`), `lapsed_at?`, `lapse_reason?` (`expired`, `suspended`, `revoked`, `authorisation_removed`, `condition_expired`, `car_ended`). Mapping a licence to a flag is action code `licence.map_flag` (SUPER → CCO, 4E) through A14; a binding to a licence that lacks a required activity, is not `active`, or whose expiry instant is before the flag's `effective_from` is refused at precheck with `G21_BINDING_NOT_COVERED` naming the missing activity.
- Turning a `licence-bound` or `phase` flag **on** is action code `flag.toggle` (SUPER → CCO, 4E) through A14. The precheck hook this node registers with A14 refuses with `FLAG_KILL_SWITCH_OWNED_BY_A48` for any kill-switch key, with `G21_NO_BINDING` when a licence-bound key has no `valid` binding for that scope, with `G21_PHASE_NOT_REACHED` when the flag's phase is later than `PHASE` (A08's guard, re-checked here so the database source cannot bypass it), and with `G21_ACTIVITY_MISMATCH` when the binding's activities no longer cover the map. Turning a flag **off** needs the same 4E but no binding.
- Effector re-check (stale approvals): approvals live up to 72 hours, so the `flag.toggle` and `licence.map_flag` effectors re-check, in the same database transaction as the write: the binding is `valid`, its licence is `active` and before its expiry instant, its CAR appointment (if named) is in force, its activities still cover the map, `PHASE` has been reached, the key is not a kill switch, and the approval is `approved` with `action_code` and canonical payload naming the same key, scope and target state. Any failure refuses with the matching `G21_*` or `G13_APPROVAL_MISMATCH` code and writes nothing; A14 records the effector failure under its effector contract. Every flag write inserts a `flag_change` row whose `approval_id` is UNIQUE, so one approval id can change a flag once. When a binding lapses, `binding_sweep` asks A14 to cancel every pending `flag.toggle` request whose payload depends on it (system actor, reason `G21_BINDING_LAPSED`); the effector re-check is the guarantee whether or not the cancel lands first.
- Kill switches (every key of `kind: kill-switch` in A08's table, read by kind, today `platform.inflow_freeze`, `platform.marketplace_suspend` and `agents.traffic`) are exempt from licence binding because they only restrict. They are set and lifted only by [[A48 - Halts, kill switches and wind-down]] through `setFlag({key, scope, state, approvalId})`. `setFlag` refuses (with `G13_APPROVAL_REQUIRED` for a missing id, `G13_APPROVAL_MISMATCH` otherwise) unless every check holds: the approval's `action_code` is an A48 kill-switch code registered for that key (the engage code for the key, or `kill_switch.release`); the canonical payload names the same key, `scope = platform` and the same target state; the approval id has never been used on a flag write (`flag_change.approval_id` UNIQUE, so replaying an old release after a new engage fails); and the request is in exactly the A14 states in which effectors run: `approved` with `ratification_state` `pending` or `ratified` for an `SGL+R` engage, `approved` for a `4E` release (A14 has no state called `acted_pending_ratification`; A48's text uses that name and must be aligned, flagged). This node never toggles a kill switch on its own and never decides ratification. `flag.toggle` never touches a kill-switch key.
- Auto-revert: `perimeter.binding_sweep` runs every minute under the clock and also synchronously inside every licence state change, CAR end, authorisation removal and condition expiry. For each binding whose licence is no longer `active` or is past its expiry instant, whose CAR appointment has ended or passed `effective_to`, whose authorisations no longer cover the map, or whose named condition has expired, it performs any stored expiry transition due, marks the binding `lapsed` with the reason, sets every flag that depended on it to `off` with `auto_reverted_at` and `auto_revert_reason`, bumps `perimeter_state.version`, writes audit `flag.auto_reverted` per flag, and emits `licence.expiry` through A13 with `severity: 2` and payload sub-code `binding_lapsed` (owner CCO, target ADM-34), so the lapse is a Sev2 and there is exactly one per flag. Reverting is not an approval and needs none. Re-enabling later needs a new binding and a new 4E toggle; the old binding is never revived.
- Launch state (`launch-state.ts`, derived from A08's flag table, not a literal list): every licence-bound key is `off` and unbound except `offers.wholesale`, which is `on` and bound to the platform's active CAR appointment under the sample licensee's AFSL; every phase-kind key (today `wallets.external`) is `off`; every kill switch is at A08's default (today `platform.inflow_freeze` and `platform.marketplace_suspend` off, `agents.traffic` on). `GET /v1/flags/launch-state` returns the expected set and the live set with a pass or fail per key for A69's launch-state card. Keys with `phase: P2` or `P3` refuse before `PHASE` reaches them even with a binding; a test proves each unbound licence-bound key's toggle is refused with `G21_NO_BINDING`.
- Listing visibility mode: platform setting `listing.visibility` with values `public` (visitors see PUB-03 and PUB-04 with the wholesale-only copy, the design's behaviour and the default), `signed_in` (offers and prices need a session), `verified_wholesale` (offers and prices need an active wholesale classification, G04). Changing it is action code `perimeter.visibility` (CCO → LEGL, 4E). A tenant may set a stricter mode for its own vehicles through `perimeter.visibility.tenant` (SP-OWN → CCO, 4E) and never a looser one (422 `G21_VISIBILITY_LOOSER_THAN_PLATFORM`). A36's offering reads apply the mode in-process through `evaluateG21`; A54 reads `GET /v1/perimeter/settings` only to choose its empty state.
- Maker-checker policy rows: `licence.activate`, `licence.condition_change`, `licence.reinstate`, `licence.revoke`, `car.record`, `car.end`, `licence.map_flag`, `flag.toggle`, `perimeter.visibility` (4E as stated above), `perimeter.visibility.tenant` (4E, SP-OWN → CCO) and `licence.suspend` (SGL+R, `protective = true`, `system_trigger_allowed = false`, not reversible) are data files proposed to `packages/domain` (A03's `actions.ts`) and to A14's `approval_policies` seed in AM1 and applied by the domain node's owner in the same milestone, as A33 does for its codes; the product map's three perimeter rows are among them unchanged. If a row is missing at Specify, the Specify step stops.

**G21 evaluator (the single authority)**

- A21 holds the only G21 implementation. It exports `evaluateG21` from its `index.ts`; A19, which depends on this node, wires it in as the only G21 evaluator through its `g21.ts` adapter (A19 line 202), so A21 never calls A19. A21 registers its guard with A14's `registerPerimeterGuard` so approval prechecks get the same verdict. A19's `LICENCE_PERIMETER` reason becomes an umbrella that always carries A21's specific `G21_*` codes inside it, and A19's own DAF meter monitor is dropped in favour of this node's meter (A19 changes, flagged). The test that A19's G21 result for an action equals A21's for the same snapshot runs at A19's gate.
- `evaluateG21({activity, actorEntityId?, tenantId?, vehicleId?, regime?, basis?, amountCents?, clientId?, viewer?: {kind: visitor|investor|sponsor|partner|staff, hasSession, wholesaleActive?}})` in the module's public interface and at `POST /v1/perimeter/evaluate`. The caller supplies `wholesaleActive` from its own G04 result (A36 at listing reads, A37 at order placement, A54 through A36's reads); an absent value under `verified_wholesale` is treated as not wholesale. The function is pure over a licence snapshot (all licences, CAR appointments, bindings, settings and meter totals as of the clock, with expiry instants applied) and returns `{result: pass|fail, reason_codes[], licence_version_ids[], flag_states, exemption: {basis, daf_status, used_bp, used_pct, client_remaining_cents?}}`; the calling wrapper writes one G21 `GateEvaluation` row (inputs hash, result, reason codes, snapshot version) in the shared table A04 created.
- Reasons: `G21_NO_LICENCE` (no active licence holds the activity), `G21_CAR_ENDED`, `G21_LICENCE_SUSPENDED`, `G21_LICENCE_EXPIRED`, `G21_LICENCE_UNVERIFIED` (a sponsor row not `verified`), `G21_CONDITION_BREACHED`, `G21_FLAG_OFF` (the activity's flag is off in the effective scope), `G21_PHASE_NOT_REACHED`, `G21_EXEMPTION_EXHAUSTED`, `G21_CLIENT_CAP_EXCEEDED`, `G21_VISIBILITY_HIDDEN`, `G21_MARKETPLACE_SUSPENDED`. Fail-closed: an empty register, a missing snapshot or an unknown activity code is `fail` with `G21_NO_LICENCE`, never `pass`.
- Caps, one rule for both: with `amountCents`, the check passes when `used + amount <= cap`; with no amount, it fails when `used >= cap`. This applies to the platform cap (`G21_EXEMPTION_EXHAUSTED`) and to the per-client cap (`G21_CLIENT_CAP_EXCEEDED`, which returns `client_remaining_cents = max(0, client_cap - client_used)`).
- Who asks: [[A36 - Offerings- offer terms, listing review, raise monitor (SM-04)]] at listing review, go-live and every public offering read (the vehicle's trustee or RE must hold `issue_wholesale_units` or the retail set, and RealX must hold `arrange_wholesale_units` through a live CAR; visibility with the viewer); [[A37 - Orders, escrow, allocation and refunds (SM-05)]] at order placement (`digital_asset_platform` with `amountCents` and `clientId`) and through `recordExemptionEvent` at allocation and refund; [[A91 - P2- resale board market module (SM-09)]] before listing an instrument, on every venue-mode change (`operate_market` and `resale.board` on) and on every resale trade once `resale_trade` is a counted kind; [[A69 - Console- sponsor admission, licences, sponsors and guardrails, feature flags, entities register]] shows the admission `GateEvaluation` A33 wrote; [[A45 - Reporting, regulatory calendar, filings and metric governance]] for the licensee and CAR obligation calendar (7/30/90-day reporting rows are A45's; this node supplies the licence and appointment dates they hang off). **DAF Act low-value exemption meter and TCP/DAP status**

- Commencement: the DAF Act checks apply from `daf.commencement` (2027-04-08; the key is read from A08's config, and A19's adapter passes the rule-pack value in as an argument when it calls the evaluator). Before it, `digital_asset_platform` and `tokenised_custody_platform` evaluate `pass` with warning `G21_DAF_NOT_COMMENCED` and the meter is informational. From it, the meter blocks when the activity's `daf_status` is `low_value_exemption`; with `licence` it needs an active licence row holding the activity and the meter is informational; with `not_required` it passes and shows on ADM-04 as such. One meter serves both DAF activities.
- Thresholds are rule-pack keys that A19 owns: `daf.low_value_annual_cents` (A$10,000,000), `daf.low_value_per_client_cents` (A$5,000). A21 never imports A19: `evaluateG21` takes them as arguments, which A19's adapter fills from the pack, and A21's own jobs and tests read the same defaults from A08's config. This node's own `perimeter_parameter` rows, each `set_with_counsel`: `daf.window_days` 365 (trailing window ending at the evaluation instant), `daf.client_window_days` 365, `daf.client_cap_measure` `entries_net_of_reversals`, `daf.counted_kinds` (`entry`; `resale_trade` added from P2 because the product map's meter counts "transactions"), `daf.warn_pct` 80. The DAF block is not downgraded by A19's generic `COUNSEL_PENDING_*` rule: the stricter reading is deliberate until counsel answers (a divergence A19 must record, flagged).
- `exemption_event` row: `client_id` (investor), `tenant_id`, `vehicle_id`, `kind` (`entry`, `resale_trade`, `reversal`), `amount_cents` (integer), `occurred_at`, `source_ref` (order, trade or refund id), `idempotency_key`. Other modules record through `recordExemptionEvent()` in the public interface. Reversals (refunds, failed offers) subtract; nothing is ever deleted.
- Precision: `used_bp = floor(used_cents * 10000 / cap_cents)` as an integer; `used_pct = used_bp / 100` is for display only. Threshold comparisons use integer cents (`used_cents * 100 >= cap_cents * warn_pct` for the warning; the cap rule above for the block). `GET /v1/perimeter/exemption-meter` returns `{window_start, window_end, used_cents, cap_cents, used_bp, used_pct, warn_pct, clients_at_cap, basis, daf_status, commencement}` and the per-client remainder on `?client=`. The meter is recomputed on every event and by `perimeter.meter_sweep` nightly (which also rolls entries out of the window); both paths must agree to the cent.
- Alert rule (A13's dedup behaviour, one rule everywhere): crossing 80 percent emits `licence.daf_exemption_meter` (Sev2, CCO, ADM-04) with dedup key `meter:platform:80`. A re-cross while that alert is open re-emits under the same key, which A13 turns into `occurrences + 1` and no new alert. A21 never resolves the alert; after a human resolves it, the next crossing raises a new alert. At 100 percent the cap rule blocks with `G21_EXEMPTION_EXHAUSTED`; a client entry past A$5,000 fails with `G21_CLIENT_CAP_EXCEEDED` and the remaining amount, so the orders node can show "you may invest up to A$X under the current arrangement". The ExemptionMeter on ADM-04 (a RaiseBar with the 80 percent marker) is a direct read of this endpoint.

## Node-specific challenges (node QA)

- **A flag that stays on after its licence dies.** The sample licensee AFSL is suspended by CCO under SGL+R at 10:00; `offers.wholesale` must read `off` with `auto_revert_reason: suspended` on the next `isEnabled` call in the API process although the revert ran in the worker, `/perimeter/public` must report `car_active: false` and an empty disclosure on its next request, a Sev2 `licence.expiry` with sub-code `binding_lapsed` must exist once, and a listing go-live request in A36 evaluated at 10:01 must fail with `G21_LICENCE_SUSPENDED`. The same with the CAR appointment ended, an authorisation removed from the licence, a named condition expiring, and a licence whose expiry instant passes at 00:00 with no sweep run since. An implementation that waits for the minute sweep, relies on a per-process cache, or leaves the flag on because the stored state (not the clock) was checked fails.
- **A binding that pretends.** SUPER binds `offers.retail` to the sample AFSL, which holds `arrange_wholesale_units` only: refused with `G21_BINDING_NOT_COVERED` naming `deal_retail_units`; then a CAR appointment is created whose authorisations exceed its licensee's: refused with `G21_CAR_EXCEEDS_LICENSEE`; then a P2 binding that is valid in every respect is toggled on with `PHASE=P1`: refused with `G21_PHASE_NOT_REACHED`. Any of the three accepted fails the node.
- **The stale approval.** SUPER binds and submits `flag.toggle` for `offers.wholesale` to `on`; the licence is then suspended (or expires, or loses the activity) before the CCO approves; the CCO approves within the 72-hour TTL: the flag stays `off`, the effector refuses with the matching `G21_*` code, and no `flag_change` row exists. The same for `licence.map_flag` approved after the licence is revoked.
- **The toggle without the checker.** The SUPER's agent token drafts and submits `flag.toggle` for `offers.wholesale` (allowed, as maker), then the same token, the SUPER, and a CCO who is the SUPER's delegate each try to decide: all refused by A14, and this node's effector must never run; then an `approved` request for a different key is replayed against the `offers.wholesale` effector: refused with `G13_APPROVAL_MISMATCH`.
- **Four doors to the kill switch.** (a) SUPER opens `flag.toggle` for `agents.traffic` to `on`: refused with `FLAG_KILL_SWITCH_OWNED_BY_A48` at precheck and at the effector. (b) `agents.traffic` is released (4E), engaged again (SGL+R), and the old release approval id is replayed through `setFlag`: refused, because the id is already in `flag_change`. (c) `setFlag` is called with an `SGL+R` engage approval that is `approved` with `ratification_state = pending`: accepted; with the same request after it is `rejected`, `expired` or `cancelled`: refused. (d) A CCO's token drafts `kill_switch.release` for `agents.traffic`, a human SECO submits and the other human approves: the effector's `setFlag` is refused with `self_subject` because the maker principal is a token; a CCO token calling directly is refused the same way; the CCO with a passkey as maker and A48's code succeeds.
- **Meter arithmetic at the edges.** With a clock at 12:00 on 12 April 2027 (AEST, after the DST end and after `daf.commencement`), entries of A$9,999,999.99 spread over the last 365 days plus one A$0.02 entry dated 366 days ago: the meter must read `used_bp = 9999` (99.99 percent) with the old entry rolled out; a further A$0.01 entry passes because it reaches exactly the cap, and the meter then reads `used_bp = 10000`; after it, an evaluation with no amount and one with any positive amount both fail with `G21_EXEMPTION_EXHAUSTED`; a reversal of A$5.00 reopens it for up to A$5.00; one client with A$4,999.99 may enter A$0.01 and not A$0.02 (`G21_CLIENT_CAP_EXCEEDED` with `client_remaining_cents: 1`), and the same client after a A$100.00 reversal may enter A$100.01. The 80 percent alert: the meter crosses 80 percent, falls below on a reversal and crosses again while the alert is open: exactly one alert with `occurrences: 2`; the alert is resolved by a human and the meter falls and crosses again: a second, distinct alert. The same entries dated before 8 April 2027 yield `pass` with `G21_DAF_NOT_COMMENCED`. Floating-point sums, a window measured in calendar months, or a per-client cap that ignores reversals fail.
- **Expiry alerts that repeat or vanish.** A licence expiring on 1 January 2027 under a clock advanced day by day from 1 September 2026 must produce exactly three `licence.expiry` alerts (3 October, 2 December, 25 December 2026) and one `licence.expired` audit event at 00:00 `Australia/Sydney` on 1 January 2027 with the binding lapsed and the flag reading `off` from that instant; re-running the sweep ten times on each day changes nothing; rewinding the clock and running again creates no fourth alert; a licence whose `expires_on` is edited to a later date must cancel the pending T-7 clock and re-arm at the new dates; a licence suspended on 20 December 2026 still moves `suspended -> expired` on 1 January 2027.
- **A flag on through the side door.** With an empty database and every `FLAG_<KEY>=on` set in `RUN_MODE=local`: every licence-bound flag reads `off` through `isEnabled` and `evaluateG21`, and `offers.wholesale` does not fall through to A08's static `on`. A tenant row `on` while the platform row is `off`: the effective state is `off`. A vehicle row `on` with a valid platform binding but no binding to the tenant's issuing licence: refused at bind and toggle.
- **Design and copy fidelity.** With the seed, `GET /v1/perimeter/public` must return `disclosure_text`, `warnings[0]` and `sample_notice` whose join equals the design footer paragraph byte for byte, `phase_label` `Wholesale · P1`, `retail_launch_label` `Wholesale investors · retail from 2027`, `marketplace_suspended: false` and `public_flags` both off; `GET /v1/flags` must return exactly the keys of A08's flag table (read from A08's data, not a literal count) with the launch-set states and `licence_binding` populated only for `offers.wholesale`; `GET /v1/licences` returns only the platform rows the seed wrote. A hard-coded footer string anywhere in the module, or a seed that binds a P2 flag "to make the demo work", fails.
- **Visibility as a leak.** `listing.visibility` is set to `verified_wholesale` on the platform and a tenant then sets its own vehicles to `public`: refused with `G21_VISIBILITY_LOOSER_THAN_PLATFORM`; a visitor's `evaluateG21` for `arrange_wholesale_units` on a hidden vehicle (viewer `{kind: visitor, hasSession: false}`) must fail with `G21_VISIBILITY_HIDDEN` and write a `GateEvaluation` row, and so must an investor with `wholesaleActive` absent; the setting change itself must carry a 4E approval id (CCO → LEGL) or be refused.
- **Test routes in production clothing.** In `RUN_MODE=local` with the Docker preview profile, `POST /__test/perimeter/advance-licence` returns 404 to a CCO and to every token; the route is absent from the OpenAPI document, the generated SDK and the MCP tool list.
