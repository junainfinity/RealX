# A64 - Sponsor console: register, distributions, property reporting, valuations, announcements

**The five sponsor "run the trust" screens, rendered from their owning modules' contracts and nothing else: SPN-08 a read-only investor register (holder, type, classification, residency, units, % of trust, wallet, status; Frozen shown with no reason; largest holding against the cap; the last reconciliation as register = on-chain supply = bank; a break banner that says resale is halted; a logged export for the trustee), SPN-09 distributions (rent-roll import, costs and reserve, the proposal, A41's withholding preview, the `DistributionChain` sponsor accountant → sponsor owner → RealX fund accountant → RealX CFO → paid, funding instructions, lateness with its reason, and past runs), SPN-10 the monthly proof-of-property attestation with evidence, a person-only passkey signature and the "late reports pause new offers" rule as its own flag (never the distribution-approval flag: prototype bug 2), SPN-11 valuation upload with the server's token-valuation preview and the banner for moves above 10%, submitted straight to RealX's valuation officer (A34 has no second sponsor approver on a valuation), with a limited valuer view for SP-VAL, and SPN-12 announcements with the RG 234 claims check and the second-human rule. Every action on these screens has the same API, SDK and MCP route for the member's own agent, under the same gates, and every approval a sponsor human must give stays with a sponsor human.**

## Build brief

This node is UI-only: the `(sponsor)/s/[tenant]/operations` route folder of `apps/web` and the `features/sponsor-operations` package of components, hooks and formatters. It calls the API only through `packages/sdk` (A09, regenerated from the OpenAPI documents of A18, A34, A40, A41, A43 and A47) and never through a hand-written fetch. It owns no API route, no table and no job. Every figure is one of the API's fields rendered as its `formatted` twin; every rule (who may see a row, who may approve, whether a report is late, whether a move needs comparables, whether a phrase is blocked) is decided by the API, and the screen only shows the answer. Because the same routes serve a member's agent through A12's tokens and A104's MCP server, this node adds nothing an agent could not also do, and it publishes the mapping that proves it (`parity.json`, below).

**Routing, shell, roles and screen codes**

- Pages live under the owned folder: `/s/[tenant]/operations/register/[code]` (SPN-08, `code` = the vehicle's short code), `/s/[tenant]/operations/distributions` (SPN-09, `?vehicle=&run=`), `/s/[tenant]/operations/reporting` (SPN-10, `?vehicle=&period=`), `/s/[tenant]/operations/valuations` (SPN-11, `?property=&valuation=`), `/s/[tenant]/operations/announcements` (SPN-12, `?item=`). A52's `routes.ts` currently lists the shorter paths (`/s/[tenant]/register/[code]` and so on); at the Specify step this node asks A52 to point the five rows at the `operations/` paths (A52's build-time test requires the page path and the table path to agree). It never creates a page or a redirect outside its owned folder; if A52 prefers to keep the short URLs, A52 adds the rewrites in its own files.
- Each page exports `screen = { code: 'SPN-0x', design: 'spRegister' | 'spDist' | 'spReport' | 'ext:SPN-11' | 'ext:SPN-12' }` for A52's screen registry and the fidelity harness. The sidebar items "Investor register", "Distributions", "Property reporting", "Valuations" and "Announcements" are A52's `SponsorSidebar`; the active item comes from the route table.
- The group layout (A52) already returns a 404 for any tenant slug the principal is not a member of. Inside a tenant, a vehicle, property, run, attestation, valuation or item id that belongs to another tenant returns the owning module's 404 (RLS), and the page renders A52's `not-found`, never an empty screen and never a 403 that would confirm the id exists.
- Roles (from `/iam/me`, used only to choose which controls to draw; the API refuses anyway): SPN-08 SP-OWN, SP-FIN, SP-IR; SPN-09 SP-FIN prepares (the rent-roll import is A34's `SPN.rentRoll.import`, which A34 grants to SP-FIN and SP-OPS, and A98 to SP-PM; the period, run and proposal are A40's `SPN.distribution.submit`), SP-OWN approves, SP-OPS and SP-IR read; SPN-10 SP-OPS and SP-OWN prepare and sign, SP-PM (A98) fills rent roll, maintenance log and arrears and vacancies only; SPN-11 SP-FIN and SP-OWN upload and submit (A34 `SPN.valuation.submit`; no sponsor-side approval exists), SP-VAL (A98) uploads its own drafts only through the valuer view below and cannot submit; SPN-12 SP-IR, SP-OPS and SP-OWN draft and check, SP-IR and SP-OWN submit (A43), and for a material item the submitter must be a different human from everyone in the item's `authors[]`. A member without the role sees the page read-only with no disabled-button clutter: a control the principal cannot use is not rendered, with one exception, the "Sign attestation" (SPN-10) and "Approve as sponsor owner" (SPN-09) controls, which render for an eligible role but disabled with the API's reason when the API says `your_turn = false` (for example "You prepared this, so a different sponsor owner must approve").
- All five pages are server components reading with `cache: 'no-store'` (a break, a halt, a pause or an approval must show on the next load). Client components exist only for forms, uploads, the claims editor, "Load more", passkey prompts and toasts.

**SPN-08 Investor register (`operations/register/[code]`, design `spRegister`)**

Header from the design: code line "SPN-08", title "Investor register", subline "{trust_name} · mirrors the trustee register. Last reconciled {last_reconciled_at}." ("23 Sep 2026, 06:00 AEST" on the seed); when `last_reconciled_at` is null the subline ends "Not yet reconciled" and no tick is drawn. A vehicle selector (the tenant's vehicles, from the same A33 tenant read the SPN-02 listings table uses) changes `code` in the URL.
- KpiGrid, three tiles as the design plus the product map's cap line: **Holders** `holder_count`; **Units** `total_units` with sub-line "= {token_supply} tokens" when `supply_matches` and, when it does not, the sub-line "Register and chain differ, RealX is checking" in amber with no delta figure; **Largest holding** `largest_holding_bps` as a percentage with sub-line "Cap {holder_cap_bps}" (4.8% / "Cap 5%" on the seed), the tile's value turning amber at or above 90% of the cap only when the API returns `cap_warning = true` (G07 by display: the tone comes from `cap_warning` alone, never a client comparison; A47 does not return the flag today, so it is on the Specify follow-up list and the tile shows no tone until it does). Every tile figure is the API's `formatted` twin (`formatted.holder_count`, `formatted.total_units`, `formatted.token_supply`, `formatted.largest_holding`, `formatted.holder_cap`); A47's register view has no twins today, which is a Specify follow-up, and a missing twin renders "—", never a locally formatted number.
- Reconciliation card (product map component "Last reconciliation: register = on-chain supply = bank"): a white card with "Reconciliation · {last_reconciled_at}", a KeyValueList Register {total_units} / On-chain {token_supply} / Bank or escrow {client_money_result} / Result ✓ or "Checking". The bank leg is A47's `kpis.client_money_result` (from A20, already in the register-view contract), and the card never infers it.
- Break and halt banner (G10): when `banner.kind = 'break'`, a brick-tint band (`#F5E4DB` / `#7A3A1E`, the prototype's PreviewBanner) reading "Reconciliation break found {opened_at}. Resale of this trust is halted until RealX resolves it. You don't need to do anything unless RealX contacts you." with `banner.text` from the API appended only when present; `kind = 'halted'` reads "Trading in this trust is halted." plus the API text; `kind = 'pending_ack'` reads "Waiting for the registry to confirm the latest changes." No banner ever shows a cause, a delta, a holder or a case id. Gympie Road Retail on the seed renders the break banner (opened 23 Sep 2026 06:02).
- DataTable, the design's columns plus the product map's two: Holder / Type / Classification / Residency / Units / % of trust / Wallet / Status. `holder_display` as returned (masked by A18's rule, "A. Morgan"; no unmask control exists on this surface), `holder_type`, `classification` (Wholesale, Sophisticated, Sponsor, Retail from P2), `residency` (AU or the country code, G06 by display: shown exactly as A18 returns it through A47, with no client mapping, flag or colour), `units` and `pct_bps` through their row twins `formatted.units` and `formatted.pct` (a Specify follow-up to A47; "—" while missing), `wallet_address_short` exactly as sent (A18's first-6 + last-4 rule, design-analysis §6.4 bug 3; the prototype's "0x7a…1e" is not reproduced), and a StatusPill: Active green, Frozen red, Partially frozen red with "{formatted.frozen_units} frozen" under it (A47's rows carry no `frozen_units` today: a Specify follow-up), Locked grey sub-line "{formatted.locked_units} locked" when non-zero. The Frozen pill has no tooltip, no link and no reason prop. Rows are A47's order; "Load more" appends the next cursor page; the count line reads "Showing {n} of {holder_count} holders" (the total is an API figure).
- As-of: a date field (`as_of`, default today) re-reads the view as of an earlier effective date, for the trustee's month-end, with the caption "Register as at {date}, version {last_certified_version.id}"; a date before the first issue shows the empty state.
- **Export register** (outline-ink, product map action "Downloads the holder list for the trustee (logged)"): calls A18's `POST /register/{vehicleId}/exports` (scope `register:export`) with the current `as_of`, then downloads the returned file; the confirmation line under the button reads "Exported {as_of} · {row_count} rows · sha256 {first 12}… · logged". `REG_EXPORT_RATE_LIMIT` renders "You've reached the export limit for this hour. Try again after {retry_at}." The node never builds a CSV from the table in the browser: the only export is A18's, so exactly one `register.exported` audit event exists per file.
- Empty states: a vehicle with no issued units (an open offer) shows the tiles with 0, the sentence "Units are issued to the register when the offer closes. Applications are held in escrow until then." and no table; a vehicle with no certified version shows "The trustee hasn't certified a register version yet." SP-OPS or SP-PM opening the URL get the owning API's 403 rendered as A52's "You don't have access to the register" page.

**SPN-09 Distributions (`operations/distributions`, design `spDist`)**

- Reads: A40's `GET /v1/sponsor/distributions/runs?vehicle=` (scope `distributions:read`) for the current run card, the chain and `past_runs[]`; A40's `GET /v1/distributions/runs/{id}` (sponsor view: calculation and checks without exception codes); A34's attestation read for the same period; A41's `GET /v1/vehicles/{id}/tax/withholding-preview` (`SPN.withholdingPreview.read`) and the run's declared tax components. A40's sponsor read today returns only `run_id, vehicle_name, period_label, total_cents, per_unit_display, proposed_by, chain[] {stage, status, who, at}, paid_at, scheduled_pay_date, state, late, late_reason, formatted {total, per_unit}` and `past_runs[] {period_label, total_cents, per_unit_display, paid_at, state}`. Every other field this section renders (`legal_hold`, `due_date`, `funding`, the chain's `actor` and `substages[]`, the richer `past_runs[]`) is on the Specify follow-up list below, owned by A40; the page renders "—" or omits the element while a field is missing and never derives it. Header from the design: title "Distributions", subline "Fund accountant prepares, sponsor owner approves, RealX checks and pays."
- **Prepare panel** (SP-FIN, or SP-FIN's agent; product map components "Rent roll and expenses upload", "Reserve movement", "Proposed amount per token and total", "Withholding preview"): shown when the selected period has no run or its run is `draft`. Two scopes are involved and the panel names each next to its control and in `parity.json`: the rent-roll import is A34's `SPN.rentRoll.import` (shorthand `rent_roll:import`), and the income period, the run, the lock and the proposal are A40's `SPN.distribution.submit` (shorthand `distributions:write`). A token holding only `distributions:write` cannot import (A34 refuses with `G22_SCOPE_MISSING`), and the page shows the upload control only when the principal holds the import cell. (1) Rent-roll upload, a DropBox for the property manager's CSV with a mapper select (generic, PropertyMe, Yardi). There is one import route: A34's `POST /v1/properties/{id}/rent-roll/import`, whose `import_id` A40's income period references (`rent_roll_import_id`; A40 owns no rent-roll route, per its boundary lint), so one file fills both SPN-09's gross rent and SPN-10's rent-roll item, and an import the property manager (SP-PM) already made for the period is offered for selection instead of a new upload. The screen never uploads the same file twice. A rejected file (`RR_IMPORT_INVALID`) shows the API's error list as a table Row / Column / Code / Message and the sentence "Nothing was imported. Fix the file and upload it again."; a clean file shows "{row_count} rows · gross rent received {gross_rent} · sha256 {first 12}…". (2) Cost lines: PM fee, maintenance and insurance, reserve top-up (signed; a negative figure is shown as "draw from reserve") and management fee, plus the forecast, as money inputs that send integer cents parsed by A02's `parseAudToCents` (the only client-side money function allowed, and it only parses). (3) **Save** calls `POST /v1/sponsor/vehicles/{vehicleId}/income-periods`; the API returns `net_distributable_cents`, which is the only net the page shows. `DST_NEGATIVE_NET` renders under the cost lines: "Costs are more than the rent received. Nothing can be distributed this month." (4) **Confirm period** (`…/income-periods/{id}/confirm`) freezes the figures and shows "Confirmed by {who} {at}" (with "agent {name} for {person}" when `on_behalf_of` is set).
- **Proposed amount and withholding preview**: after confirmation the page reads A41's `withholding-preview?gross_cents={net_distributable_cents}&period_end=` and shows a KeyValueList: Total {total} · Per token {per_unit} (from the API's twins, "A$2,592.00 · A$0.2592 per token" on the seed) · Holders {holders} · Without a TFN {no_tfn_count} · Foreign residents {foreign_count} · Tax withheld (estimate) {withheld_total} · Paid to wallets (estimate) {net_total}, captioned exactly "Preview, final at calculation" (G16). The page does not compute per-token, withheld or net figures; a missing field shows "—".
- **Tax components** (SP-FIN, or SP-FIN's agent; A41 `SPN.taxComponents.declare`, shorthand `sponsor:tax:write`): while the run is `draft`, a small repeater of component type (A41's enum, from the API) and basis points of gross, sent to A41's `PUT /v1/vehicles/{id}/tax/runs/{run_id}/components`. The page does not check the sum; `TAX_COMPONENTS_DO_NOT_SUM` renders "The components must add up to 100% of the distribution." With no declaration the block shows A41's default ("100% Australian rental income, estimated") as returned. Once the run leaves `draft` the block is read-only and a replayed write renders A41's `TAX_RUN_NOT_DRAFT` sentence "The tax split is fixed once the distribution is locked." The declaration id and hash travel in A40's proposal payload (A41's follow-up to A40), so the sponsor owner approves them. The FY true-up (`PUT …/tax/fy/{fy}/components`) is not on SPN-09; which screen owns it is a Specify question to A41 and the [[Screen Coverage Matrix]].
- **Lock and calculate**, then **Propose distribution** (primary green, the product map's "Submit distribution"), following A40's three routes exactly: `POST /v1/sponsor/distributions/runs` creates the run from the confirmed period in `draft`; `POST …/runs/{id}/lock` locks the period and snapshot and A40's job moves the run `draft → calculating → calculated` (the card shows "Calculating" and re-reads on the next load; no A14 request); `POST …/runs/{id}/propose` on a `calculated` run creates A14's `distribution.propose` request (SP-FIN maker → SP-OWN checker, `4E`, inside the tenant). So the panel has three buttons in order: **Create distribution** (outline-ink; after it the run is `draft` and the Tax components block above is editable), **Lock and calculate** (outline-ink, shown while `draft`) and **Propose distribution** (primary, shown only when the run is `calculated` and its `proposed` chain stage is not done). Each call is its own `parity.json` entry. Refusals render as sentences: `DST_PERIOD_NOT_CONFIRMED`, `DST_PERIOD_ALREADY_RUN` ("There is already a distribution for {period}"), `DST_SPONSOR_SIGNOFF_REQUIRED` ("A second person must approve for your company. Add a sponsor owner in Team, or ask RealX to name a checker." with a link to SPN-14, owned by [[A62 - Sponsor console- apply, dashboard, team and approvals, billing]]).
- **G19 early warning**: when A34's attestation for the run's period is not `attested` or `reviewed`, an amber band above the run card reads "The {period} property report for {vehicle} hasn't been signed. RealX can't approve this distribution until it is (G19)." with a link to SPN-10. This reads the attestation's own `state`; it is the only place the two flags meet, and it only reads.
- **Run card** (design card): "{vehicle_name} · {period_label}" in Newsreader 22 and "{total} · {per_unit} per token" in Geist Mono 20, then the `DistributionChain`. The page never guesses a checker. Chip tones as the prototype: DONE green on `#F4F8F5`, YOUR TURN green border, WAITING grey text. Each chip's `who` line comes from the stage's `actor { kind, person_name, agent_name, token_prefix }` (an A40 follow-up: today `chain[]` has only a `who` string) through `actorLabel()`, and shows "agent {agent_name} for {person_name}" when `kind = 'agent'` (for example the proposal: "agent Month-end bot for Leo P."). The page never parses the `who` string to find an agent.
- **Approve as sponsor owner** (the design's green pill button): rendered only when the API marks the sponsor-owner stage `your_turn` for the calling principal (A40 computes it from A14's eligibility, so a token session never gets it). A decide refused by A14 (maker cannot be checker, role lost, already decided, token principal) renders the A14 reason sentence; the button is never simply hidden after a refusal.
- **Funding** (after RealX approval, state `approved` or `funding`): a card "Fund this distribution: pay {funding.formatted.amount} to {funding.account_name} with reference {funding.reference}" with BSB `funding.bsb` and account number `funding.account_number` exactly as returned, a copy chip for the reference, and, when the run reports a shortfall, "Received {funding.formatted.received} of {funding.formatted.required}". - **SM-08 as the sponsor sees it**: a pure function `runStageLabel(state, chain)` maps every state, and for `calculated` also the `proposed` and `sponsor_owner_approval` chain statuses, to the card's status line: `draft` "Draft · not yet locked"; `calculating` "Calculating"; `calculated` with `proposed` not done "Calculated · ready to propose"; `calculated` with `proposed` done and `sponsor_owner_approval` not done "Waiting for sponsor owner"; `calculated` with `sponsor_owner_approval` done (the short moment before A40's service fires `calculated → in_review`) "With RealX fund accountant"; `in_review` "RealX fund accountant reviewing", `approved` "Approved by RealX · waiting for funds", `funding` "Waiting for funds", `funded` "Funded", `executing`, `executed`, `partially_failed`, `retrying`, `manual_payout`, `reconciling` all "Paying investors", `closed` "Paid {formatted.paid_at}", `cancelled` "Cancelled". Those fields beyond A40's current five are A40 follow-ups. Empty: "No distributions yet. Your first one starts with a rent roll."

**SPN-10 Property reporting (`operations/reporting`, design `spReport`)**

- Reads: A34's attestation list for the tenant and period and the attestation detail, and `GET /v1/tenants/{id}/offers-paused`. Header from the design: title "Property reporting", subline "Attest each property every month. Late reports pause new offers from this sponsor (G19)."
- **Pause banner** (its own flag, `sponsor_new_offers_paused`, never derived from the table): when true, a brick band "New offers from {tenant} are paused. {n} report(s) are more than 10 days late: {vehicles}. Offers reopen when RealX has reviewed every late report." The figure "10 days" is the API's `grace_days`, not a literal. Live offers, distributions and holdings are untouched, and the banner says so in one line.
- **Overview table** (product map mock): Trust / Rates / Land tax / Insurance / Certificates / Vacancy / Status from each attestation's items, with StatusPill `open` grey "Not started", `prepared` amber "Ready to sign", `attested` grey "Signed · RealX reviewing", `reviewed` green "Accepted", `flagged` amber "Flagged: {item titles}", `overdue` red "Overdue {late_days} days". A row whose public proof row is `due`, `overdue` or `failed` carries the caption "Investors see an amber flag on the listing" (red wording for `failed`), from A34's `proof` read.
- **Attestation detail** (the design's TaskRows, title "{vehicle} · {period}"): one TaskRow per item in A34's order: Rent roll ("Tenant paid in full · A$3,120.00", from the import totals), Arrears and vacancies, Maintenance log ("1 item · hot water unit A$1,480.00"), Insurance still current ("Policy to 30 Jun 2027"), rates and land tax, compliance certificates, reserves, incidents and, where a zone flag needs it, the FIRB vacancy-fee return; each pill is the item's own completion state (Uploaded or Confirmed green, Missing amber). **Cross-cutting behaviour**

- Formatting: money, unit, per-token and percentage strings come from the API's `formatted` twins (dates use a twin where the contract gives one, otherwise the shared `DateAu` primitive). - Tipping-off: the register and run components have no prop through which a freeze reason, an AML hold, a case id or an exception code could be rendered; the sponsor view of a run never lists held lines (A40 counts them for staff only).

- Loading shows skeleton tiles and rows in the prototype's placeholder stripes. On error the page shows "We can't load this right now. Nothing has changed." with a retry. A 401 goes to A52's sign-in; a 404 goes to A52's not-found.
- Width: consoles are desktop-first. A52's sidebar collapses below 1024 px, KpiGrids fold to two columns, and DataTables scroll inside their card (`min-width: 720px`) with a 16 px gutter and no page-level horizontal scroll at 375 px.
- Reuse for partners: the register table, reconciliation card, run card with its chain, and the past-runs table are exported from `features/sponsor-operations/index.ts` with a `mode` prop (`sponsor` | `partner_readonly` | `trustee_countersign`) so that [[A105 - Partner portal- trustee-RE, auditor, regulator observer and licensee views]] reuses them without copying.
